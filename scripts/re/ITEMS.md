# Items and inventory (game 1.0.0)

What adding and owning an item does in the main module, the Chamber Dungeon's stones and panels, and the saved data the inventory is part of, from static analysis. Offsets are module offsets; `las.sym` names them at their runtime addresses (module offset + 0x8504000). Item ids are `Items.gsheet`'s `itemID`, as the module's `kItemNames` (`game/hooks/inventory.hpp`) lists them.

## Adding and owning

`Inventory_AddItemID(item, count, index)` (`0x8d08e0`, hooked by the module) and `Inventory_HasItem(item, count, index)` (`0x8d1a30`) switch on the item id, 0 to 0x7e. `count < 1` adds nothing and owns everything. An id from 0x80 throws (a bitset's out_of_range), so the module's hook passes on ids below 127 only.

After every add, also those that change nothing, AddItemID sets the item's bit in the obtained bits (inventory `+0x124`, a bit per item id), and for the Boomerang (7), Seashell (22), Piece of Heart (58), Bottle (113) and Chamber Stone (114) it sends a play report (`PlayReport_ItemCommon`: SaveId, TotalTimePlayed, Chapter, Warashibe, then ItemId and Index). The getting flags (`Item_CheckGettingFlag`, `Item_SetGettingFlag`, both hooked) are something else: the event flag the item's `Items.gsheet` row names (row `+0x70`).

Inventory fields by name are in the module's `game/data/inventory.hpp` (`InventoryItems`; Saved data below).

`CranePrize_Has` (`0x148b10 (prize row, count, index)`) is the Trendy Game's own check by `CranePrize.gsheet` row (8 heart piece, 9 seashell, `0xa`–`0x13` figurines, `0x14` chamber stone bits); it skips a featured prize already owned (CRANE.md, Prize selection). The item actors do not use it.

What this means for received items:

- An index out of its range adds nothing but the obtained bit; a received Chamber Stone with index -1 is one (TODO.md).
- Dungeon items go to the dungeon Link is in; the module's hook sets `LevelIndex` to the item's dungeon around the call.
- A trade item replaces the one held; the module's hook adds none of 29–40 and sets their flags instead.
- Secret Medicine is a single bit: a second one while Link holds one is lost. LASR's pool has three.
- Heart containers take 9 indices: the 8 bosses and the Chamber Dungeon's reward for 12 clears (`MapPieceClearReward` index 8).

## Item actors

The item actors placed in rooms (ItemSmallKey, ItemGoldenLeaf, ItemHeartPiece, ...) share an item base class: an actor and an NPC component, whose Npc.gsheet row gives the model, tailor, flowchart (`eventInfo`), triggers and collision. The table entries of ItemSmallKey (`0xa9`) and ItemGoldenLeaf (`0x88`) name no resources. The item base's actor vtable is `0x1bc9ac0` (`ItemActor_Ctor` sets it), its NPC component's `0x1bc9d50`; both are complete (a class overrides only what differs). The module's drop actor is an item class of its own on them (DESIGN.md, Drop actor). A placed item's LEB parameter 0, when an int, is its index (else -1): `ItemActor_CanAppear` (`0x8c4510`) tests `Inventory_HasItem(item, 1, index)`, `ItemNpcComponent_StartEntry` (`0x8c4750`) passes it to the `get` entry as `itemIndex` (beside `itemKey` and `itemCount`), and actor virtual `+0x150` (`0x8b9480`) holds for two items of the same id and index.

- **Factory** (ItemSmallKey `0x8cabb0`, the table's `(out x8, owner sp*, params*)`): `ActorName_Make` (`0x23830`, the LEB name, else `<table name>:<counter>`), then `0x8cacf0`: null for a name of 0 or 32+ characters or one the owner has (`Entity_FindChildInMap` on the owner's `+0x10`, `+0x38`; one in `+0x10` must also be in `+0x60`); `0x8cb180` builds the `ActorArgs` (`{name, length, 1, owner sp (one reference), params copy at +0x30}`, `ActorParams_Copy` `0x31100`), constructs (`0x8cb220`) and destroys them (`ActorArgs_Dtor` `0x319f0` releases the owner and the params); unless destroying: Register (`+0x78`), Setup (`+0x20`), flags bit 3, `Entity_Start` (`0xfab470`), `Entity_AddChild(owner, sp)` (`0xfb3290`), else `Entity_Destroy`.
- **Constructor** (`0x8cb220`): `operator_new(0x340)`, a make_shared block: control block vtable `0x1bcaa38` (its zero-shared calls the actor's virtual destructor), the 0x320-byte actor at `+0x20`. `ItemActor_Ctor` (`0x8b6880 (actor, ActorArgs*, StringView* row key, u8 item id, u32 count, pose pair)`): `Actor_Ctor`; the row key at `+0x2a8` (char[0x20], length `+0x2c8`; 0x20 characters or more throw); item id `+0x2e8` (0x30 for the small key), count `+0x2ec`, NPC component sp `+0x2f0`, pose pair `+0x300` (the small key's `0x16fc744`, the side view's `+0x48` when `0x8b6710(position)` finds a side-view area), touch delay `+0x308` (0.5 s), `+0x310` set when an event runs as it is made, classBits `|= 0x201`. `game/actors/item.hpp` types the actor and the component. Then the class vtable (ItemSmallKey `0x1bcaa70`) and the self pointer (`+0x8`, weak owners 1).
- **NPC component.** The item base's Setup (`0x8b6b70`) finds the Items row of `+0x2e8` (`ItemsSheet_FindRow`, kept at `+0x2e0` and `+0x2d0`) and calls actor virtual `+0x128 (actor x0, name* x1) -> sp x8` with `"Npc"`. ItemSmallKey's (`0x8cb8a0` → `0x8cb8f0`, `0x8cbb90`, `0x8cbeb0`): null for a destroyed actor, a name of 0 or 32+ characters or one it has (`0xfa9490 (actor, name, length)`); `operator_new(0x360)`, `ItemNpcComponent_Ctor` (`0x8c3f10 (component, ComponentName*, row key*)`: `NpcComponent_Ctor`, which looks the row up, and the item base's fields from `+0x2e0`: a random angle (-pi to pi), the hold, moving and launched flags (`+0x2e6`..`+0x2e8`), the rest timer `+0x2ec`, the launch velocity `+0x2f0` (per frame), a signal `+0x300`), vtable `0x1bcabf0`, u16 `+0x358` 0 (body ready, fall pending), `0x8cbf40 (out, component)` (its shared_ptr, control block vtable `0x1bcb028`); Register, Setup, bit 3, the parent-active bit 1 from the actor (`+0x50` when the active state flips); `EntityManager_PostStart`; `Entity_AttachChild(actor, component)`. The row key is read only by `NpcComponent_Ctor`; the item base's own maker (`0x8b8420`) takes it from the actor's `+0x2a8`.
- **Row strings.** `NpcComponent_ResolveParam` (`0x95af30 (out view, component, view*)`) gives a row string that starts with `$` and a number N from 0 to 7 as the owner's string LEB parameter N (type 4 through `LebRoom` virtual `+0x50`, type 5 through `0x35c30`), an empty view when it is not a string, and any other string as it is. The component resolves its row's `graphics.path` and `graphics.model` through it when it loads its model, and calls it again later for row strings such as animation names (Marin's `$4`) and the take entry (a LASR heart piece's `$3`). Its callers pass a copy of the row's view: the characters pointer is the row field's, the view's address is not. A model named so loads with the component's own resource loads, also from a file nothing else in the room uses: a freestanding `ItemHeartPiece` given `ItemSmallKey.bfres` and `SmallKey` here showed the small key, and its take entry and item-get ran as before (measured 2026-11-03). LASR's Npc rows for `ItemHeartPiece`, `ItemSlimeKey`, `ItemSmallKey` and `ItemStick` name their model `$1`/`$2`, `ItemHoneycomb` and `ObjSinkingSword` `$0`/`$1`, and `ObjTreasureBox` with Chest Types `$6`/`$7`.
- **Actor overrides** (ItemSmallKey over the item base): `+0x18` the deleting destructor (the same code), `+0x68`/`+0x70` IsA (type id address) and TypeId (`0x8cb450`: the small key's `0x1cb2aa0`, then the item base's chain; the item base's IsA `0x8b7250`), `+0x78` the start task (typed), `+0x100` the zone enter (the item base's `0x8b8410` clears the component's `+0x2e4` and its `+0x30c`; the small key's then falls again, see Event actions), `+0x128` the component maker. The make_shared control block's zero-shared calls the actor's `+0x10` (`0x8cf710`).
- **Component overrides** (ItemSmallKey over the item base `0x1bc9d50`): `+0x18` the deleting destructor, `+0x68`/`+0x70` IsA and TypeId (`0x8cc140`: the small key's component `0x1cb2ab0`; the item base's IsA `0x8c4120`), `+0x78` the start task, `+0x98` `SmallKey_UpdateAppear` (enabled while switch 0 is on; casts its owner to ItemSmallKey without a null check; the item base's `0x948190` enables it), `+0x178` the event start (an entry named exactly `take` adds a small key (`Inventory_AddItemID(0x30, 1, -1)`), sets switch 1, autosaves and destroys the actor; any other entry: the item base's `0x8c4750`), `+0x210` MakeCollision, `+0x220` MakeEventChara (both below), `+0x388` BuildComponents (the item base's `0x8c5530`, then the compass chime `CompassAlarm`), `+0x3e0`..`+0x3f8` the inventory hide (off; the item base's on), impulses and freeze (on; off), the sleep check (off; on). Its own code casts by its type ids. The component's shared_ptr is a pointer block (`0x8cbf40`; its zero-shared calls the component's `+0x18`). The pop check `+0x88` (`NpcComponent_CheckPop` `0x947d70`, the row's popConditions) gates `+0x98 (component, bool quiet)`.
- **MakeCollision** (component `+0x210 (out x8, component, name*, x2, x3)`, as the other makers): ItemSmallKey's (`0x8cc910`) calls `NpcComponent_MakeCollision` (`0x94b350`), and for a collision with a body (IsA `0x1cab3a8`, not destroying) connects two slots (virtual `+0x20 (signal, std::function*)`) to the collision's signals at `+0x1b8` (the body made: u8 `+0x358` 1, and a pending fall runs) and `+0x210` (lost: `+0x358` 0), through their owners `+0x1c8` and `+0x220`. `BodyCollision_AddToScene` (`0x10bcbf0`) adds the body to the world's PxScene and emits `+0x1b8` with it, or puts it in the `+0x180` PxAggregate (`BodyCollision`, `PhysicsBody`). Each slot is a libc++ `__func` `{vtable, component}` (vtables `0x1bcb128`, `0x1bcb170`; the game has no RTTI, so 7 slots: destructor, deleting destructor, clone, clone into, destroy, destroy and free, call), called with the body's shared_ptr moved in, which it releases.
- **Event actions.** Each EventChara dispatches by action name through the `std::function<bool(std::function* step, args)>` at `+0x400` (the args' first member points to the name's `{characters, length}`): generic actions (`0x1049a0`: Activate, Deactivate, Destroy, SetActorSwitch, PlayOneshotSE, GenericGimmickSequence, ...), wrapped by the item base (`0x8c4a30`, component `+0x220`: `PlayTailor*Channel`) and the class, each wrapper asking the one inside first. An action that takes time swaps a step callable into `*step` (`std::function` swap), which the event runs each frame until it returns `{0, 0}` (through x8). `Fall` is ItemSmallKey's (MakeEventChara `0x8cccb0`, wrapper `__func` vtable `0x1bcb098`, step `0x1bcb0e0`: `SmallKey_StartFall` `0x8ce2f0 (component)`, done at once) and ItemGoldenLeaf's (`0x8a7f60`). `SmallKey_StartFall` reads no type: without a body yet (`+0x358` 0) it sets `+0x359` and runs again once the body is made; else the body dynamic with gravity, its velocities zero, and the root 10 units above the spawn (`Node_SetWorldPos` `0xfb6d30`); gravity drops it. ItemSmallKey's zone-enter (`+0x100`) runs it too when LEB parameter 0 is the string `ReFall` and switch 0 is on.
- **Buried items.** ItemSlimeKey (component vtable `0x1bc6b78`) overrides `+0x88`: with its item id `0x19`, when a dig spot of the scene's dig map (Framework `+0x4a8` → `+0x208` → `+0x228`) is at its root (`0x89fa90`), it pops once that spot is dug up (`0x89fcb0`); else the row's popConditions. Its `+0x98` (`0x89f770`) enables it and, unless quiet, sets its body's velocity to (0, 4, 0): it hops out. Neither helper reads the class.
- **Appearing.** `NpcComponent_BuildComponents` arms the row's trigger conditions 14 to 17 (switch 0 to 3 turns on, `+0x320`): the pop entry. Touch (condition 0) runs the take entry once the touch delay has run out outside events. `ItemActor_CanAppear` (`0x8c4510 (actor)`), while component virtual `+0x3e0` (the inventory hide) holds, hides the actor while `Inventory_HasItem` holds for its item (`+0x2e8`) with, when its first LEB parameter is an int (type `+0xc0` 3), that value (`+0xbc`) as the index (heart piece, seashell, golden leaf and chamber stone bits), else -1: any owned (the Slime Key for `ItemSlimeKey`, a trade item while held). LASR's `randoFixes` patch at `0x8c45b8` makes it false.
- **Physics.** The row's `collision.traits` names an `NpcPhysicsTraits` row (mass, drag, angularDamp, bounciness, friction, PhysX combine modes, axis locks), applied when the collision is made and again on landing after an impulse. Component virtual `+0x290 (component, const Vec3*)` sets the body's linear velocity (`PxRigidDynamic` vtable `+0x138`, waking it) unless it is kinematic. The item update (`0x8c6030`, component vtable `+0x3c8`) does not run during events; physics does. On landing it applies the traits row again (`0x963df0 (body, row)`: PhysX `+0x100` the mass, `+0x1c8` setLinearDamping the drag, `+0x1d8` setAngularDamping, then the axis locks); once the body's linear velocity has stayed near zero for 0.25 s (`+0x2ec`) it makes the body kinematic (`BodyCollision_SetKinematic` `0x10bd430 (collision, bool)`: PxRigidBody `setRigidBodyFlag(eKINEMATIC)`; turning it off wakes a body that is in a scene); while `+0x2e7` is set it makes it dynamic again. A launch (`+0x2e8` clear) sets the body's velocity from `+0x2f0` times the frame rate and sets `+0x2e8`; the next update applies the traits and clears it. The body is PhysX 3.4's `PxRigidDynamic`: `+0x130` getLinearVelocity, `+0x140` getAngularVelocity (each returns a `PxVec3` through x8, its copy constructor not being trivial), `+0x148` setAngularVelocity, `+0x1e0` getAngularDamping. A ball meeting a wall at about 1 unit a second does not bounce, whatever its bounciness: its velocity into the wall drops to zero (the scene's bounce threshold).
- **Pulls.** Component virtual `+0x3a8` (`ItemComponent_AddImpulse` `0x8c5980 (component, const Vec4*, bool hold)`) adds the vector to the launch velocity (`+0x2f0`), sets `+0x2e7` and `+0x2e6` to `hold`, unless `+0x2e5` is set or virtual `+0x3e8` is off. An antlion pit (`AreaAntlion`, `0x39a60`) and a DeathBall (`0x25b8f0`) pull items this way each frame; at their centre they call `+0x3b0` (`ItemComponent_Swallow` `0x8c59f0`), which, while virtual `+0x3f0` holds, disables the collision (`BodyCollision_SetEnabled` `0x10bbc50`), makes the body dynamic with gravity (`BodyCollision_SetGravity` `0x10bd590`: PxActor `setActorFlag(eDISABLE_GRAVITY)`), zeroes the launch and sets `+0x2e5`; an item without a body collision is destroyed.
- **Adding.** Component virtual `+0x418` (`ItemComponent_AddItem` `0x8c76a0 (component, item, count, index)`) sets the actor's flags `+0xa2` bit 2, calls `Inventory_AddItemID` and emits the component's signal `+0x300`. Three item classes call it (`0x890d70`, `0x89a3a0`, `0x8a3060`). The only listener is TagRapidFlowGame's: its setup (`0xe2a2b0`) finds each linked actor's ItemComponent (`0x3efd0`, type `0x1cab500`) and connects a slot (`0xe2b670`) that marks the item's entry (by the actor's `+0xa8`) collected in the rapids game's state (`0x1cbb110`, map `+0x48`, entry `+0x24`).
- **Water.** The component's water event (shared_ptr at `+0x168`) holds the in-water flag (u8 `+0x151`) and the water surface height (f32 `+0x154`). Its task (`WaterEvent_Update` `0x13c100`) probes the water each frame and emits `+0x58` on entering, `+0xb0` on leaving (`WaterEvent`; the offset is the Npc row's `waterChannel` offsetY). While in water, the item update compares the water event's height with the surface: deeper than 0.3 below it, it adds the upward acceleration component virtual `+0x400` returns (the item base's 7.0, less than gravity: items sink) through `PxRigidBody::addForce` (vtable `+0x150`, `(force, mode 3 eACCELERATION, wake)`), within 0.3 none (the `NpRigidDynamic` vtable `0x1c8c2a0`: `+0xb0` and `+0x170` load setGlobalPose's and setRigidBodyFlag's error strings). Linear damping (`setLinearDamping`, `+0x1c8`) is component virtual `+0x410` in water (the item base's 1.8) and `+0x408` (`Npc_TraitsValue`, the traits row's drag) out of it, set by the water event's enter and exit closures (`0x8c6c40`, `0x8c7060`) and on landing. On entering, without an `attributeProvider` the water event casts a ray 25 down from its probe point (filter word `0x14004c2`, the owner actor's `+0xa8` as the group) and takes the hit shape's attribute (`Physics_ShapeAttribute` `0x825a20`), else 0x12.
- **Physics worlds.** `Physics_Init` (`0xb6a0`, from `Framework_Init`) makes worlds 0 and 1 through `Physics_GetWorld` (`0x10c6790 (physics, desc*, id)`: the slot at `+0x38` + 16 × id, made on first use). The constructor makes the scene from a PxSceneDesc: gravity (0, -9.81, 0), `events`, the desc's callbacks, `limits`, `frictionType`, `treeRebuildRate`, the CPU dispatcher (`threadCount`, `threadCores`), dynamic AABB trees as both pruning structures, the rest PhysX's defaults scaled by the tolerances. It then makes the controller manager (`PxCreateControllerManager`) and sets the PxScene's userData to the world. World 0: `Physics_FilterPair`, one thread on core 1, rebuild rate 10000, limits 200 actors, 80 bodies, 256 static and 256 dynamic shapes, 32 aggregates, 128 constraints, `desc80` 1. World 1: filter shader `0x8299d0` (the same layer and group rule, pair flags 0x61c), one thread on core 2, rate 100, limits 128 actors, 128 bodies, 128 dynamic shapes, `desc80` 0. Both share the filters: `controllerQueryFilter` `0x1b50038` (preFilter `0x829a60`), `blockFilter` `0x1c971a8` and `touchFilter` `0x1c97198` (vtable `0x1bc2450`, preFilter `0x829bb0` returns the object's `+0x8`, 2 and 1), `controllerFilter` `0x1b50040` (`0x829b00`: the rule on the two controllers' shapes' filter data). The defaults: filter shader `0x10ca330`, filters `0x1c51210` (preFilter and postFilter return eTOUCH), controller filter `0x1c51218`. The queries at PxScene `+0x2d8` (`0x10cdd30`, `0x10cdefc`) and `+0x2e0` (`0x10ce08c`, `0x10ce228`) pass `blockFilter` or `touchFilter`.
- **Physics step.** `PhysicsWorld_Make` (`0x10c6880`) allocates a world (0x2e0 bytes, the physics heap, 0x10-aligned) and wraps it in a shared pointer. The physics update phase (`0x15730`) steps each world under its `mutex`: it clears `resultsReady`, emits `beforeStep`, starts the PxScene's simulate (virtual `+0x1c8`) with `stepTask` as completion task; the task (`0x10cceb0`) fetches the results (virtuals `+0x338`, `+0x1f0`, with `desc80` `+0x2c8 (1, 1)`, then `+0x340`), sets `resultsReady` and signals `condition`, which `PhysicsWorld_DeliverEvents` waits on.
- **Body events.** Each physics world's simulation event callback (`PhysicsEvents_vtable` `0x1c512b8`; onWake and onSleep empty) queues contacts (`PhysicsEvents_OnContact` `0x10ca9f0`, the PxContactPair events at `+0x32` into `PhysicsContact::events`) and triggers (`PhysicsEvents_OnTrigger` `0x10cb9e0`, the PxTriggerPair status). After a step, `Physics_DeliverEvents` (`0x10c6b10`, for up to four worlds at the manager's `+0x38`..`+0x68`) delivers them (`PhysicsWorld_DeliverEvents` `0x10ccfb0`) and emits each world's `stepped`. A contact goes to both bodies (`PhysicsContact_Emit` `0x10c1930`; the second with `second` set), on the signal of each of its events (`PhysicsBody_EmitContact` `0x10c16b0`); a trigger of status Found or Lost to `triggerEntered` or `triggerLeft` of both. `controllerHit` is `CctHitReport_OnShapeHit`'s. `BodyCollision_SetName` (`0x10bb6a0`) also sets the PxActor's name (PxActor vtable `+0x40`).
- **Collision filters.** The row's `collision.filter` (1..7) picks a filter word from `NpcCollisionFilters` (`NpcComponent_CollisionFilter`, component virtual `+0x128`; anything else `0xd727ffe0`). A word's bits 0-4 are its layer and bits 5-31 the layers it collides with (bit 5 + n: layer n); the physics scenes' filter callback (`Physics_FilterPair` `0x829920`) lets two shapes collide only when each one's set holds the other's layer, and not when both carry the same nonzero group word. Filter 7 (the items: layer 9 with {1, 2, 6, 12, 13, 16, 19, 26}) passes through rocks, bushes, chests and Link; filter 4 (most NPCs: layer 7 with {1, 2, 5, 6, 7, 8, 11, 12, 13, 15, 16, 17, 19, 23, 25, 26}) collides with them. `SetTouchable` (`0x8c7850 (component, bool)`, an item component virtual) clears bit 11 (layer 6, that of `NpcCollisionFilters` 1 and 2) unless its bool is set; layer 6 is Link's (his controller capsule `0xd1773dc6`, item sensor `0xc006`, event sensor `0x8006`): a dropped rupee with bit 11 cleared was not picked up, and was once it was set again (measured 2026-11-01). A rock's collision (`ObjRock`) is a block well above its model: a ball with filter 4 bounced off its side about 2.9 above the floor. `Physics_FilterPair` also suppresses a pair whose word 3 is 1, and gives a trigger pair (filter attribute bit 5) pair flags 0x414, two kinematic bodies (bit 4) 0x61c, others 0x61d. `Collision_SetFilter` (`0x7c240`) makes a word from a `CollisionFilterDesc` (`CollisionFilter_Apply` `0x829e50`: `CollisionFilter_Presets`, a function static at `0x1cb2578`) and sets it with the group through collision virtual `+0x90` (a PxFilterData `{word, group, 0, 0}`).
- **Collision attributes.** A shape's material's userData points at a u32 attribute (`Player::groundAttribute`'s format); `Physics_ShapeAttribute` (`0x825a20 (u32* out, shape wrapper sp*, triangle)`) reads it, a triangle mesh's by triangle. `ObjTree_Setup` points both boxes' first material at `Tree::collisionMaterial` (`0xcaaf30`; collision virtual `+0xc8 (shape, material)` returns the PxMaterial in a reference handle). The material words are built by the NPC component (`0x949e30`: the row's material, bits 14-17 set to 1 with Npc.gsheet `attribute` bit 2, bit 19 the inverse of `attribute` bit 1), ObjDungeonPot (`0xb240b4`), ObjInvisibleWall (`0xbc7bd4`), ObjRock (`0xc45c90`, `0xc45dec`) and the trees. Bit 19 clear is read by `0xd907f0` (from Locomotion's update and `0xdb86a0`): when Link moves within 20° of his facing, a ray ahead hits a shape whose attribute has bit 19 clear: Link's push pose (`push_st`, `push_lp` in state 0), at walls and push blocks alike; at a block state 6 follows after about 30 frames (measured 2026-11-01). Bit 19 is set on the NPC component's shapes whose row `attribute` lacks bit 1 (attributes 0, 1 and 4: the talking NPCs, items and triggers; clear for 2 and 6: doors, locks, chests, statues, `ObjSignboard`, `ObjSquareBlock`, `ObjCaveRock`), on the trees (`TreeParams::flag73` 0 in every table), on the three `ObjInvisibleWall`s (set unless LEB param 3 is 1, `0xbc7c4c`; none is), not on pots or rocks (their words start at 0), and on about 3 in 10 of the collision files' material words: a `.cidb` (embedded in a map piece's or actor's bfres) ends each mesh entry with its attribute words, one per material index (entry `+0xc` their byte size), and `Tree.cidb`'s is 0x84c49, the word `ObjTree_Setup` builds; set ones are the tree pieces' 0x84c49, the hole pieces' kinds 5 and 6 and the `AirWallAutojump` walls among others. No code extracts bits 14-17.
- **Talking tree.** `ObjTree_Setup` for ObjSpeakTree (actor id 0xc0) loads `event/SpeakTree.bfevfl` in a DeferredInit task; its closure (`0xcb32b0`) stores the flowchart resource in `Tree::eventSource` and its ResFlowchart in `eventFlowchart`, then calls the tree's virtual `+0x90`.
- **Seashell drops.** A bonked tree (`ObjTree_DropItem` `0xcb1f30`, the tree) and a bombed hole's AreaShellDropper (`AreaShellDropper_Drop` `0x855a0`) drop their seashell through `Enemy_DropItems` with callbacks that place and launch each item. Both aim at the point of their first LEB rail link (actor `railLinks`, `+0x118`: an `ActorRailLink`, 0x30 bytes, vtable `0x1b51068`: the record's rail link at `+0x8`, the actor's LEB room at `+0x20`, whose virtual `+0x48 (the link's point index, +0x1c)` gives the point's position). The tree starts the item at its root plus its parameters' (`+0x478`) crown height (`+0x6c`) and 0.5, launched at their speed (`+0x68`) toward the point (without one, toward Link). Link's dash crash into the tree (`PlayerSignal::kDashCrash`) starts the drop in the Wait state (`ObjTree_OnPlayerSignal` `0xcb0f30`; the Hit state's enter `ObjTree_HitEnter` `0xcb04e0`; `game/actors/tree.hpp`); an apple tree drops its apples instead (`0xcb18f0`). The dropper starts it 2.25 above itself (virtual `+0x138`), launched at 10.8 toward the point or itself (`+0x140`). `Drop_LaunchVelocity` (`0x89d880 (speed, Vec3* from, Vec3* to)`) solves the launch angle for that speed under gravity -9.81 (the higher of the two arcs; 45 degrees plus half the slope's angle when out of reach) and returns the velocity. A cut bush, a lifted rock and a pot (`0xba63e0`, `0xc49b10`, `0xb2ae50`, called from states the ObjGrass, ObjRock and ObjDungeonPot setups install) drop the item their LEB parameter names, else the bush and the rock `ItemDrop.gsheet`'s row `Grass` (key 17, `0x89d6e0`: Heart, Rupee1, Rupee5 or nothing by weights 8, 6, 1, 85) and the pot the row its `+0x578` names, through `Enemy_DropItemsDefault` (`0x89b7e0`), whose default callbacks (`0x899d10`) start each item 0.5 above the object's root (`0x899f40 (actor, id, index, count)`) and launch it at (0, 4, 0) (`0x89a190`); with 2 or more items each also goes out on a fixed fan (0.5 out, and 1 outward in the launch). `Enemy_DropItems` passes seashells (22), golden leaves (23), heart pieces (58) and heart containers (59) one at a time (index 0, count 1): a bush's seashell hops straight up.
- **Boss drops.** Eleven bosses drop an item with the event action `BossItemDrop` (the eight with a heart container, Lanmola, the Armos Knight, Master Stalfos in its fourth fight): `Enemy_DropItems` with the boss's `ItemDrop.gsheet` row (`HeartContainer0` to `7`, `AnglerKey`, `FaceKey`, `HookShot`), which takes the item's start and launch from the boss's callbacks (the defaults of Seashell drops: 0.5 above the boss, straight up at 4; Moldorm's starts near the middle of its room) and makes it with `ItemActor_Create`. - **Buff drops.** The enemy drop code (`0x89c02c`) replaces a drop by a buff: a Guardian Acorn (`DefenceUp`) once `KillCountNoDamage` (inventory `+0xa5`, zeroed by a hit on Link) reaches 14, which sets it to 0; else a Piece of Power (`PowerUp`) once `KillCount` (`+0xa4`) reaches the maximum health / 4 + 32 (`Inventory_MaxHealth` `0xdf8260`, quarter hearts), which leaves it at the remainder. - **Shop shelf.** `ShopItemSheet_Load` (`0xa4ab60 (object, out sp x8)`) loads `datasheets/ShopItem.gsheet` into its object's `+0x2e0` (the resource) and `+0x2f0` (the sheet). ## Item-get

`Player_ItemGetSequence` (`0xd795d0 (shared_ptr* out, Player*, int itemId, bool keepCarry, StringView* messageEntry)`) is the body of Link's event actions `GenericItemGetSequenceByKey` and `GenericItemGetSequence`; the sequence is the action's waiter (EVENTS.md, Actions and queries).

- **Text.** The text step (`ItemGet_TextStep` `0xd741c0`, a closure that returns its future through `x8`) waits 1 s (`ldr s0, [x20, #0xa0]` at `0xd741f8` loads the delay for `Delay_Make`), then shows the text, joined with the fanfare's future (`ItemGet_FanfareFuture` `0xd7a820`): the fanfare plays, then a task polls `ItemGet_FanfareDone` (`0xd7af30`), true once no event runs, the wait was cancelled or the fanfare stopped. The step ends once the text has closed and that wait is done.
- **Fanfare.** `ItemGet_PlayFanfare` (`0x8d5700 (u32 item id)`) plays the `Items.gsheet` row's sound (`+0x58`): an SE when it starts with `@`, else a BGM jingle through `BgmManager_Play`, kind 2; every vanilla jingle is a BGM. Before it, when the item's info `+0xe` is set, the item-get calls `BgmManager_MuteZone(8)`; for the Guardian Acorn (111) and the Piece of Power (112) it calls `BuffMusic_Play(true)` (FRAMEWORK.md, Audio).
- **Autosave.** `ItemGet_RowAutoSave` (`0x8d5ad0 (item id)`) tells whether the row asks for an autosave, through `ItemRow_AutoSave` (`0x8d5bc0 (row)`: `+0x80` enabled, `+0x84` category, `+0x88` its condition's parameter). The item-get's step then calls `SaveManager_RequestAutoSave` (`0xe0b360 (save manager, u8 kind, bool)`) with the level scene's `saveManager` (scene `+0x90`) and kind 3; it returns false when a request waits already (`+0x161`). The save runs once no event runs (the event manager's request count, `+0x1d0`, is 0).
- **Model.** `ItemModel_Make` (`0x8d3670 (out holder, owner sp*, StringView* name, root node sp*, u8 item id)`) loads the item's model and posts the item-get's model task, which makes the skeletal model component, disabled, into holder `+0x18`; it copies the owner, the name view and the root, not the name's characters. The task (`ItemGet_ModelTask` `0x8d41c0 (task*)`) reads the item's Npc row, gets its model (`ModelResource_Get` `0x1046190 (out, resource holder, const char* model name)`) and makes the component `ItemModel` (`*(*(task+0x8)+0x18)`, a shared pointer) on its node.
- **Model makers.** `ItemModel_Make` is called by the item-get's item node (`0x884a10`, below) and by code that sits with NpcDrWrite's (`0x98ce64`), NpcMarthasBayFisherman's (`0x9fa104`), NpcSale's (`0xa2d9e4`) and NpcTarin's (`0xa45a00`), at `0xa40550`, by the item node chests and ItemSecretSeashell make (`0xcc1858`, Item-get poses) and for `AppleModel` (`0xde90a4`). The item id picks the `Items.gsheet` row, whose `npcKey` names the Npc row with the model.
- **Item node.** `ItemGetHolder_Make` (`0xd7a4f0 (out sp, ComponentArgs*, u8 item id)`, called only by `ItemGet_MakeCarryHolder`) keeps the item id at `+0x1c1`; the node's model maker (`ldrb w4, [x23, #0x1c1]` at `0x8849fc`, then `ItemModel_Make`) and its pose (vtable `+0xa8`) read it. Another id there gives the item-get that item's model and pose, while its text and fanfare stay those of the sequence's id: the placeholder (71) made 58 there held up the Piece of Heart at its pose under "You found an Archipelago item" (measured 2026-11-03). LASR's flows add a placeholder before its item-get: the module's `collected location` came 4 ms (a freestanding heart piece) and 10 ms (a chest) before the node was made (measured 2026-11-03).
- **Nodes.** The model component (vtable `0x1c4a060`) is itself a node (ACTORS.md, Nodes) under the item's node (its parent, component `+0x58`, also task `+0x38`), which sits at local (0, 2, 0) under Link's node, rotated −65° about X, its scale popping 0 → 1.015 → 1; the shine shows at the item's node. The game writes the item-get pose (below) to the model component's node once the item pops up. The model's bones follow the component's own copy of its world transform (`SkeletalModel_SyncWorld`, MODELS.md), which it refreshes only when its node is marked (`Node_MarkDirty`).

## Saved data

The save is the static `GlobalSave` (`0x1cbb200`). `GlobalSave_Reset` (`0xdfab90`, a new game; also on `$QUIT`) zeroes `+0x20`..`+0x5f00` (the file image) and fills its sections through pointer slots:

|---|---|

| `+0x5f20` | the body at `+0x100`, 0x5e00 bytes, which the CRC32 covers; `EventFlags_ptr` is this slot, the start of the slot block |
| `+0x5f80` | the level state at `+0x5f40` (0x30 bytes, not saved): `+0x0` the 256 level flags (`LevelFlags`, bit table at slot `+0x5f88`), `+0x20` a position, `+0x2c` it is set |

| `+0x5fc8` | the Chamber Dungeon section at `+0x240`, 0x5160 bytes (below) |
| `+0x5fd0`..`+0x6138` | ten bit tables of the Chamber Dungeon section (below) |
| `+0x6160` | `SaveHeader_ptr`: the save header (`SaveHeader`, 0x140 bytes) at GlobalSave `+0x53a0` (`0x1cc05a0`) |

The save files are `save:\savedata0.bin` to `3` (a table at `0x1cc1950`, 0x28 bytes per file), read and written by asynchronous file tasks (`0xdfd420`, `0xe00a80`, `0xe02730`, `0xe072b0`, `0xe07930`).

**SaveHeader** (0x140 bytes, the size `GlobalSave_Reset` clears):

- `knockCount`: the enemies defeated; each enemy's death code adds 1 (beside `KillCount` and `KillCountNoDamage`).
  Bit 0 is what the event query `TestEnemyKnockCountOddEven` tests (lambda `0x96c680`, registered by `0x96c5a0`).
- `deathCount`: one more, up to 0xffff, by Link's event action `AddDeadCounter` (`EventAction_AddDeadCounter`
  `0xd6e650`); not 0, it changes a choice in `0x82c870`.
- `totalTimePlayed`: microseconds; the actor update phase (`0x15be8`) adds the frame time × 1e6 while no event runs,
  saturating.
- `chapterCount` and `chapters` (`ChapterRecord`, 0x20 bytes): `Inventory_RecordChapter` (`0x8d1830`) records each
  instrument: its index (0–7), `bits` (a `std::bitset<16>`: bit 0 the Shovel obtained, bit 1 the Bow obtained, bit 2
  `HeartPieces` bit 24, bit 3 + i Chamber Dungeon set i owned) and the rupees; it writes nothing else of the record.
- No access found to `+0x6`, `+0x29`..`+0x3f` and the records' `+0x8`..`+0x1f`: probably unused space.

**InventoryItems** (`SaveCurrent`, 0x160 bytes): `GlobalSave_Reset` clears 0x160 bytes, and `SaveCurrent_LoadKeepLocation` (`0xdf8850`) copies 0x160 bytes from a loaded save, keeping `LevelName`, `Locator`, `RestartPos` and bits 0–2 of `RestartDirection`. A new game sets `LevelName` `MarinTarinHouse`, `Locator` `Opening`, `Health` 12, `EquipY` and `EquipX` 0xff, and picks `GridPuzzle` and `TilePuzzle` at random.
