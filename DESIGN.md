# LAS Archipelago: design

How the pieces fit and the contracts between them. TESTING.md covers the harness.

## Components

| Dir | What | Language / runtime |
|---|---|---|
| `apworld/las/` | Archipelago world (`Links Awakening Switch`) plus PC client | Python, AP's venv (`.venv-ap`, Py 3.12) |
| `patcher/` | Makes the mod for an AP patch file: the mod's files (Assets) applied to the player's RomFS dump, and the seed's `config.ini` and seed file; `patcher/modbuild` builds the assets with LASR's mod generator (MIT) | Python: pure Python plus PyYAML and `bsdiff4` (`requirements.txt`); the asset build also evfl, PyLibMS, oead, quicktex and Pillow (`requirements-assets.txt`) |
| `las-ap-exl/` | exlaunch module (subsdk9) derived from Owen-Splat/exlaunch (GPL-2.0) | C++, Docker `devkitpro/devkita64` |
| `scripts/` | Build, test and reverse-engineering tools (TESTING.md) | Python, Bash |
| `docker/ghost-relay/` | The ghost relay's container image (docs/ghost-relay.md) | Docker |

The module runs LASR's hooks and its code patches (`patches/patches.hpp`), except LASR's `CompareInt` event rewrite, which only LASR's own keysanity chest and present flows use; no flowchart of the mod asks `CompareInt` (`verify_patch.py` checks). The asset build's chests and presents keep the game's own add (`ChestRandomizer.writeChestEvent`), so a dungeon item with an index goes to that dungeon (the module's `AddItemID` hook; `dungeon_item`) and one without, as the Chamber Dungeon's keys, to the dungeon Link is in.

Flow:
1. AP generates a multiworld. The world writes `AP_<seed>_P<n>_<slot>.aplas` (the patch file).
2. The player opens the patch file with the Launcher, which starts the client with it. On Play, the client runs the patcher on the patch file plus the user's romfs dump, and installs its output (see Client install).
3. The game runs with the mod. The module listens on TCP port **43384**, or on the port `config.ini` sets (`[archipelago] port`); the client's `--game-port` must match. The test sandbox uses its own port so it runs beside a modded game.
4. The client connects to the AP server (websocket) and to the game (TCP), and relays checks and items.

## Assets

The mod's RomFS is the same for every seed: every file it changes or adds is an asset (`patcher/ap_assets.py`). `scripts/build_assets.py` (in `.venv-lasr`) builds them from a RomFS dump:
- LASR's mod generator with the patcher's edits (`patcher/modbuild/mod.py`, LASR's code in `modbuild/RandomizerCore`), run on a patch with the locations the world gives every seed (`make_test_patch.make`). LASR's settings read as the build sets them (`ap_options.LASR_SETTINGS`), and the options' edits are calls into `ap_option_edits.py`.
- The files only the build makes: `StartUp.arc` (`ap_ui.py`), `ItemArchipelago.bfres` (`ap_model.py`) and `Game.arc` (the map tracker's icons, `ap_map_icons.py`).
- The files the patcher makes itself from the player's dump (`ap_assets.MADE`), by a recipe in its own code, so the release carries none of their source's texture data. They are `PlayerGhost.bfres` from `Playerlink.bfres` (`ap_ghost_model.py`), and from `ObjTreasureBox.bfres` (`ap_chest_model.py`) `ObjTreasureBoxSeashell.bfres` and LASR's chests for its "Chest Types" (`ObjTreasureBox{Junk,Key,LifeUpgrade}.bfres`). `ap_bntx.py` reads and writes their BNTX textures, in the standard library. The build makes these files the same way and refuses a recipe that does not make the built file. The whole patch took 4.4 s on a Ryzen 7000-series desktop (measured 2026-11-04).
- It stores each other file that differs from the dump's in `patcher/assets/files` as a bsdiff4 patch against the RomFS file it comes from (against nothing for a file of the mod's own). `assets.json` holds each file's source and both files' SHA-256 (a file in `MADE` has no patch).
- `build.json` holds what the seed's files take from the build: LASR's tables, the mod's `Items.gsheet` rows, the map tracker's door places and dungeon chests, the messages Randomize Text shuffles, and the patch's shape: per location its local id and what it holds (`las_ap_patch.patch_shape`).
- The build also needs the BNTX editor (`RandomizerCore/Tools/bntx_editor`, GPLv3). `--check` builds and compares with the committed assets. After a change to anything the mod's files come from (`patcher/modbuild`, LASR's data, `map_positions.json`), rebuild and commit the assets.

The patcher (`las_ap_patch.py`) applies the patches to the player's dump, makes the `MADE` files from it and checks the results against `assets.json`; a dump of another game version fails with a message naming the file. It refuses a patch whose shape is not the assets' (one of another world version), and writes `config.ini` and the seed file from the patch.

Datasheets (`.gsheet`) are read and written by `modbuild/RandomizerCore/Tools/gsheet.py`, a pure-Python version of oead's gsheet module that LASR's `oead_tools` and `flag_manager` use. It writes what oead writes, byte for byte. `scripts/check_gsheet.py` compares the two on every RomFS datasheet and on any given files.

## Release

`scripts/build_release.py` (in `.venv-lasr`, after `build_exl.sh`) writes `build/release/LASAP-<world version>/`: `las.apworld`, the options template `Links Awakening Switch.yaml`, the setup guide `Setup guide.md` and, with `.venv-relay`, `LASGhostRelay.exe`. The template asks for the world's minimum Archipelago version (`archipelago.json`), not that of the checkout that wrote it.
- The world carries the patcher as `las/patcher/` (`PATCHER_FILES`): its Python files, LASR's data (`data/`), the assets and the game module. The asset build (`patcher/modbuild`) stays out; `test_install.py` patches seeds with its modules blocked (`BUILD_ONLY`). `build.txt` holds a hash of all of it. The repository's `LICENSE` goes in as `las/LICENSE.txt`. The world's own build ("Build APWorlds") is the same without it, and with the world's tests (`las/test`), which the release leaves out.
- The patcher runs in Archipelago's Python: pure Python plus PyYAML and bsdiff4, which Archipelago ships.

## Client install

- The client's Patch tab (`client_gui.py`) edits the settings in `host.yaml` under `las_options` (`host_settings.py`): `platform`, `emulator`, `game_file`, `romfs_folder`, `sd_card_folder`, `mod_folder`, `patcher_command`, `game_host`, the ghosts' settings (Ghosts) and the player settings below. `checklist.py` gives one status line per setting and decides whether the ones the platform needs are valid. The RomFS dump's line runs the check the patcher runs before patching (`patcher/romfs_check.py`, which `install.romfs_problem` loads from the world's copy of the patcher without unpacking it).
- **Gameplay options and player settings.** Settings that change how the game plays are options, so a seed plays the same for everyone in it: the option group "Gameplay" (`options.py`), which the patch file's `settings` carry under LASR's names. Settings that change only how the game looks or sounds are the player's, for every seed, stored in `las_options` (`host_settings.PLAYER_SETTINGS`): Blur Removal, Music, Randomize Text, Randomize Environments, Disable Low Health Beep, No 30 FPS Drops. The patch file carries their defaults; the client passes the player's values to the patcher as `--settings <JSON object>` (`las_ap_patch.PLAYER_SETTINGS`, the same keys; the patcher rejects any other). LASR does not implement Item Get Animations or Randomize Sound Effects, so they stay off.
  - `config.ini` `[movement]`: `full_360`, `walk_speed` and `swim_speed` (1.2 with Movement Speed on, 1.0 off; dashing keeps the module's default).
  - `config.ini` `[tweaks]`: settings LASR lists but never implemented, and settings of our own, done by the module (`mods/tweaks.cpp` unless named):
    - `instant_text`: a page of text shows whole as it appears, without its pauses; waits for input stay.
    - `no_low_health_beep`: no low-health warning.
    - `no_guardian_acorn`, `no_piece_of_power`: the buff that replaces an enemy's drop after a run of kills is picked in the game's code, not in `ItemDrop.gsheet` (scripts/re/ITEMS.md, Item actors, Buff drops); the module patches out its branch.
    - `easy_fishing`: a hooked fish's line never snaps (scripts/re/ACTORS.md, Fishing). LASR's Fast Fishing (a world option) only removes the instruments the bigger fish need.
    - `instant_pickups` (`disabled`, `incoming` or `everything`; Instant pickups).
    - `no_30fps_drops` (`emulator`, `true` or `false`): a frame that misses the display's vsync costs only its own time instead of dropping the game from 60 to 30 fps (scripts/re/FRAMEWORK.md, Frame pacing). `emulator`, the default, applies it where the kernel is not Atmosphere's.
  - `config.ini` also holds LASR's own settings: `[nice_items]` `bombs`, `hookshot` and `rod`, `[blur_removal]` `enabled`, `[damage]` `mode`, and `[randomizer]` `enabled`, `free_book` and `stealing`.
  - Randomize Enemies and Randomize Enemy Sizes are LASR's (`patches/enemies.cpp`; `config.ini` `[randomizer]` `enemies`, `enemy_sizes`), not seeded: a room's enemies change each time it loads. The logic does not change.
- `emulators.py` derives the rest from the emulator's executable:
  - Ryujinx: data folder `portable` next to the executable, else the per-user `Ryujinx` folder. SD card `<data>/sdcard`, mods `<SD card>/atmosphere/contents/01006BB00C6F0000`, game folders from `Config.json`.
  - Yuzu and its forks (Eden, Citron, Sudachi, Suyu, Torzu): data folder `user` next to the executable, else the per-user folder named after the emulator. `config/qt-config.ini` gives the SD card (`sdmc_directory`), mods (`load_directory`, plus `01006BB00C6F0000/Archipelago`; their SD card's `atmosphere/contents` loads only RomFS mods), RomFS dumps (`dump_directory`), game folders and recent files.
  - An SD card folder in the settings overrides the emulator's; for Ryujinx, its parent is the data folder, passed as `--root-data-dir` when it is not the default.
- Install (`install.py`): with `patcher_command` empty, the client runs the patcher on a worker thread of its own process: the release world's `las/patcher`, unpacked once per `build.txt` into Archipelago's cache folder (`las/patcher/<build>`), or the repository's `patcher/` from source. It imports `las_ap_patch` fresh for each run and calls `main([<patch>, "--romfs", <dump>, "--out", <temp dir>, "--settings", <player settings>])`, then drops the patcher's modules, which keep state in module globals. With `patcher_command` set, it runs that command with the same arguments as a subprocess. It then replaces `romfs` and `exefs` in the mod folder and copies the `config/lasr-exl` folder (`config.ini` and the seed file) to the SD card, `config.ini` last.
- The mod is current when the installed `config.ini`'s `[archipelago] seed_hash` matches the patch, both mod folders exist, and, for the built-in patcher of a release world, `config/lasr-exl/patcher_build.txt` names its `build.txt`, and `config/lasr-exl/player_settings.json` (written on install; the defaults when missing) holds the current player settings; then Play skips patching (`mod_state`). Reinstall mod patches regardless. Other Link's Awakening mod folders the emulator would also load are reported.
- The client never looks at running programs: the player chooses the emulator in the Patch tab the first time.
- Opened with a patch file, the client shows it in the Patch tab and connects to the patch's `server` as its `player_name`; it neither installs nor starts anything. Play (`/play` in a client run from source) installs the mod when it is not current, then starts the emulator with the game (unless the game is connected or the emulator this client started is still open).
- `file_types.py` registers `.aplas` for the current user (`HKCU\Software\Classes`), opening with the Archipelago Launcher, which hands the file to the client.

## Seed file

The patcher writes the per-seed tables the module reads to `config/lasr-exl/ap_seed.txt` next to `config.ini` (`patcher/seed_file.py`, `AP::SEED_PATH`): a `[<section>]` line before each section's lines. The module reads it once at boot (`config/seed_file.cpp`) and keeps it; the loaders keep views of its names, each ended with a 0, as the game reads some names to their terminator. Each line is space-separated fields, a name with spaces last. A section without lines is left out, and the module reads a missing section as empty. Sections: `names`, `indices`, `kept`, `models`, `start`, `shop`, `jumps`, `markers`, `shuffles`, `hints`, `map`; their lines are in the sections below that use them. `config.ini` stays apart: LASR's format, and the client reads the installed seed from it.

## Code the module writes

The module patches and hooks the game's code at boot, after an emulator may already have translated it: Ryujinx's translation cache (PPTC, on by default) translates the functions of earlier runs from the unpatched code. A translation that starts after a patched instruction and branches back over it survives a flush of the written line alone, so every code write in the exlaunch lib (`util::InvalidateWrittenCode`, used by the patchers and the hooks) also invalidates the text after it, up to `WrittenCodeReach` (`written_code.hpp`).

## Module source

`las-ap-exl/source/program/`, besides exlaunch's `lib/`:

| Folder | What it holds |
|---|---|
| `game/` | How the module reaches the game: addresses and typed symbols named as in `las.sym` (`addr.hpp`, `sym.hpp`), field access (`mem.hpp`), read-only views of the game's libc++ types (`stl.hpp`), and the game's objects as types. `game/hooks/` holds the hooks on the game's own systems that several features use. |
| `config/` | `config.ini`, parsed once at boot into `PatchConfig`, its choices as enums; the seed file's reader (`seed_file.cpp`, `fields.hpp`). |
| `patches/` | LASR's randomizer at runtime: the code patches (`patches.hpp`, tables of offset and instruction) and the hooks for enemies, fishing and seashells. |
| `mods/` | The optional changes `config.ini` turns on: controls, fixes, tweaks. |
| `ap/` | The Archipelago bridge: the network thread (`ap_net`), the game side (`ap_game`, and its parts that `ap_bridge.hpp` declares), each feature's own files, and the patcher's names (`ap_patcher.hpp`). |
| `ghost/` | Multiplayer ghosts: the network half (`ghost_net`), the puppets (`ghost_puppets` and its parts: replay, look, dither, instanced equipment, crowds) and the name tags. |
| `map/` | The map tracker: its icons, check list, hint strip and dungeon dots. |
| `music/` | The jukebox and its pause menu page. |
| `test/` | The test build alone (`LASAP_TEST`): the debug port, the trace, the input ops, the DBG commands and the probes of the ghosts and the map tracker. |

The root holds `main.cpp` (the install list, in order), `hooks.hpp` (the hook groups' `Install()`), `flags.hpp`, `test_only.hpp`, and the files exlaunch's lib includes by path.

The game's offsets and structures are in the reverse-engineering docs (`scripts/re/*.md`), its symbols in `scripts/re/las.sym`.

Conventions:
- Compiled sources' basenames are unique across `source/`: the build finds a source by its name alone. The `.cpp` files of `ap/`, `ghost/`, `map/`, `music/` and `test/` carry their folder's name as a prefix.
- Includes name paths from `source/program/` (`"game/sym.hpp"`) in four groups: the file's own header, the program's headers, exlaunch's and the SDK's (`lib.hpp`, `nn/…`), the standard library's; sorted within each group.
- A feature's header declares what other files call. Parts shared by a feature's own files and the test build go in its `*_impl.hpp` (`ap_bridge.hpp` for the bridge), in the feature's namespace; code used by one file stays in that file's anonymous namespace.
- Hooks are `HOOK_DEFINE_TRAMPOLINE`, `_INLINE` or `_REPLACE` structs in an anonymous namespace, named after the game function as `las.sym` names it, or after what the hook changes where it hooks inside a function. Each installs from its feature's `Install()` or `InstallHooks()`, with `InstallAtFuncPtr` on the typed symbol where `sym.hpp` has one: exlaunch then checks the hook's signature against the symbol's.
- The game's objects are read through the types in `game/`: one member per field, padding named `pad_<offset>`, and a `static_assert(offsetof(...))` per field. The game's `std::` objects are libc++'s and the module's standard library is libstdc++, so they are read through `game/stl.hpp`'s views, never as `std::` types.
- No function-local static that needs a constructor at run time: its first use hangs the game. Such objects go at namespace scope.
- Test-only code stays under `#ifdef LASAP_TEST`, a line of it in `TEST_ONLY(...)` (`test_only.hpp`). The test build's own code lives in `test/`; a feature keeps only small probes (a STATE field, a counter, a log).
- Style: 4 spaces, 120 columns; `g_` for globals, `k` for constants, PascalCase for types and functions.

## Item model: remote items

- Every randomized location in the patched game gives the **AP placeholder item**, with `index` = the location's **local id** (AP location id − `LOCATION_BASE`).
- The module's `Inventory::AddItemID` hook sees the placeholder item id, reports a check, and adds nothing to the inventory.
- Every real item, including the player's own, arrives from the server and is granted by the module. The client uses `items_handling = 0b011`: starting inventory comes from the patch file and the module grants it (Start state), so the server does not send it again.
- The activities the options leave out are optional (`lasr_settings.optional_locations`, `LASWorld.optional`). They are shuffled AP locations that the logic reaches only after the goal (their rule and the `Victory` event), and `set_rules` excludes them (`LocationProgressType.EXCLUDED`): Archipelago's fill gives them filler and traps from any player's pool, never progression or useful items (`Location.can_fill`), so no seed needs them. A slot with fewer filler and traps than optional locations excludes only as many, picked at random; the others take the slot's own items but small keys (an item rule). The patch's settings keep the options as they are (`Trade Quest` off), which PopTracker reads to hide those checks.
- A location the other options do not randomize gives its default item (`lasr_settings.unrandomized_locations`). It is an AP location holding its default item, locked (`LASWorld.locked`): it holds the placeholder, reports a check, can be hinted, and the item arrives from the server.
- The Trendy Game's prizes and the companions cannot hold the placeholder (LASR places no items in the crane game; its followers are no item locations). They keep their item in the game (`lasr_settings.kept_locations`; the patch's `placements` name it) and are locked checks. The companions are `moblin-cave` (Bow-Wow) and `rooster-statue` (the rooster), holding the items Bow-Wow and Flying Rooster, which the rules ask for.
  - The seed file's `kept` has per Trendy Game check the item's key, its index (-1 for none) and the local id; per companion `F`, the flag its joining sets and the local id (`BowWowJoin`; `RoosterFoundFlag`, which the patcher sets after the rooster's `Join` in `RoosterBones.bfevfl`).
  - The module reports a Trendy Game check when the game adds that item with that index (any for -1) outside a received item's grant, and a companion once its flag is set. The server's copy adds the item only to a save that lacks it (`ap_items.cpp`), as the Trendy Game decides which prizes it offers, and a companion's item adds nothing: the companion joins in the game.
  - Their heart pieces and seashells count as vanilla sources in the seed file's `indices`.
- Starting Gear (`start_inventory_from_pool`) comes out of the pool, so every copy it gives must be in it. Where a locked location holds the pool's copy, that location holds 50 Rupees instead and its item joins the pool (`LASWorld.replaced`, `LASWorld.content`); the Trendy Game's prizes and the companions stay. A pre-fill item in the starting gear goes into the pool too.
- With fewer than `EARLY_LOCATIONS_WANTED` locations reachable at the start, one of them holds an item that opens up the island, as LASR's Tarin rule does (`LASWorld._place_opener`, at the start of `pre_fill`).
- `small_keys`, `nightmare_keys` and `dungeon_items` each place their kind (`LASWorld.dungeon_item_placements`, `LASWorld.restricted`, `local_items`, `non_local_items`); `start_with` makes every copy a starting item. The patch's settings name them as LASR does (`Own Dungeon`, `Any Dungeon`, `Anywhere` for both worlds, `Start With`). The patch's `starting_items` leave the keys of a `Start With` setting out; the patcher gives every dungeon its keys (Start state). `generate_early` reads a `keys` option in slot data as both kinds, when Universal Tracker regenerates a seed that has one.
- The logic counts the small keys received; the game takes one per lock opened, and Archipelago's fill never spends a key, so it only proves that some order of play finishes the seed. `test_key_logic.py` checks that what the logic gives stays reachable whichever locks a player spends keys on (`key_locks.yml`, `key_logic.py`), crediting no key found behind a lock. `accepted` lists the targets the logic keeps short on purpose: Key Cavern's west and south rooms, where a bad spend can still dead-end a seed, and in glitched and hell Angler's Tunnel's small island.
- The shop slots LASR does not shuffle (`lasr_settings.fixed_locations`) keep their vanilla content and are AP event locations (no id) with the vanilla item locked, if it is progression. The Color Dungeon's blue rupees with Blue Rupees off are optional checks (above), drop actors as with it on (Drop actor, The blue rupees).
- Each location shows a model for the item it holds, picked by the world (`models.py`, `data/item_models.yml`). The patch file's `location_models` carries the picks.
- **Item models.** The module shows each location's model at runtime (`ap_models.cpp`; scripts/re/ITEMS.md, Row strings, Item node, Model makers), so the RomFS is the same for every seed's models.
  - Every AP location holds the placeholder, `ArchipelagoItem`. Its item actors name the location's token, `ap:<local id>` (`MODEL_TOKEN`), as their model file and model name, LEB parameters that their Npc row reads (`$1`/`$2`). Where an NPC component resolves its row's model (`NpcComponent_ResolveParam`), the module gives a token the model of the location's item, else the Archipelago model.
  - The seed file's `models` has `M <local id> <item id> <model file> <model name>` per location whose item shows its own model (item id -1 where the item-get has no model); `S <local id> <scale factor> <yaw or -> <rise>` where LASR places an item actor showing that model differently from one showing the token (`ground_transform`), which the location's item actors take and its chests and drop actors do not; `I <row key> <item id> <local id>` per LASR row that stands in for a location's item (`STAND_IN_ROWS`).
  - The module places such an actor when it is made (`Actor_Create`): its scale times the factor, its height plus the rise, its yaw the one given.
  - The item-get's item node takes the item id of the location added last, or for a stand-in row of that row's location (`ItemGetHolder_Make`): it holds up that item's model in that item's pose, while its text and fanfare stay the placeholder's. The items NPCs hold up (`ItemModel_Make`) and a find's popup take the same.
  - The shop's shelf shows its stand-in goods with the model of their location's item: the module sets their `ShopItem.gsheet` rows when the game makes the sheet (`Datasheet_Create`). LASR writes the Archipelago model into the sheets that name a location's model (`SHEET_MODEL_LOCATIONS`).
  - **Chests.** The chest's Npc row reads its model file and model name from LEB parameters 6 and 7 (`$6`/`$7`), and every chest names one (`_chest_contents`): an AP location's chests the location's chest token, `apchest:<local id>` (`CHEST_TOKEN`), the Chamber Dungeon's the plain chest, a chest holding this slot's own item the chest LASR's "Chest Types" gives it (`chest_look`). `models` has `C <local id> <size> <chest file>` per AP chest that is not the plain chest at size 1; the module resolves a chest token to its chest file, else `ObjTreasureBox.bfres`, and scales the chest by its size when it is made. The chest files are installed in every mod.
- The Archipelago model (`patcher/modbuild/ap_model.py`) is `ItemArchipelago.bfres`, with its own Npc entry, `ItemArchipelago`.
- Indexed items (heart pieces, seashells, golden leaves, heart containers, bottles, chamber stones) are counted by inventory bits: collecting one sets the bit of its source (its vanilla index, `index` in `logic.yml`), and the count is the number of bits set. A bottle's bit is its slot; one added with index -1 sets no bit and gives no bottle. The seed file's `indices` has, per source its kind (`S`, `H`, `L`, `C`, `B`, `P`), its bit and the local id of its location when shuffled, else -1. A received item takes the lowest free bit that no vanilla source of the seed sets, so a vanilla source collected later still counts, within the game's totals (heart pieces below 32, seashells below 50, heart containers below 9). A received chamber stone takes a chamber panel that Dampé makes at his next talk (scripts/re/ITEMS.md, Chamber stones). The shop's and the Trendy Game's stones stay vanilla, as owning a stone hides the Trendy Game's prize of that index and takes the shop's off sale; received ones take the indices of the Seashell Mansion's, the rapids race's and fishing's, and one more finds no index and adds nothing.
- The Memories map marks heart piece and seashell bit i at the vanilla place of source i. Received items hold the bits of shuffled sources, so the module (`ap_indices.cpp`) marks source i once it is done instead: a vanilla source by its bit, a shuffled one by its location's check.
- Item actors show by their flag or actor switch alone: LASR's `randoFixes` code patch stops the game's inventory check (`ItemActor_CanAppear`, scripts/re/ITEMS.md, Item actors), and LASR gives every heart piece and seashell actor a flag, so received heart pieces and seashells never hide an actor.

## IDs

- `ITEM_BASE = 0x4C410000` and `LOCATION_BASE = 0x4C420000`. The AP id is the base plus a stable offset.
- **Stable offsets.** They live in `apworld/las/data/ids.json` (`{"items": {lasr_name: offset}, "locations": {lasr_location: offset}}`).
  - The file is generated once from LASR's data in file order and committed.
  - New names are appended; existing offsets never change.
- **Local id.** A location's local id is its offset, which is the `index` stored in-game. It must stay below 65536.

## Names

- **AP display names** are human-readable, e.g. `Progressive Sword`, `Small Key (Tail Cave)`, `Tail Cave - Feather Chest`.
- **Location names** (`apworld/las/data/location_names.json`) are `<region or dungeon> - <label>`, the label as the PopTracker pack names the check, so hints, the spoiler, the in-game map and the tracker agree. `scripts/poptracker_map.py` finds dungeon checks in the pack by that label.
- **LASR names** (`sword`, `key-D1`, `D1-west-hallway`) are used in the patch file and in `ids.json`.
- The world keeps the mapping between the two.

## Save name

- A new file's name entry shows `UI:NameEntry_Default` until the player renames it, and OK keeps it (scripts/re/UI.md, Name entry). The module hands out the patch's `slot_name` for that label, from `config.ini` `[archipelago]` `save_name` (`ap_save_name.py` makes it), so a new save is named after the slot.
- The game takes up to 8 characters: its keyboard's limit, and OK cuts a longer name. From the slot name the patcher keeps printable ASCII except `@`, `%` and `\` (the keyboard refuses them) and `[`, `]` (they start a message tag), and the Latin-1 letters (`À`–`ÿ` without `×` and `÷`), which the game's fonts have. Runs of spaces become one space, and the result is cut to 8 characters with no space at either end. When nothing is left, the name is "Link".

## Start state

- The module gives a new save its starting items and start flags; LASR's start event (`PlayerStart.bfevfl`, `player_start.py`) keeps only its other changes (`makeStartChanges`: the rooster after D7, the companions' wait at a loading zone). The seed file's `start` (`start_lines`) has `I <item key> <dungeon index>` per starting item (-1 for none), `R <rupees>` (the option `starting_rupees`), `F <flag>` per start flag.
- **Items.** The patch's `starting_items`, a second sword, shield or bracelet as its upgrade, a dungeon item for its own dungeon (`dungeon_item`), and for each `Start With` setting every dungeon's items of that kind in place of the patch's (`START_WITH_KINDS`). The module grants them once Link stands in his first level (`ap_start.cpp`, `TickStart`), before the save's `RECV`, as received items are granted (`GrantItem`), and sets `APStartItems`. A save past Marin's talk at the wake-up (`OpTalked`) without `APStartItems` gets `APStartItems` alone, and no items.
- **Flags.** `START_FLAGS` and the flags of the settings in `START_SETTING_FLAGS`. The module sets them the first time Link stands in a level other than Tarin's house (`MarinTarinHouse`) while the save's `FirstClear` is unset, `FirstClear` last: the opening and Marin's talk in the house read `FirstClear`, `SwordGet`, `MarinRescueClear` and `WalrusAwaked`, as LASR's start event sets them on Link's first exit from a building. Without a `start` section the module gives nothing.

## Options

The RomFS is the same for every seed. What a LASR setting changes in the game's files, the mod holds both ways, and `config.ini` `[options]` (`ap_options.OPTIONS`: `open_mabe`, `classic_d2`, `completed_bridge`, `randomize_enemies`, `fast_fishing`, `shuffled_bombs`, `shuffled_powder`, `song_cutscenes`, `owl_overworld`, `owl_dungeons`, `ammo_ghost`, `bouncy_items`) picks one at runtime (`ap_options.cpp`). LASR runs with fixed settings (`ap_options.LASR_SETTINGS`); `config.ini` has the seed's (`las_ap_patch.config_text`).
- **Flags.** The module's `EventFlags_Check` hook answers `APOpt.<option>` (the option is on) and `APIf|<option>|<type>|<argument>|<type>|<argument>` (the first condition while the option is on, else the second, by `Conditions_Check` type and argument; type 0 holds unless its argument is `false`). Events' `CheckFlag` and sheet conditions of type 1, NPC layout conditions among them, reach it (scripts/re/EVENTS.md).
- **Events.** `ap_option_edits.gated` runs LASR's event edits and puts each link they change behind a `CheckFlag` of `APOpt.<option>`: case 1 the edit's target, case 0 the old one; the events and entry points they add stay as made. Gated: the owl statues' gifts (Owl Gifts, `owl_changes`; each statue's location has an id in every mod, the patch's `removed_location_ids` for those the options leave out), Marin's, Manbo's and Mamu's songs (Song Cutscenes), Kiki's bridge (Completed Bridge), the blue guard's powder (Shuffled Powder), and the drops' launches (Bouncy Items).
- **Sheets.** `option_if` conditions in `Npc.gsheet`, `Conditions.gsheet` (`ShopBombCondition`) and `CranePrize.gsheet`. The module edits some sheets as the game makes them (`Datasheet_Create`): `FishingFish` (Fast Fishing: every fish that gives an item gives `ClothesGreen`, which the game turns into the row's item), `FishingSpot` (Easy Fishing: Ol' Baron's weight in the deep spot), `ItemDrop` (Disable Guardian Acorn and Piece of Power: the row's drop empty) and `Npc` (Bouncy Items: `ItemAPDrop` takes `ItemAPDropBall`'s row, its name kept).
- **Rooms.** The module's `Room_OnLebActor` hook (scripts/re/ACTORS.md, Rooms) leaves out, retypes or moves LEB actors by key (`kActorEdits`) for Open Mabe, Randomize Enemies, Classic D2, Completed Bridge and the Ammo Ghost. Drops that chests and owl statues launch are left out without Bouncy Items.
- **Shuffles** (player settings Music, Randomize Environments, Randomize Text; `ap_shuffles.cpp`, `patcher/ap_shuffles.py`). The seed file's `shuffles` has, when one is on, a line per swap: `M <track> <track>` (`-` for none: Music Removed), `E <environment> <environment>` (one of its kind, top-down or side view), `T <File:Label> <File:Label> <fix>` (LASR's dialogue and Talker pools). The module swaps the name as the game looks it up: `BgmManager_Play` (the Jukebox's chosen track is not swapped), `LevelEnvironment_Find` and `MessageManager_Find`. `<fix>` adds (`+`), takes off (`-`) or keeps (`=`) the input wait at a moved message's end. A message ending in the hold tag (`[1:6]`: the window stays until its event closes it) swaps only with another such, as any other event would wait for it for good. Dampé's and the Chamber Dungeon's messages, the egg book's and the shop's price tags stay out of the pools (`_kept`, `_valid`).

## Patch file (`.aplas`)

An Archipelago player container (`container.py`, `APPlayerContainer`): a zip with `archipelago.json` (game, player, player name, server; WebHost fills in the room's server) and `patch.json`. The patcher also accepts a bare `patch.json`. `patch.json` is UTF-8 JSON:

```json
{
  "format": 1,
  "seed_name": "<AP seed name>",
  "player": 1,
  "slot_name": "Link",
  "seed_hash": "<8 hex chars; also in slot_data; the game reports it in HELLO>",
  "settings": { "<LASR setting key>": "<value>" },
  "starting_items": ["<lasr item name>"],
  "placements": { "<lasr location name>": "<lasr item name> | \"ap-item\"" },
  "location_ids": { "<lasr location name>": "<local id (int)>" },
  "removed_location_ids": { "<lasr location name>": "<local id (int)>" },
  "optional_locations": ["<lasr location name>"],
  "location_names": { "<lasr location name>": ["<AP item name>", "<owner's name, empty for this slot>"] },
  "location_models": { "<lasr location name>": "<lasr item name whose model it shows>" },
  "location_chests": { "<lasr location name>": ["<LASR item type: chest size>", "<chest texture or null>"] },
  "dungeon_entrances": { "<dungeon>": "<dungeon>" },
  "hints": { "<hint source>": { "kind": "<hint kind>", "text": "<hint text>", "player": "<slot of the location (int)>", "location": "<AP location id (int)>" } },
  "ghost_secret": "<32 hex chars, the same in every LAS slot's patch of the multiworld>",
  "ghost_relay": "<the generating host's relay address, or empty>"
}
```

- `settings` uses LASR's `SettingsManager.fetch()["Settings"]` keys (`lasr_settings.lasr_settings`), as the options set them; the player settings hold their defaults (Client install). "Bad Pets" is always off: it is not supported.
- `starting_items` are what a new save starts with (Start state).
- `placements` covers every LASR item location: AP locations are `"ap-item"`, the kept and fixed ones carry their vanilla item. Owl statues that give no gift are left out, as in LASR.
- `removed_location_ids` gives the owl statues the options leave out their ids, so every mod has each statue's gift (Options). It is optional.
- `optional_locations` lists the AP locations of the activities the options leave out (`LASWorld.optional`). The map tracker leaves them off the map. It is optional: without it they show.
- `location_names` covers the AP locations. The patcher writes it to the seed file's `names` for the in-game text, which gets the same names at runtime from the client.
- `location_models` leaves out locations that show the Archipelago model. It is optional: without it every location shows the Archipelago model.
- `location_chests` gives each AP location's chest the size and texture of LASR's "Chest Types" setting (option `chest_appearance`, `lasr_settings.chest_look`): for this slot's items as LASR's shuffler gives them, and `seashell` for seashells; for other players' items, `important` for progression, `good` for useful, and `junk` with the junk texture for filler and traps. The patcher turns it into the module's chests (Item models, **Chests**). It is optional.
- `dungeon_entrances` maps each dungeon's door to the dungeon it leads into (Shuffled dungeons): an identity map with the option off.
- `slot_name` is also a new save's name (Save name).
- `ghost_secret` groups the multiworld's LAS players on the ghost relay (Ghosts). It is optional: without it the client shows no ghosts.
- `ghost_relay` is the generating host's `las_options.ghost_relay`, used by a client whose own setting is empty (Ghosts).
- `hints` gives each in-game hint source its kind and text (In-game hints). `player` and `location` name the hinted location when reading the hint makes a server hint. It is optional and empty with the option off.

## slot_data

`{"seed_hash": str, "goal": str, "instruments_required": int, "instruments_known": bool, "seashells_required": int, "seashells_known": bool, "death_link": bool, "location_count": int, "settings": {...}, "logic": {...}, "options": {...}, "starting_instruments": [...], "dungeon_entrances": {...}}`

`goal` is always `wind_fish`: the goal is reaching the Wind Fish, through the Nightmare after the egg opens with `instruments_required` instruments or, on a seashell hunt, straight from the egg's door once it opens with `seashells_required` secret seashells (Goal). The count the goal does not take is 0; trackers tell the goal by `options`' `goal`. `instruments_known` and `seashells_known` are false for a count left to chance (Goal, **Hidden count**); slot data without them counts as known.

`settings` holds the seed's LASR settings that decide which checks exist and what reaches them (`TRACKER_SETTINGS` in `lasr_settings.py`), under LASR's names and values, as the options set them. Trackers such as PopTracker packs read them on connect.

`logic` is what the client needs to evaluate the world's rules for the map tracker (`tracker.py`): `preset` (the logic option), `tokens` (the settings tokens the rules test), `vanilla` (fixed locations that keep a progression item, whose items count as found once they are reachable), `locked` (AP locations holding their own progression item; the map counts their items once received, like any other), `optional` (`LASWorld.optional`, in logic only once the goal is) and `starting` (the slot's starting items: the module grants them from the patch's `starting_items`, so the server does not send them).

`dungeon_entrances` is the patch's (Shuffled dungeons). The map tracker's rules (`LogicTracker`) follow it.

`options` (the world's own option values, `SLOT_DATA_OPTIONS`), `starting_instruments` (the LASR instruments the slot starts with) and `dungeon_entrances` let Universal Tracker regenerate the slot without a YAML: the world sets `ut_can_gen_without_yaml`, `interpret_slot_data` returns the slot data, and `generate_early` takes them from `multiworld.re_gen_passthrough` instead of the YAML and the seed's random (`test_universal_tracker.py` compares the regenerated slot). Universal Tracker asks the server for the starting inventory (items_handling `0b111`), which the LAS client leaves out.

**Deferred.** Universal Tracker leaves what the player finds in the game to the player, through its deferred entrances: the world lists `las_sign_<team>_<slot>` and `las_doors_<team>_<slot>` (Data storage) in `found_entrances_datastorage_key`, and Universal Tracker passes each one's value to `reconnect_found_entrances` when it changes. Its host.yaml setting `enforce_deferred_entrances` (`multiworld.enforce_deferred_connections`) decides: `on` and `default` defer (`LASWorld.deferred`), `off` shows everything at once.
- A count left to chance takes every instrument or seashell until the sign key is true (Goal, **Hidden count**).
- With shuffled dungeons the doors' entrances stay unconnected (`connect_entrances`) until the doors key names them; once eight are found the ninth is connected too, as its dungeon is the one left (`connect_doors`). An unconnected door shows in Universal Tracker's list of unconnected entrances while it is reachable, and the dungeon behind it is out of logic. Universal Tracker sweeps only event locations, so it counts a locked location's item once the server sends it (after the check); the LAS client counts it once the location is reachable.

## Data storage

The client writes these keys from the game's lines; `SIGN` and `DUNGEON` count only from the game of the slot's seed.
- `las_level_<team>_<slot>`: the level the game shows (`Field`, `Lv01TailCave`, ...), from `LOG level`; trackers show the current dungeon's map.
- `las_sign_<team>_<slot>`: `true` once the sign at the egg's stairs is read, from `SIGN` (Goal, **Hidden count**).
- `las_doors_<team>_<slot>`: `{door: dungeon}` for each dungeon door found, by `dungeon_entrances` names, from `DUNGEON` (Shuffled dungeons, **Doors found**).

## Game ↔ client protocol (TCP 43384, game listens)

UTF-8 lines terminated by `\n`, fields separated by single spaces. The game accepts one client at a time. The client sends `PING` every 2 s, and the game drops a client that has been silent for 10 s.

- The game never waits for the client: the network thread sends on a non-blocking socket, without the lock the game thread takes to queue a line. A client that takes nothing for 10 s while lines wait, or leaves more than `kMaxWaiting` waiting (`ap_net.cpp`; the module's heap is small), is dropped; it connects again, and its `SYNC` brings the game's state back.
- The client logs and skips a line from the game it cannot handle (a field it cannot read, a line longer than its reader's limit); the connection goes on (`LASContext.on_game_line`).
- The game reads a line's fields with `Fields` (`config/fields.hpp`, also the seed file's reader). It answers an unknown command with `ERR unknown command <command>` and an `ITEM` or `NAME` missing a field or with a non-number where a number goes with `ERR malformed <command>`; an id list (`CHECKED`, `INLOGIC`, `DOORS`, `HINTED`) ends at its first field that is not a number, and a `GHOST` line with a bad field is skipped.
- The game listens and the client connects, so a Switch needs no address of the PC. The network thread polls for a client rather than blocking in `Accept`, which would keep emulators from closing the game.
- The client drops a connection that gets no `HELLO` within 5 s: the game serves another client (a second client window), which the Patch tab then says, and Play starts no emulator.

**Client → game**

| Line | Meaning |
|---|---|
| `PING` | Keep-alive; the game answers `PONG` |
| `ITEM <n> <item-key> <count> <dungeon> <location> <item name>\|<sender>` | The n-th received item (1-based AP index). `item-key` is the game's item symbol (`SwordLv1`, `SmallKey`, …). `dungeon` is the dungeon level for dungeon items, else `-1`. `location` is the local id the item came from when it is this slot's own, else `-1`. `sender` is empty for own items and items from the server. The game applies it only if `n` = stored count + 1, then answers `RECV <count>` |
| `NAME <local id> <item name>\|<owner>` | What a location holds, from `LocationScouts`; `owner` is empty for this slot's items. Sent for every location on connect |
| `NOTICE <text>` | A toast (In-game text, **Toasts**); `\|` starts a new line. The client sends its connection notices this way |
| `SERVER 1` / `SERVER 0` | Whether the client is logged into the slot of the game's seed: sent when the game connects, when the slot connects and when the server goes away |
| `SYNC` | Asks the game to send `RECV <count>` and `CHECKS ...`, and `GOAL`, `SIGN` and the read hints when they apply |
| `CHECKED <id> <id> ...` | Locations the server has as checked, for the map tracker: all on connect (possibly several lines), then new ones from `RoomUpdate`. Kept in memory only |
| `INLOGIC CLEAR` / `INLOGIC <id> <id> ...` | Locations in logic for the items received, for the map tracker: `CLEAR`, then all of them (possibly several lines), each time the set changes. Kept in memory only |
| `DOORS CLEAR` / `DOORS <id> <id> ...` | Dungeon locations whose dungeon's door is reachable for the items received, for the map tracker's hidden dungeon icons: `CLEAR`, then all of them (possibly several lines), before `INLOGIC` each time either set changes. Kept in memory only |
| `HINTED CLEAR` / `HINTED <id> <id> ...` | Locations of this slot holding a server hint not yet found, for the map tracker (Map tracker, **Hints**): `CLEAR`, then all of them (possibly several lines), on each game connection and each time the set changes. Kept in memory only |
| `DEATH [<player>]` | DeathLink: another player died; a toast names them (see DeathLink) |
| `GHOSTNAMES 1` / `GHOSTNAMES 0` | Whether name tags show over the ghosts (Ghosts); sent on each game connection and when the setting changes |
| `GHOSTS 1` / `GHOSTS 0` | Whether the client relays positions (joined to the ghost relay); with 0 the game sends no `POS` and shows no ghost (Ghosts) |
| `GHOST <n> <level> <x> <y> <z> <yaw> <anim> <anim frame> <upper anim> <flags> <time> <shapes> <tunic> <eye> <mouth> <ear> <slot name>` / `GHOST <n> off` | Another player in this area, in ghost slot n (0–29), with the time its game took the position (ms, 16 bits), or nobody there any more (Ghosts) |
| `MSG <text>` | Logged by the module |
| `DBG <cmd> [args]` | Test-only debug commands (see the module source) |

**Game → client**

| Line | Meaning |
|---|---|
| `HELLO <proto=2> <seed_hash>` | Sent on connect |
| `PONG` | Answer to `PING` |
| `ERR <text>` | An unknown command or a malformed `ITEM` or `NAME` (above) |
| `RECV <count>` | Number of items applied (saved; Persistence): in answer to `ITEM` and `SYNC`, and once each time a save has loaded (from the title or the System page's Load), so the client sends the items it lacks |
| `CHECK <local_id>` | A location was collected |
| `CHECKS <id> <id> ...` | Every collected location, sent on connect and on `SYNC` (possibly several lines). The client keeps the checks and the goal of the game connection (a new `HELLO` drops them) and sends them only into a slot whose seed hash is the game's |
| `HINT <slot> <location id>` | An in-game hint was read (its flag is set): once per hint and connection, and all read hints again on `SYNC` |
| `GOAL` | Goal completed: Link entered the `Ending` level, or the `ShadowClear` flag is set (also resent on `SYNC`) |
| `SIGN` | The sign at the egg's stairs has been read (Goal, **Hidden count**): once, and again on each `SYNC` |
| `DUNGEON <n>` | The player has entered dungeon `Lv<n>` (1–8, 10 the Color Dungeon; Shuffled dungeons, **Doors found**): once per connection, and again on each `SYNC` |
| `DIED` | DeathLink: Link died, and no Secret Medicine saved him (see DeathLink) |
| `DEATHDROPPED` | DeathLink: a `DEATH` arrived with no save loaded and was dropped; the client logs it |
| `GHOSTNAMES 1` / `GHOSTNAMES 0` | The player turned the ghosts' name tags on or off in the game (d-pad up); the client keeps it as its `ghost_names` setting and sends it back |
| `LOG <text>` | Debug text; `LOG level <name>` on every level change and when a client connects |
| `POS <level> <x> <y> <z> <yaw> <anim> <anim frame> <upper anim> <flags> <time> <shapes> <tunic> <eye> <mouth> <ear>` / `POS none` | Link's position while the client asks for it (`GHOSTS 1`), with the time it was taken (ms), or no player (title, file menu, level load, leaving a level by its exit) (Ghosts) |

Lines that need a loaded save (`ITEM`, `SYNC`, `DEATH`, most `DBG`) wait until the player has stood in the current level for a moment (`kSettleMs` in `ap_game.cpp`), counted again from each level reload; other lines are handled immediately. A jump within a level keeps Link and the level's name, so the module marks each level jump from its start (`LevelManager_LevelJump`) until the level arrives (`SetCurrentLevel`, `game/hooks/level.cpp`) and counts the moment again from there. From the game over menu on they wait until its Retry has reloaded the level, as do item displays: Retry stands Link up with full health before the reload, under the same level name.

**Items with special handling in the module**
- Progressive sword, shield and bracelet arrive as their Lv1 key; the module upgrades when LASR's `*FoundFlag` is set.
- Seashells, heart pieces, heart containers, golden leaves and bottles take the lowest in-game index that is unused and that no vanilla source sets (Item model: remote items).
- The Secret Medicine is a single inventory bit, and the pool has three. One received while Link holds one shows its item-get and waits in the save (`APMedicine0`..`APMedicine1`, a count up to 3); once Link is free with none, the module gives the next.
- Traps (`*Trap`, `$ENEMY`, the Zol Trap) wait like item displays (below). Unknown keys are logged and counted as applied.

**In-game text**
- A found placeholder says what it is: "You found <item> for <player>!", or "You found your <item>!" for this slot's own items. The patcher writes the names to the seed file's `names` (`NAME` lines without the command), which the module reads at boot, so this works before the client connects; `NAME` lines replace them. A location without a name says "You found an Archipelago item!".
- **Toasts.** Notices that are not items, and items with Instant Pickups, show in the autosave popup (`ThrobberSave`; scripts/re/UI.md, Autosave popup) in its auto mode (`ap_text.cpp`), which does not stop the game. The asset build widens its text pane and its text buffer (`ap_ui.py`, `StartUp.arc`). A toast waits while the popup is busy; a save during a toast shows the toast's text. The module shows `NOTICE` lines, and "Archipelago client disconnected" when the client goes away. While the client or the server (`SERVER`) is not connected, it shows "Archipelago client not connected" or "Archipelago server not connected" after a while in a level and then at intervals (`kOfflineNoticeMs`, `kOfflineRepeatMs` in `ap_game.cpp`).
- A received item from another player names the sender. Own items found in this save since it loaded are not shown again; other own items and server items show the item's native text, except items whose native text names their vanilla source (the Boomerang, the capacity upgrades).
- In these texts long item and player names are clipped, UTF-8 kept whole (`ap_text.cpp`). A shop's price tag (the buy dialog's first line) holds 46 characters: a longer item name ends in "…" and the owner stays.
- **The shop.** Each AP slot of the shop (`ShopRandomizer`'s `TEXT_TO_CHANGE`) names its item on its price tag and in its buy dialog (System.msbt). The seed file's `shop` (`shop_lines`) has per slot the two labels and the location's local id; the module (`ap_text.cpp`) puts the name in both. A slot without a name says "Archipelago Item".
- The asset build adds the messages `Place:ArchipelagoItem` and `System:APReceived` and the Item event entry point `APReceived`. The module hooks the game's MSBT label lookup and text getter and hands out the text for these two messages (`ap_text.cpp`).
- The module learns the location from the placeholder's `AddItemID`, so placeholder flows add the item before playing the item-get (LASR's item-get chains and a TreasureBox branch). That location names the found text until the player is free again.
- The Seashell Mansion's presents add their item after the item-get. The module reads the location from `ShellMansionMaster.PopBox` when the present appears.

**Showing received items**
- The module grants an item the moment its `ITEM` line is handled, and queues a display of it.
- A display is the game's own item-get, played as an event (Instant Pickups disabled, the default; Popup below): the asset build adds the `Common.bfevfl` entry `APItemGet`, and the module starts it and hooks the item-get (`Player_ItemGetSequence`) to show the received item and its text instead (`ap_itemget.cpp`; scripts/re/ITEMS.md, Item-get). An item-get outside an event leaves the camera zoomed in.
- A display starts once the player has been free for `kFreeSettleMs` and holds nothing over his head: an item-get takes a held object out of the game, such as a shop item. Displays run one at a time. In the trendy game (`CraneGame`) they wait until Link leaves: Link counts as free while the player steers the crane, which a display would cut off.
- LASR's songs and tunics show NPC models: Marin, Manbo and Mamu, and the Color Dungeon's guards (the asset build gives the tunics' `Items.gsheet` rows the guards' npcKey). NPC models stand on their feet where item models are centred on their origin, so the module places, turns and sizes these five in every item-get (`g_HeldModelFixes` in `ap_held_model.cpp`), from their bind-pose bounds (`scripts/model_bounds.py`).
- **Shorter item-get.** Every item-get is shorter (TESTING.md, Item-get timing): Link lowers the item as the text closes, instead of waiting for the fanfare to end (`ap_itemget.cpp`; scripts/re/ITEMS.md, Item-get).
- **Instrument songs.** The game plays each instrument's own song in the pedestal's whiteout, while its `Items.gsheet` rows all name the shared fanfare (scripts/re/FRAMEWORK.md, Audio). The asset build puts each one's song in its row (`INSTRUMENT_JINGLES`), so every item-get and find of an instrument plays it, and a received one's popup too.
- **Popup** (Instant Pickups on `incoming` or `everything`). A received item shows as its 3D model above Link's head and a toast instead of an item-get, and play goes on. It starts once the player has been free a moment (`kPopupSettleMs`), also while he holds something over his head and in the trendy game, and the next one waits until both the model and the toast are gone. It plays no fanfare, but an instrument's song. Traps still play their effect as an event.
  - The model is made as the NPCs that hold an item make theirs (`ItemModel_Make`), owned by Link and posed by the module each frame; a level load takes it with Link (`ap_popup.cpp`). It shows at the item-get's scale and pose for its item (Item models; `g_HeldModelFixes`).
  - Link walks on while it shows, also into a doorway, whose roof would cut into it, so its opaque shapes draw after the rest of each pass, over the world (`ap_popup_draw.cpp`; scripts/re/MODELS.md, Draw tree).
- With three or more displays waiting, filler (rupees, ammo, drops) is granted without a display. The queue is not saved; a restart drops pending displays, not items.
- A trap plays LASR's effect as the `Common.bfevfl` event `AP<trap key>` the asset build makes with LASR's trap flow, and the autosave popup names the trap and its sender. In the normal damage mode a trap leaves at least a quarter heart (the module raises health first if needed).
- **Zol Trap** (`$ENEMY`; `ap_zol_trap.cpp`). A chest at an AP location holds the placeholder instead of the game's `$ENEMY` (`ObjTreasureBox_PopEnemy`), so the trap comes back from the server as a received item. It plays no event: its notice shows as the other traps', then the Zols appear. When a placeholder is found, the module keeps the chest nearest Link in his zone with the location; an own Zol Trap of that location lets out the chest's Zol while the chest is still in Link's zone. On the overworld (`Field`), where the game's Zol falls through the ground, the module makes it between the chest and Link. Otherwise two `EnemyZolGreen` appear beside Link, owned by his zone's room, so they go with the room and a level jump takes them away. With no room of Link's zone the trap costs one heart instead.

**Drop actor** (`ap_drop.cpp`, `patcher/modbuild/ap_drop.py`)
- Every location LASR shows as a stand-in item holds `ItemAPDrop`, an actor type of the module's own: drops from bushes, rocks, pots, trees and holes, the dungeons' falling keys, the Kanalet Castle golden leaves, the dig spots' buried items (LASR's `*_ROOMS` tables), the bosses' items, the ghost's reward and the Color Dungeon's blue rupees. The asset build gives each stand-in the actor id `DROP_ACTOR_ID` (an empty id of the game's actor table) and the name `DROP_ACTOR`. - **Class.** At boot the module fills that id's actor table entry with an item class of its own on the item base (scripts/re/ITEMS.md, Item actors), with the Npc row `ItemAPDrop` and the small key's behaviour. The one game function it hooks is `ItemActor_Create`, for the bosses' items.

Each boss's room has a drop (`BOSS`) linked to the boss, switch 0 the global flag `APBossDrop_<location>`, switch 1 `APDropGet_<location>`. The `ItemActor_Create` hook makes none of these items: the boss's drop, not taken, moves to the item's start, takes its launch and turns its switch 0 on. The module carries the bind-pose centre and radius of every model a drop can show, the same in every seed (`ap/drop_bounds.hpp`, written by `scripts/drop_bounds.py`; `verify_patch.py` wants bounds for every drop's model), and gives each drop the pose pair that centres those bounds on the root, with the radius at most `kModelRadius`.

The drop is a ball, and the AP chests and owl statues get drops too. Every mod has the ball and those drops (Options). The ball's constants are `ap_drop.py`'s and `ap_drop.cpp`'s; the game's physics are in scripts/re/ITEMS.md (Physics, Water).
  - **Launch.** A ball has its own `NpcPhysicsTraits` row. It leaves the ground at a random speed up and outward, so it may get away from Link: over a wall, onto a ledge, into water or into another room (Rooms). Its `fall` skips the 2 s wait (a `CheckFlag` of `APOpt.bouncy_items`), as the ball's physics do not run during events. A lost ball pops out again when Link repeats what dropped it once the level loads anew.
  - **Rooms.** A launched ball roams (`Roams`: not `STANDS`, `PLACED` or `REFALLS`). It takes zone -1, so that Link's zone does not suspend it, and each item update it joins the room it is over (`JoinRoom`, `Room_AdoptActor`), so that it lasts as long as that room is loaded, not its chest's. Over no loaded room it falls out of the world, and the game destroys it. A room that reads a live roaming ball's record leaves it alone (`DropStaysOut`): it makes no drop, as the game makes none for a live key, and the game's adoption would pull the ball back.
  - **Chests.** Each AP chest (`CHEST_ROOMS`, but for `CHEST_SKIPPED`) has a drop (`CHEST`) linked to it, on the tile in front of it. The chest holds `APDropChest`: `TreasureBox.bfevfl` gives the AP placeholder without Bouncy Items; with it, it plays no item-get but turns on the chest's switch 2 (unused by chests), a level flag of its own and the drop's switch 0: the launch flag. The drop's switch 2 is the chest's opened flag (its switch 1, saved). `ap_drop.add` runs after `ap_map_edits`, which finds the AP chests by their placeholder. The ball's landing spot is rolled on each opening; nothing makes sure it is floor Link reaches. In `taltal-5-chest-puzzle` all five chests have a drop, with one take entry.
  - **Owl statues.** Each owl statue has a drop (`OWL`) on the tile in front of it. In its flowchart (`OWL_FLOWS`) LASR's gift becomes turning on the statue's switch 2 (`LAUNCHED_SWITCH`), the drop's switch 0, a launch flag as a chest's. The drop's switch 1 is the location's flag, so examining the statue launches the ball until it is taken.
  - **Opened when taken.** Opening the chest sets its opened flag, and the flag stays on while the ball is out: the chest closes if it reads the flag off as an event runs, also another item's pickup (scripts/re/ACTORS.md, Persistence), so nothing turns it off in play. A chest made anew while its ball is out, in another room, is open, with no second ball. When the chest's room reads the drop's record with no ball out and the location not collected (`DropStaysOut`, `CollectedHere`), the flag goes off, however it came to be on: the chest is made closed and launches the ball again when opened. The launch flag is off with the level's load, or the drop's factory turns it off when only the room loads again (`Unlaunch`), so a ball never waits at its spawn. It is a level flag that no actor of the level's rooms and no RomFS flowchart uses (`FLOW_LEVEL_FLAGS`, `LEVEL_FLAG_TOP`); `verify_patch.py` checks that only the chest (or owl statue) and its drop use it.
  - **Motion.** The module's item update (`ItemUpdate`, after the item base's) adds what PhysX lacks: rolling resistance and the bounce off a wall met below the scene's bounce threshold. The ball floats on the drawn water: a probe under its root (`kProbeBelow`, `SetProbe`) and a spring around `kRestDepth` (`LiftAt`), which the module adds within `kLiftBand`, where the item base adds none.

On `everything`, the module's hook returns the game's ready future (`Delay_Make(0)`) instead, and the find shows as a popup.

So an event that gives several items shows them one after another before it goes on: the Fairy Queen's two show before her whiteout. In an event Link moves on through it does not wait.

It also stays for the received-item event. A find while Link holds something over his head is instant too, and he keeps holding it. The shop takes its item from Link as he pays (`RemoveGoods`), so its item-get is a find.
- Link moves on through a pickup's event. An event's start holds every actor still and puts Link in the demoEvent state (scripts/re/EVENTS.md, What an event's start does to the actors). The hooks `Player_OnEventStart` and `Player_OnEventEnd` leave him out of an event whose flow, read from the running flowchart in memory, has Link do nothing but item-gets the module makes instant, when he moves freely as it starts (`MovesFreely`).

**Shuffled dungeons** (option `shuffled_dungeons`, settings key `Shuffled Dungeons`; `lasr.door_logic`, `lasr.dungeon_logic`, `patcher/ap_entrances.py`)
- Each of the nine dungeons' overworld doors leads into a random dungeon (`lasr.shuffle_dungeons`). `dungeon_entrances` names each door by its dungeon's LASR region (`tail-cave`, ...) and maps it to the dungeon it leads into.
- **Logic.** In LASR's logic a dungeon's region node is its inside, and its conditions are its door's. The Face Shrine's region is either of its entrance rooms (`D6-8D`, or `D6-3A`, which its side entrance reaches); its door is the outside part of `D6-8D`'s conditions. LASR's shuffler moves only `condition-basic`, and moves the Face Shrine's region with its entrance rooms.
  - The world (`lasr.door_logic`): each door is a region of its own (`<dungeon>-door`) with the door's conditions and an AP entrance (`<Dungeon name> Entrance`) into the region of the dungeon it leads into (`lasr.dungeon_region`), which `connect_entrances` connects. Those regions have no other way in (`lasr.ENTERED_BY_DOOR`), but `D6-8D` keeps the way in from `D6-3A`. The logic is the same for every map of the doors.
  - The top of Turtle Rock (`Field_01A` to `Field_01C`) is a region of its own, `turtle-rock-top` (`lasr.EXTRA_NODES`, `lasr.MOVED_LOCATIONS`), entered from Turtle Rock's `D8-4C`, so it follows Turtle Rock through whichever door leads into it. Neither LASR nor the world has a way onto the top from a warp point or back through the side doors: the warp point unlocks only once Link stood on it. Shuffled warp points would need both (LADXR's `dungeon8.py`).
  - `lasr.dungeon_logic` gives each dungeon the conditions of the door that leads into it. `test_logic.py` checks the world's entrances against LASR's evaluator with these conditions.
  - The client's map tracker (`LogicTracker`) enters a dungeon's region from the region of the door that leads into it once that door is found (**Doors found**), as Universal Tracker does. `test_tracker.py` checks the client's rules against the world's.
- **Patch.** The rooms and flowcharts keep their vanilla targets; the module leads the level jumps (`LevelManager_LevelJump` hook, `ap_jumps.cpp`). The seed file's `jumps` (`jump_lines`) has `<from level> <level> <locator> <new level> <new locator>` per led jump, a jump from `<from level>` to that level and locator going to the new one instead. Per door that leads into another dungeon (`ap_entrances.jumps`), the overworld's jump to the door's dungeon entrance goes to the entrance of the dungeon behind it, and that dungeon's jumps to the outside of its own door go to the outside of the door that leads into it. **Map tracker** (option `map_tracker`, settings key `Map Tracker`; `patcher/ap_map.py`, `modbuild/ap_map_edits.py`, `map/`)
- The pause map shows the slot's unchecked locations, and the whole overworld and every dungeon room are revealed. Off for a patch without the settings key. - **Overworld reveal.** The map shows an area once its flag `UI_FieldMapTraverse_<area>` is set, and plays the reveal once `UI_FieldMapOpen_<area>` is not; the `CheckFlag` hook answers both as set. `LocationName.gsheet` gates the area name banners on the same flags.
- **Dungeons.** While Link is in a dungeon the module fills its visited-room mask, so every room counts as visited in the save, and an inline hook makes the compass and the map read as owned for the map screen only; the sidebar still shows the items Link has.
- **Out-of-logic toggle.** The map's X button hides and shows the out-of-logic icons instead of opening the memories, on both map pages (`UI:MapCaptionMemory`). A hook after the icon setup hides out-of-logic markers while the toggle is off; toggling sets their visible bit on the open page. The toggle is kept in memory only.
- **Skipping a check.** A on an overworld icon of one unchecked location marks it skipped or unmarks it. A skipped location counts as checked on the map, and it leaves a group's to-do count but stays in its unchecked count. A location checked in the game or on the server cannot be marked. The client and server are not told, and the module keeps the mark per seed (Persistence).
- **Live updates.** The open map applies a logic (`INLOGIC`, `DOORS`), checks (`CHECKED`) or hints (`HINTED`) update one frame after its last line. An overworld icon has a marker for each look that skipping or an update can give it while the map is open; the hook after the icon setup hides those not shown.
- **Check list.** A on an overworld icon or dungeon dot of several locations opens a panel listing them, one row per location in the `map` section's order (`N` lines), checked ones included. Not for a dungeon's icon whose name is hidden. It is built from the game's layouts and hung under the map page (`map_checklist.cpp`; the list, the pad and the guide are `ap_list.cpp`'s, shared with the Jukebox page). While it is open the game sees no buttons and no sticks, and the panel reads the pad itself. The buttons held as it closes reach the game only once released, so B does not close the menu.
- **Dungeon dots.** The dungeon page has no icons of its own for checks, so `map_dots.cpp` adds them, one per spot: locations within `DOT_DISTANCE` of each other in the same room share one, and a location with two places has a dot in each. The game's chest icons of the slot's chests are hidden. After the page's setup it makes a map marker per dot of the current dungeon, hung after the room icons, so the pins draw over the dots. With no pin hovered, the nearest shown dot within the pins' radius is hovered and the map cursor names it (`Place:APMapDot`, whose text the module gives). A on a hovered dot acts as on an overworld icon and places no pin.
- **Hints.** The client sends the slot's locations that hold a server hint not yet found (`HINTED`, from the server's `_read_hints_<team>_<slot>`, which Archipelago's client keeps), and `NAME` lines say what each holds. A location shows its hint while it is neither checked nor skipped and its item has a name: its icon and dot get a gold ring (`MakeRing`, `ap_map_icons.ring_frame`), and its check list row shows the item. An icon whose name is hidden (Shuffled dungeons) gets none: it would tell which dungeon holds the hinted location. While the page waits for buttons with the cursor on a ringed icon or dot, a paper strip under the map lists the hinted items (`map_hintstrip.cpp`, `HintedItemText`).
- **The map section.** The seed file's `map` has `O <group> <local id>...` per overworld group holding any of the slot's locations, `M <dot> <room> <x> <z> <local id>...` per dungeon dot (its room as `Lv01TailCave_05F`, its world position), `C <level> <x> <z> <local id>` per dungeon chest of the slot in each of its location's rooms, `G <group> <name>` per overworld icon, `MG <dot> <name>` per dungeon dot, with shuffled dungeons `H <group> <flag> <name>` per dungeon icon: its name, shown without the count, until the flag is set, and `N <local id> <name>` per location of an overworld icon or dungeon dot: its name without its area, for the check list (a seed without them lists "Location <local id>"). The module turns the tracker on when the section has lines, and keeps its groups, dots and chests in fixed static storage (`map_tracker.cpp`), their texts as views into the seed file; a line that does not fit is left out, and the module logs how many were.

**In-game hints** (options `in_game_hints` and `hint_distribution`; `hints.py`, `patcher/ap_hints.py`, `modbuild/ap_hint_edits.py`)
- The hint sources are the 9 overworld owl statues, the 24 dungeon owl statues (by the LASR name of their location) and six of the library's books (`book-<color><n>`, the book actor's name); the map, the egg book and the Color Dungeon's book keep their text.
- The world picks the hints once the multiworld is filled (`choose_hints`, with the world's random). An area is the part of a location's name before " - " (Location names): an overworld region or a dungeon. The kinds:
  - `always`: one of this world's long checks (`hints.ALWAYS`) holding a progression or useful item.
  - `required`: an area of this world, or a location of another, holding an item of this slot without which the multiworld's other items do not reach this slot's goal.
  - `barren`: an area of this world whose locations hold no progression item of any player.
  - `area`: the area or the player's world that holds an item of this slot, this world's locations first.
  - `precise`: the location that holds an item of this slot.
  - `joke`: a joke line, for the sources left over.
- `hint_distribution` sets how many of each, in the order they are picked (`hints.DISTRIBUTIONS`, `FALLBACK`). Area and precise hints leave out the locations whose item is known anyway, and those nobody needs: unrandomized, kept, locked and optional locations of this slot, items in `start_hints` and locations in `start_location_hints`, seashells, dungeon items in their own dungeon.
- In every patch each source shows its own message (`ap_hint_edits.add`), `Hint:APHint<n>` for owl statues and `System:APHint<n>` for books (n: the source's place in `ap_hints.SOURCES`): a copy of the text it replaces, so a patch without hints keeps the vanilla texts. With Owl Gifts on, the gift follows the hint.
- The seed file's `hints` (`ap_hints.lines`) has, per source with a hint: `L <n> <text>` per line and `P <n>` before each further page, wrapped to `LINE_WIDTH` characters and `PAGE_LINES` lines per box; for a book `B <n> <question label> <volume>`; with `server`, for a hint that names one location (`always`, `precise`), `S <n> <slot> <location id>`. The module (`ap_text.cpp`) shows the hint in the source's message. Showing a hint sets the event flag `APHint<n>` (`ap_hints.FLAGS`, all in `GlobalFlags.gsheet`), which the save keeps. The module polls the flags of the `S` lines and sends `HINT` lines; the client sends `CreateHints` with priority status for each new one, or on servers before 0.6.2 `LocationScouts` with `create_as_hint` 2 for this slot's own locations. It sends them again after each server connection; the server skips hints it has.

**Ghosts** (`ghosts.py`, `ghost_relay.py`, `ghost_net.cpp`, `ghost/`)
- The multiworld's other LAS players show where this player is, as see-through Links. Positions travel game → client → ghost relay → the other clients → their games; the AP server is not involved. Running a relay: docs/ghost-relay.md and the setup guide (`apworld/las/docs/setup_en.md`, Ghosts). Its limits are `ghost_relay.py`'s constants.
- **Relay.** `ghost_relay.py` (standard library only, runs on its own) can serve any number of multiworlds. The client connects to the one in `las_options.ghost_relay`, else the patch file's, else `DEFAULT_RELAY`, which is also the setting's default value, so the patch file's relay applies only to a player who empties the field. The world draws one random secret per multiworld (`LASWorld.ghost_secret`) into every LAS slot's patch file, not into the slot data, which anyone who can log into a slot reads. A client joins the group SHA-256(`lasghost|<secret>`) (`group_id`), so the relay never sees the secret; the LAS players of one multiworld share a group whatever their slots' seeds. The relay forwards a player's frames to the group's members in the same level, in `Field` only to those within the 3×3 screens around the sender (`field_screen`); each member gets the `MAX_SHOWN` nearest players of its area, and an `OFF` for a player who leaves it or goes silent (`SILENT_OFF`). A second connection of the same slot of the same multiworld replaces the first. With `--nogroups` every member is in one group (`ONE_GROUP`), and the client tells its own player by the id in `WELCOME`, not by its slot name, which another multiworld's player may share. With `--password` the relay lets in only joins carrying it, the join's optional last field; it travels in plain text, so it keeps strangers off the relay, not eavesdroppers.
- **Wire.** `ghost_relay.py` defines it, both ends included (`connect`, `WebSocketReader`, `WebSocketWriter`). TCP with TCP_NODELAY (also between the game and the client), or a WebSocket on the same port (RFC 6455; the client uses one for a `ws://` or `wss://` address, `http://` and `https://` taken for them) for a relay behind a proxy such as a Cloudflare Tunnel; the relay tells them apart by the first byte. Each message is a u16 length (big-endian) and a payload whose first byte is its type (`JOIN` … `ERROR`, with their fields); a WebSocket's binary messages carry the same byte stream. The join carries `PROTOCOL_VERSION`; the relay refuses a client of another version. A position (`Pos`, `encode_pos`, `decode_pos`) holds the `POS` line's fields: the time as a wrapping u16, the level as its index in `LEVELS`, append only, and Link's animation as the `PlayerAnimation.gsheet` key + 1. A keyframe carries every field; any other only the fields that changed since the sender's previous position. The level changes only with a keyframe, and so does a jump too far for a difference. A client sends a keyframe first and after `NOWHERE`. To a member that got each of the sender's frames since a keyframe the relay passes a frame on as it came, to any other a keyframe of its own. Proxy headers count for the per-address limit only from a trusted proxy (`Relay.trusts`, docs/ghost-relay.md).
- **Rate.** The module sends `POS` at most every `kMovingMs` while anything changes, every `kStillMs` while Link stands still, and what the player does at once (`ghost_net.cpp`). The client caps frames at about the same rate (`MIN_INTERVAL`), what the player does excepted. Flag warped: the first position in a level and a jump of more than `kWarpDistance`.
- **Client.** `GhostLink` joins once ghosts are on, a relay address is set, and the patch file's ghost secret (`--ghost-secret` replaces it, for tests) and the slot name are known. It gives each player in the area one of `GHOST_SLOTS` ghost slots and turns the relay's frames into `GHOST` lines; a player beyond them waits for a free slot. It sends `GHOSTS 1` once joined and `GHOSTS 0` when it leaves. `GHOSTNAMES` carries the name tags' setting (`ghost_names`) both ways (Jukebox page, **D-pad in the game**).
- **Module.** `ghost_net.cpp` reads Link's position, yaw, animations and look each frame, with no player during level loads and while he stands at the origin (leaving a level by its exit), and keeps the last `GHOST` lines per slot (`HISTORY`). A new client connection clears both until it sends `GHOSTS 1`.
- **Puppet** (`ghost_puppets.cpp` and its parts, the other `ghost_*.cpp`; the test build's `DBG puppet`). Each ghost slot of `GhostNet` has a puppet: an `NpcGhost` actor spawned through the game's actor factory, whose NPC component the module gives the Npc row `APGhost` while it spawns it, drawn with Link's model from `PlayerGhost.bfres` (Assets), dithered in screen space (`ghost_dither.cpp`), with no collision, action or event triggers. The asset build adds the row and its facial row (`ap_player_ghost.py`). In a mod without the `APGhost` row the module spawns no puppet, since `NpcGhost`'s component looking up a missing row crashes. Each frame the module places the puppet by replaying the slot's `GHOST` lines on the sender's clock a buffer behind, the buffer following how evenly they arrive, so a late or bursty link shows as a ghost further behind, not a jerky one (`ghost_replay.cpp`). It draws the line's look (`ghost_look.cpp`).
- A ghost that arrives (a warped line) stays hidden until a later line moved, started or changed the animation, or `kArriveHoldMs` passed on the sender's clock, so a player entering a level stands still through their own fade-in first. Its name tag and instanced shapes show once its body has drawn two whole frames with its actor active.
- A puppet shows while the client is connected, its ghost is in Link's level and not hidden, and its last line is under `kStaleMs` old. After `kHiddenRemoveMs` hidden its actor is removed, and a later line spawns a new one. Every puppet spawns in zone -1, which is never suspended, as `NpcGhost` is zone-scoped and an actor of a zone Link has left is suspended (scripts/re/ACTORS.md, Activity).
- **Crowds** (`ghost_crowd.cpp`). Each shape a ghost draws costs a draw call in each of two render passes, and on an emulator the draw calls limit the frame rate (TESTING.md, Ghost crowd). The nearest ghosts draw their whole look, the next ones only `kCrowdShapes`, the farthest none. How many of each follows the frame rate the module measures, with minimums (`kMinWhole`, `kMinDrawn`).
- **Instanced equipment** (`ghost_instanced.cpp`). The shapes of Link's model bound to one bone each draw once for all ghosts: per group of shapes shown together one InstancedModel component on Link, one record per drawn ghost, written each frame (scripts/re/MODELS.md, Instanced models). The puppets draw none of these shapes; while a ghost's face differs from the instanced one it draws its own face shapes.
- **Name tags** (`ghost_nametag.cpp`). A ghost drawn whole has its slot name over its head bone in the game's action prompt (`Gm_HUDInteract.bflyt`): a layout of its own per ghost slot. The name goes in through the game's message pipeline (scripts/re/UI.md, Text boxes, Glyphs). The tags are built again after each level load.

**Music** (jukebox; `music.cpp`)
- The Jukebox page chooses a BGM that plays instead of the zone's music until the player stops it (`AP::Music::Choose`). The tracks are the patcher's `BGM_TRACKS`, then the Ballad of the Wind Fish (`music_tracks.hpp`). The title's file menu and the System page's Load (`FileOperate20_StartLoad`) turn the Jukebox off, so a track chosen in one save never plays on into another. No protocol line carries the choice.
- The module's hook on `BgmManager_Play` asks for the chosen track in the zone music's calls, told apart by their return address, and in the event action `PlayBGM`'s call for the two event songs that stand in for the zone's music; the game then treats it as the zone's track (scripts/re/FRAMEWORK.md, Audio). The chosen track does not go through the music shuffle (Options, Shuffles). The module keeps it out of the doors' and the level load's stops until it knows what follows (`music.cpp`, Doors). A track that sets its volume by Link's height reads him with no check; the module's hook makes that update do nothing while there is no player.
- The game's uses of a track by name follow the choice: the Great Fairy's `BGM_FAIRY` and an event's `Audio.StopBGM` of a song that is the chosen track are held as the doors' stops are (`music.cpp`).
- Events silence music with `StopAllBGM` and bring it back with `PlayZoneBGM`, so the chosen track gives way to event music and comes back where the zone's music would.
- On a change the module calls `PlayZoneBgm` with fading and stops the previous track by name, for the cases where nothing new starts. A change waits while the BGM manager prepares a track, which no fade or stop reaches before it starts. An unknown name (`BgmTable_Find`) is refused and clears the choice.
- **Ballad of the Wind Fish.** The Jukebox's Ballad is `BGM_ENSEMBLE_INST` for every set of instruments (scripts/re/FRAMEWORK.md, Audio): the hook gives its instance the egg's `onStart`, so the tracks of missing instruments are silent from the first sample. The stream does not loop, so the patcher writes a looping copy beside it, `BGM_ENSEMBLE_LOOP.bfstm` (`ap_ballad.py`), which the module's `nn::fs::OpenFile` hook opens in the original's place while the latest request for the ensemble is the Jukebox's; the egg's request opens the original and stops the Jukebox's copy first. A mod without the copy plays the original. Its eight channels leave room for only one more stream, and a stream that starts without room is dropped (`music.cpp`, Stream channels), so the Jukebox's Ballad gives way to a jingle and to any stream that would not fit beside it. With no instrument it cannot play (`AP::Music::Playable`).
- **Mute.** While muted, every BGM but the jingles plays silent, and the game's music runs on as without it. Every BGM volume goes through `Sound_SetVolume`, whose hook gives music 0 and keeps the volume the game asked for, which unmuting gives back (`kMuteFadeFrames`). The mute lasts while the game runs.

**Jukebox page** (`music_jukebox.cpp`, `music_tracks.hpp`)
- The pause menu's fourth page, after System. The menu never opens on it. There is none in the Chamber Dungeon, whose third page is the dungeon's own.
- The header (Navi, `Gm_Navi.bflyt`) has room for three pages, so the Jukebox is a mode of index 2, System's slot: while the module's flag is set, the `Gm_System` page the header builds for index 2 hides its content and shows the Jukebox. The module makes the page changes the header would not where the game would let the page go (`music_jukebox.cpp`; the header: scripts/re/UI.md, Pause menu).
- The page is built from the game's layouts (`music_jukebox.cpp`); the list, the pad and the guide are `ap_list.cpp`'s, which the map's check list (Map tracker) uses too.
- The page runs `AP::Music::Tick` each frame, which does not run otherwise while the menu is open, so the track plays in the menu. The pause menu turns music down; a track chosen on the page plays at full volume until the menu closes. The header turns the page on ZR as on R (and on ZL as on L); on the Jukebox, where ZR mutes (Music, Mute), it does not see ZR, except while the page opens (`music_jukebox.cpp`).
- **Playback** (`music.cpp`). Repeat one is on at the start; a track that does not loop starts again once it has ended (`kLoopDelayFrames`). With it off, once the chosen track has played through, the next one follows, only while the player is free, as a change fades out an event's song too. Next and previous step through one order, round: the list's, or with Shuffle a random order of the list, drawn each time Shuffle turns on. A track's play-through is its stream's end, with a short loop repeated until a minute has passed (`music_tracks.hpp`). A track cut off by other music has not ended. The modes last while the game runs.
- **D-pad in the game.** While the player is free, outside the trendy game and the fishing pond, → and ← step through that order, from the chosen track or else the zone's own, and ↑ turns the ghosts' name tags on or off while ghosts are on (Ghosts). Each shows a toast that takes the place of the one showing or waiting, so skipping through tracks shows the last one.
- `music_tracks.hpp` holds each track's name (at most 24 characters), description (at most 80 characters) and play-through length; `test_music` checks it against the patcher's `BGM_TRACKS` followed by the Jukebox's own tracks (`JUKEBOX_ONLY`). `scripts/track_lengths.py` writes the lengths from the RomFS sound archive.

**Persistence**
- **Received-item count:** event flags `APRecv0`..`APRecv15`, read as a 16-bit counter. The patcher adds them to `GlobalFlags.gsheet`.
- **Waiting Secret Medicines:** event flags `APMedicine0`..`APMedicine1`, a 2-bit count, also added by the patcher.
- **Collected locations:** a bitset file `sd:/lasap/<seed_hash>.chk`, written on each check, so checks made while disconnected are reported later.
- **Skipped locations:** a bitset file `sd:/lasap/<seed_hash>.skp`, written on each mark or unmark on the map (Map tracker, Skipping a check).
- **Read hints:** event flags `APHint<n>` (In-game hints).
