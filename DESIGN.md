# LAS Archipelago: design

How the pieces fit and the contracts between them. TESTING.md covers the harness.

## Components

| Dir | What | Language / runtime |
|---|---|---|
| `apworld/las/` | Archipelago world (`Links Awakening Switch`) plus PC client | Python, AP's venv (`.venv-ap`, Py 3.12) |
| `patcher/` | Makes the mod for an AP patch file: the mod's files (Assets) applied to the player's RomFS dump, and the seed's `config.ini` and seed file; `patcher/modbuild` builds the assets with LASR's mod generator (MIT) | Python: pure Python plus PyYAML and `bsdiff4` (`requirements.txt`); the asset build also evfl, PyLibMS, oead, quicktex and Pillow (`requirements-assets.txt`) |
| `las-ap-exl/` | exlaunch module (subsdk9) derived from Owen-Splat/exlaunch (GPL-2.0) | C++, Docker `devkitpro/devkita64` |

The module runs LASR's hooks and its code patches (`patches/patches.hpp`), except LASR's `CompareInt` event rewrite, which only LASR's own keysanity chest and present flows use; no flowchart of the mod asks `CompareInt` (`verify_patch.py` checks). The asset build's chests and presents have no such flows (`ChestRandomizer.writeChestEvent`): they keep the game's own add, so a dungeon item with an index goes to that dungeon (the module's `AddItemID` hook; the patcher gives vanilla-placed ones the game's dungeon index, `dungeon_item`) and one without, as the Chamber Dungeon's keys, to the dungeon Link is in.

Flow:
1. AP generates a multiworld. The world writes `AP_<seed>_P<n>_<slot>.aplas` (the patch file).
2. The player opens the patch file with the Launcher, which starts the client with it. The client runs the patcher on the patch file plus the user's romfs dump, and installs its output (see Client install).
3. The game runs with the mod. The module listens on TCP port **43384**, or on the port `config.ini` sets (`[archipelago] port`); the client's `--game-port` must match. Players keep the default; the test sandbox uses its own port so it runs beside a modded game.
4. The client connects to the AP server (websocket) and to the game (TCP), and relays checks and items.

## Assets

The mod's RomFS is the same for every seed: every file it changes or adds is an asset (`patcher/ap_assets.py`). `scripts/build_assets.py` (in `.venv-lasr`) builds them from a RomFS dump:
- LASR's mod generator with the patcher's edits (`patcher/modbuild/mod.py`, LASR's code in `modbuild/RandomizerCore`), run on a patch with the locations the world gives every seed (`make_test_patch.make`). LASR's code has only what the build runs: its settings read as the build sets them (`ap_options.LASR_SETTINGS`, the test patch's), and the options' edits are calls into `ap_option_edits.py`.
- The files only the build makes: `StartUp.arc` (LASR's title screen logo and the notice look, `ap_ui.py`), `ItemArchipelago.bfres` (`ap_model.py`) and `Game.arc` (the map tracker's icons, `ap_map_icons.py`).
- The files the patcher makes itself from the player's dump (`ap_assets.MADE`), by a recipe in its own code, so the release carries none of their source's texture data: `PlayerGhost.bfres` from `Playerlink.bfres` (the multiplayer ghosts' model, `ap_ghost_model.py`: the shown albedo textures as BC3 with a constant alpha, the tunics without their largest mip level, the unshown textures shrunk to 4x4, the shown materials in render pass 1) and the chest textures from `ObjTreasureBox.bfres` (`ap_chest_model.py`): the seashell chest (`ObjTreasureBoxSeashell.bfres`, the albedo recoloured blue; each BC1 block keeps its indices, its endpoints fitted to its palette recoloured) and LASR's chests for its "Chest Types" (`ObjTreasureBox{Junk,Key,LifeUpgrade}.bfres`). Each part of a LASR chest (the metal by the metalness map, the wood and the purple panels by hue) takes the colour of LASR's flat texture for it with the original's shading. LASR's textures are linear BC1, so the game reads their colours as linear light; each part takes that colour as its mean in linear light, in the chest's own sRGB format, and renders as LASR's did. `ap_bntx.py` reads and writes their BNTX textures and the Tegra X1 block-linear layout, in the standard library. The build makes these files the same way and refuses a recipe that does not make the built file. On a Ryzen 7000-series desktop the ghost model took 0.47 s, the seashell chest 0.37 s, LASR's three chests 2.2 s together and the whole patch 4.4 s (measured 2026-11-04).
- It stores each other file that differs from the dump's in `patcher/assets/files` as a bsdiff4 patch against the RomFS file it comes from (against nothing for a file of the mod's own). `assets.json` holds each file's source and both files' SHA-256 (a file in `MADE` has no patch).
- `build.json` holds what the seed's files take from the build: LASR's tables, the mod's `Items.gsheet` rows, the map tracker's door places and dungeon chests, the messages Randomize Text shuffles, and the patch's shape: per location its local id and what it holds (`las_ap_patch.patch_shape`).
- The build needs evfl, PyLibMS, native packages (oead's SARC, quicktex, Pillow) and the BNTX editor (`RandomizerCore/Tools/bntx_editor`, GPLv3). `--check` builds and compares with the committed assets. After a change to anything the mod's files come from (`patcher/modbuild`, LASR's data, `map_positions.json`), rebuild and commit the assets.

The patcher (`las_ap_patch.py`) applies the patches to the player's dump, makes the `MADE` files from it and checks the results against `assets.json`; a dump of another game version fails with a message naming the file. It refuses a patch whose shape is not the assets' (one of another world version), and writes `config.ini` and the seed file from the patch.

Datasheets (`.gsheet`) are read and written by `modbuild/RandomizerCore/Tools/gsheet.py`, a pure-Python version of oead's gsheet module that LASR's `oead_tools` and `flag_manager` use. It writes what oead writes, byte for byte, and copies values stored into structs and arrays as oead does. `scripts/check_gsheet.py` compares the two on every RomFS datasheet and on any given files.

## Release

`scripts/build_release.py` (in `.venv-lasr`, after `build_exl.sh`) writes `build/release/LASAP-<world version>/`: `las.apworld`, the options template `Links Awakening Switch.yaml` and the setup guide `Setup guide.md` (`docs/setup_en.md`). The template asks for the world's minimum Archipelago version (`archipelago.json`), not that of the checkout that wrote it.
- The world carries the patcher as `las/patcher/` (`PATCHER_FILES`): its Python files, LASR's data (`data/`), the assets and the game module. The asset build (`patcher/modbuild`) stays out; `test_install.py` patches seeds with its modules blocked (`BUILD_ONLY`). `build.txt` holds a hash of all of it. The repository's `LICENSE` goes in as `las/LICENSE.txt`. The world's own build ("Build APWorlds") is the same without it, and with the world's tests (`las/test`), which the release leaves out.
- The patcher runs in Archipelago's Python: pure Python plus PyYAML and bsdiff4, which Archipelago ships.

## Client install

- The client's Patch tab (`client_gui.py`) edits the settings in `host.yaml` under `las_options` (`host_settings.py`): `platform`, `emulator`, `game_file`, `romfs_folder`, `sd_card_folder`, `mod_folder`, `patcher_command`, `game_host`. `checklist.py` gives one status line per setting and decides whether the ones the platform needs are valid: an emulator (`emulator`) or a Switch (`sd_card_folder` with an `atmosphere` folder, `game_host`). Until they are, the tab shows the setup steps; then a card with the seed's state, the install steps while Play runs, and summaries that open the setup, look and sound, ghost and advanced settings, all within the client window's default 800 x 600. The RomFS dump's line runs the check the patcher runs before patching (`patcher/romfs_check.py`, which `install.romfs_problem` loads from the world's copy of the patcher without unpacking it): the folders the patcher reads, the message files it edits in every language folder, and the 1.0.0 sha256 of the files the assets come from (`assets/assets.json`).
- **Gameplay options and player settings.** Settings that change how the game plays are options, so a seed plays the same for everyone in it (Archipelago is raced): the option group "Gameplay" (`damage`, `movement_speed`, `movement_360`, `skip_song_cutscenes`, `instant_text`, `nice_hookshot`, `disable_guardian_acorn`, `disable_piece_of_power`, `easy_fishing`, `randomize_enemies`, `randomize_enemy_sizes`), which the patch file's `settings` carry under LASR's names. Settings that change only how the game looks or sounds are the player's, for every seed: the Patch tab's "Look and sound" (`/setting` in a client run from source), stored in `las_options` (`host_settings.PLAYER_SETTINGS`): Blur Removal, Music, Randomize Text, Randomize Environments, Disable Low Health Beep. The patch file carries their defaults; the client passes the player's values to the patcher as `--settings <JSON object>` (`las_ap_patch.PLAYER_SETTINGS`, the same keys; the patcher rejects any other). LASR does not implement Item Get Animations or Randomize Sound Effects, so they stay off.
  - `config.ini` `[movement]`: `full_360`, `walk_speed` and `swim_speed` (1.2 with Movement Speed on, 1.0 off; dashing keeps the module's default). For the two Disable settings the module also empties the `ItemDrop.gsheet` rows `GuardianAcorn` and `PowerPiece`, for drops that name them; for Easy Fishing it gives Ol' Baron the other fish's weight in the deep spot (Options, Sheets).
  - `config.ini` `[tweaks]`: settings LASR lists but never implemented, and settings of our own, done by the module (`mods/tweaks.cpp` unless named):
    - `instant_text`: a page of text shows whole as it appears, as with B, without its pauses; waits for input stay.
    - `no_low_health_beep`: no low-health warning.
    - `no_guardian_acorn`, `no_piece_of_power`: the buff that replaces an enemy's drop after a run of kills is picked in the game's code, not in `ItemDrop.gsheet` (scripts/re/ITEMS.md, Item actors, Buff drops); the module patches out its branch.
    - `easy_fishing`: a hooked fish's line never snaps (scripts/re/ACTORS.md, Fishing); a fish that swims off the pond's edge still gets away. LASR's Fast Fishing (a world option) only removes the instruments the bigger fish need.
    - `instant_pickups` (the Patch tab's Instant pickups, off by default): found and received items show as popups instead of item-gets (Showing received items, Instant pickups).
    - `no_30fps_drops` (`emulator`, `true` or `false`; the Patch tab's On emulators, Always, Never): a frame that misses the display's vsync costs only its own time instead of dropping the game from 60 to 30 fps (scripts/re/FRAMEWORK.md, Frame pacing). `emulator`, the default, applies it where the kernel is not Atmosphere's; the module logs which it found.
  - Randomize Enemies and Randomize Enemy Sizes are LASR's (`patches/enemies.cpp`; `config.ini` `[randomizer]` `enemies`, `enemy_sizes`): each enemy of one of LASR's groups (walking, flying, in water, ...) that a room loads becomes a random enemy of its group, but for those that must be defeated and never into a blocking one, and trap chests let out a random enemy; sizes scale every enemy of a group at random. Neither is seeded: a room's enemies change each time it loads. The logic does not change. `DBG enemies` counts what the randomizer did.
- `emulators.py` derives the rest from the emulator's executable:
  - Ryujinx: data folder `portable` next to the executable, else the per-user `Ryujinx` folder. SD card `<data>/sdcard`, mods `<SD card>/atmosphere/contents/01006BB00C6F0000`, game folders from `Config.json`.
  - Yuzu and its forks (Eden, Citron, Sudachi, Suyu, Torzu): data folder `user` next to the executable, else the per-user folder named after the emulator. `config/qt-config.ini` gives the SD card (`sdmc_directory`), mods (`load_directory`, plus `01006BB00C6F0000/Archipelago`; their SD card's `atmosphere/contents` loads only RomFS mods), RomFS dumps (`dump_directory`), game folders and recent files.
  - The game is the `.nsp` or `.xci` whose name holds the title id, or whose PFS0 file list holds the base game's ticket.
  - An SD card folder in the settings overrides the emulator's; for Ryujinx, its parent is the data folder, passed as `--root-data-dir` when it is not the default.
- Install (`install.py`): with `patcher_command` empty, the client runs the patcher on a worker thread of its own process, logging its printed lines: the release world's `las/patcher`, unpacked once per `build.txt` into Archipelago's cache folder (`las/patcher/<build>`), or the repository's `patcher/` from source. It imports `las_ap_patch` fresh for each run and calls `main([<patch>, "--romfs", <dump>, "--out", <temp dir>, "--settings", <player settings>])`, then drops the patcher's modules, which keep state in module globals. With `patcher_command` set, it runs that command with the same arguments as a subprocess and logs its output. It then replaces `romfs` and `exefs` in the mod folder and copies the `config/lasr-exl` folder (`config.ini` and the seed file) to the SD card, `config.ini` last.
- The mod is current when the installed `config.ini`'s `[archipelago] seed_hash` matches the patch, both mod folders exist, and, for the built-in patcher of a release world, `config/lasr-exl/patcher_build.txt` names its `build.txt`, and `config/lasr-exl/player_settings.json` (written on install; the defaults when missing) holds the current player settings; then Play skips patching (`mod_state`). Reinstall mod patches regardless. Other Link's Awakening mod folders the emulator would also load are reported.
- The client never looks at running programs: the player chooses the emulator in the Patch tab the first time.
- Opened with a patch file (double-click, drag onto the Launcher, "Open Patch"), the client shows it in the Patch tab and connects to the patch's `server` as its `player_name`; it neither installs nor starts anything. Play (`/play` in a client run from source) installs the mod when it is not current, then starts the emulator with the game (unless the game is connected or the emulator this client started is still open).
- `file_types.py` registers `.aplas` for the current user (`HKCU\Software\Classes`), opening with the Archipelago Launcher, which hands the file to the client. It runs only from the Patch tab's button.

## Seed file

The patcher writes the per-seed tables the module reads to `config/lasr-exl/ap_seed.txt` next to `config.ini` (`patcher/seed_file.py`, `AP::SEED_PATH`): a `[<section>]` line before each section's lines. The module reads it once at boot (`config/seed_file.cpp`) and keeps it; the loaders keep views of its names, each ended with a 0, as the game reads some names to their terminator. Each line is space-separated fields, a name with spaces last. A section without lines is left out, and the module reads a missing section as empty. Sections: `names`, `indices`, `kept`, `models`, `start`, `shop`, `jumps`, `markers`, `shuffles`, `hints`, `map`; their lines are in the sections below that use them. `config.ini` stays apart: LASR's format, and the client reads the installed seed from it.

## Code the module writes

The module patches and hooks the game's code at boot, after an emulator may already have translated it: Ryujinx's translation cache (PPTC, on by default) translates the functions of earlier runs from the unpatched code. A translation that starts after a patched instruction and branches back over it survives a flush of the written line alone, so every code write in the exlaunch lib (`util::InvalidateWrittenCode`, used by the patchers and the hooks) also invalidates the text after it, up to `WrittenCodeReach` (`written_code.hpp` has the details). On hardware and on emulators without a translation cache this costs nothing that matters.

## Module source

`las-ap-exl/source/program/`, besides exlaunch's `lib/`:

| Folder | What it holds |
|---|---|
| `game/` | How the module reaches the game: addresses and typed symbols named as in `las.sym` (`addr.hpp`, `sym.hpp`), field access (`mem.hpp`), read-only views of the game's libc++ types (`stl.hpp`), and the game's objects as types (entities and actors, models and animations, NPCs, the framework, the player, saved data, UI and menus, map pages, audio). `game/hooks/` holds the hooks on the game's own systems that several features use: event flags, the current level, `AddItemID`, input and play reports. |
| `config/` | `config.ini`, parsed once at boot into `PatchConfig`, its choices as enums. |
| `patches/` | LASR's randomizer at runtime: the code patches (`patches.hpp`, tables of offset and instruction) and the hooks for enemies, fishing and seashells. |
| `mods/` | The optional changes `config.ini` turns on: controls, fixes, tweaks. |
| `ap/` | The Archipelago bridge: the network thread (`ap_net`), the game side (`ap_game`, and its parts that `ap_bridge.hpp` declares: received items, the start state, item-gets, held NPC models, checks and hints, the client's lines, the warp menu), in-game text, the item popup, the list widget, the patcher's names (`ap_patcher.hpp`). |
| `ghost/` | Multiplayer ghosts: the network half (`ghost_net`), the puppets (`ghost_puppets` and its parts: replay, look, dither, instanced equipment, crowds) and the name tags. |
| `map/` | The map tracker: its icons, check list, hint strip and dungeon dots. |
| `music/` | The jukebox and its pause menu page. |
| `test/` | The test build alone (`LASAP_TEST`): the debug port, the trace, the input ops, the DBG commands and the probes of the ghosts and the map tracker. |

The root holds `main.cpp` (the install list, in order), `hooks.hpp` (the hook groups' `Install()`), `game_version.cpp`, and the files exlaunch's lib includes by path: `offsets.hpp`, `version.hpp`, `setting.hpp`, `loggers.hpp`.

The game's offsets and structures are in the reverse-engineering docs (`scripts/re/*.md`), its symbols in `scripts/re/las.sym`.

Conventions:
- Basenames are unique across `source/`: the build finds a source by its name alone. The files of `ap/`, `ghost/`, `map/`, `music/` and `test/` carry their folder's name as a prefix.
- Includes name paths from `source/program/` (`"game/sym.hpp"`) in four groups: the file's own header, the program's headers, exlaunch's and the SDK's (`lib.hpp`, `nn/…`), the standard library's; sorted within each group.
- A feature's header declares what other files call. Parts shared by a feature's own files and the test build go in its `*_impl.hpp` (`ap_bridge.hpp` for the bridge), in the feature's namespace; code used by one file stays in that file's anonymous namespace.
- Hooks are `HOOK_DEFINE_TRAMPOLINE`, `_INLINE` or `_REPLACE` structs in an anonymous namespace, named after the game function as `las.sym` names it, or after what the hook changes where it hooks inside a function. Each installs from its feature's `Install()` or `InstallHooks()`, with `InstallAtFuncPtr` on the typed symbol where `sym.hpp` has one: exlaunch then checks the hook's signature against the symbol's.
- The game's objects are read through the types in `game/`: one member per field, padding named `pad_<offset>`, and a `static_assert(offsetof(...))` per field. The game's `std::` objects are libc++'s and the module's standard library is libstdc++, so they are read through `game/stl.hpp`'s views, never as `std::` types.
- No function-local static that needs a constructor at run time: its first use hangs the game. Such objects go at namespace scope.
- Test-only code stays under `#ifdef LASAP_TEST`, a line of it in `TEST_ONLY(...)` (`test_only.hpp`). The test build's own code lives in `test/`; a feature keeps only small probes (a STATE field, a counter, a log).
- Style: 4 spaces, 120 columns; `g_` for globals, `k` for constants, PascalCase for types and functions.

## Item model: remote items

- Every randomized location in the patched game gives the **AP placeholder item**, with `index` = the location's **local id** (AP location id − `LOCATION_BASE`).
- The module's `Inventory::AddItemID` hook sees the placeholder item id, reports a check, and adds nothing to the inventory.
- Every real item, including the player's own, arrives from the server and is granted by the module. The client uses `items_handling = 0b011`: starting inventory is granted by the patch (LASR's starting gear), so the server does not send it again.
- The activities the options leave out are optional (`lasr_settings.optional_locations`, `LASWorld.optional`): the trade quest, Dampe, the Rapids Ride (with its owl statue), fishing and the Color Dungeon's blue rupees when their option is off, and the Seashell Mansion's rewards above `seashell_mansion`. They are shuffled AP locations that the logic reaches only after the goal (their rule and the `Victory` event), and `set_rules` excludes them (`LocationProgressType.EXCLUDED`): Archipelago's fill gives them filler and traps from any player's pool, never progression or useful items (`Location.can_fill`), so no seed needs them. A slot with fewer filler and traps than optional locations (nearly every category off) excludes only as many, picked at random; the others take the slot's own items but small keys (an item rule). Their vanilla items (trade items, the magnifying lens, bottles, the Mansion's level-2 sword, Dampe's heart container) are in the pool. The patch's settings keep the options as they are (`Trade Quest` off), which PopTracker reads to hide those checks.
- A location the other options do not randomize (a place on the way: chests, gifts, boss drops, the shop, ...) gives its default item (`lasr_settings.unrandomized_locations`). It is an AP location holding its default item, locked (`LASWorld.locked`): it holds the placeholder, reports a check, can be hinted, and the item arrives from the server.
- The Trendy Game's prizes and the companions cannot hold the placeholder (LASR places no items in the crane game; its followers are no item locations). They keep their item in the game (`lasr_settings.kept_locations`; the patch's `placements` name it) and are locked checks. The companions are `moblin-cave` (Bow-Wow) and `rooster-statue` (the rooster), holding the items Bow-Wow and Flying Rooster, which the rules ask for.
  - The seed file's `kept` has per Trendy Game check the item's key, its index (-1 for none) and the local id; per companion `F`, the flag its joining sets and the local id (`BowWowJoin`; `RoosterFoundFlag`, which the patcher sets after the rooster's `Join` in `RoosterBones.bfevfl`).
  - The module reports a Trendy Game check when the game adds that item with that index (any for -1) outside a received item's grant, and a companion once its flag is set; the server sends the item back, which adds the item only to a save that lacks it (`ap_items.cpp`), as the Trendy Game decides which prizes it offers. A companion's item adds nothing: the companion joins in the game.
  - Their heart pieces and seashells count as vanilla sources in the seed file's `indices`.
- Starting Gear (`start_inventory_from_pool`) comes out of the pool, so every copy it gives must be in it. Where a locked location holds the pool's copy (the Ocarina and Manbo's Mambo with Miscellaneous off, the bosses' heart containers with Boss Drops off), that location holds 50 Rupees instead and its item joins the pool (`LASWorld.replaced`, `LASWorld.content`); the Trendy Game's prizes and the companions stay. A pre-fill item in the starting gear (a small key kept in its dungeon) goes into the pool too.
- With fewer than `EARLY_LOCATIONS_WANTED` locations reachable at the start (no starting gear, few categories), one of them holds an item that opens up the island, as LASR's Tarin rule does (`LASWorld._place_opener`, at the start of `pre_fill`): a progression item that makes that many reachable, else one that opens the most, locked at a starting location outside the shop (where only stealing gets it) if there is one.
- `small_keys`, `nightmare_keys` and `dungeon_items` (maps, compasses, stone beaks) each place their kind (`LASWorld.dungeon_item_placements`): `own_dungeon` and `any_dungeon` are pre-fill items restricted to their dungeon's or any dungeon's locations (`LASWorld.restricted`); `own_world` and `different_world` go into `local_items` or `non_local_items`, which Archipelago empties in a solo seed; `start_with` makes every copy a starting item. The patch's settings name them as LASR does (`Own Dungeon`, `Any Dungeon`, `Anywhere` for both worlds, `Start With`). The patch's `starting_items` leave the keys of a `Start With` setting out; the patcher gives every dungeon its keys (Start state). The slot data of older seeds has one `keys` option for both kinds, which `generate_early` takes for both when Universal Tracker regenerates such a seed.
- The shop slots LASR does not shuffle (`lasr_settings.fixed_locations`) keep their vanilla content and are AP event locations (no id) with the vanilla item locked, if it is progression. The Color Dungeon's blue rupees with Blue Rupees off are optional checks (above), drop actors as with it on (Drop actor, The blue rupees).
- Each location shows a model for the item it holds, picked by the world (`models.py`): an LAS item its own, another game's item by name from `data/item_models.yml` (any shield shows the shield), traps and unmatched names the Archipelago model. The patch file's `location_models` carries the picks.
- **Item models.** The module shows each location's model at runtime (`ap_models.cpp`; scripts/re/ITEMS.md, Row strings, Item node, Model makers), so the RomFS is the same for every seed's models.
  - Every AP location holds the placeholder, `ArchipelagoItem`. Its item actors name the location's token, `ap:<local id>` (`MODEL_TOKEN`), as their model file and model name, LEB parameters that their Npc row reads (`$1`/`$2`). Where an NPC component resolves its row's model (`NpcComponent_ResolveParam`), the module gives a token the model of the location's item, else the Archipelago model.
  - The seed file's `models` has `M <local id> <item id> <model file> <model name>` per location whose item shows its own model; `S <local id> <scale factor> <yaw or -> <rise>` where LASR places an item actor with that model otherwise than one with the token (`ground_transform`: a heart at a heart piece place unshrunk, the song NPCs' sizes, the sword turned), which the location's item actors take and its chests and drop actors do not; `I <row key> <item id> <local id>` per LASR row that stands in for a location's item (`STAND_IN_ROWS`: Dampé's rewards, the shop's goods, the items the bay fisherman, the witch and the walrus show).
  - The module places such an actor when it is made (`Actor_Create`): its scale times the factor, its height plus the rise, its yaw the one given.
  - The item-get's item node takes the item id of the location added last, which a placeholder's flows add right before its item-get, and of a stand-in row's location (`ItemGetHolder_Make`): it holds up that item's model in that item's pose, while its text and fanfare stay the placeholder's. The items NPCs hold up (`ItemModel_Make`), the mansion's present's among them, and a find's popup take the same.
  - The shop's shelf shows its stand-in goods with the model of their location's item: the module sets their `ShopItem.gsheet` rows when the game makes the sheet (`Datasheet_Create`). LASR writes the Archipelago model into the sheets that name a location's model (`SHEET_MODEL_LOCATIONS`).
  - **Chests.** The chest's Npc row reads its model file and model name from LEB parameters 6 and 7 (`$6`/`$7`), as LASR's "Texture + Size" has it, and every chest names one (`_chest_contents`): an AP location's chests the location's chest token, `apchest:<local id>` (`CHEST_TOKEN`), the Chamber Dungeon's the plain chest, a chest holding this slot's own item the chest LASR's "Chest Types" gives it (`chest_look`). `models` has `C <local id> <size> <chest file>` per AP chest that is not the plain chest at size 1 (`location_chests`, below); the module resolves a chest token to its chest file, else the plain chest's (`ObjTreasureBox.bfres`), and scales the chest by its size when it is made. The chest files are installed in every mod.
- The Archipelago model is six balls in the logo's colors. The patcher builds it from the player's Seashell Sensor model (`patcher/modbuild/ap_model.py`) and writes it as `ItemArchipelago.bfres`, with its own Npc entry, `ItemArchipelago`.
- Indexed items (heart pieces, seashells, golden leaves, heart containers, bottles, chamber stones) are counted by inventory bits: collecting one sets the bit of its source (its vanilla index, `index` in `logic.yml`), and the count is the number of bits set. A bottle's bit is its slot (`Bottle0`..`Bottle2`); one added with index -1 sets no bit and gives no bottle. The seed file's `indices` has, per source its kind (`S`, `H`, `L`, `C`, `B`, `P`), its bit and the local id of its location when shuffled, else -1. A received item takes the lowest free bit that no vanilla source of the seed sets, so a vanilla source collected later still counts, within the game's totals (heart pieces below 32, seashells below 50, heart containers below 9). A received chamber stone takes one of the stones the Items page counts, a chamber panel that Dampé makes at his next talk (scripts/re/ITEMS.md, Chamber stones). The shop's and the Trendy Game's stones stay vanilla, as owning a stone hides the Trendy Game's prize of that index and takes the shop's off sale; received ones take the indices of the Seashell Mansion's, the rapids race's and fishing's, and one more finds no index and adds nothing.
- The Memories map marks heart piece and seashell bit i at the vanilla place of source i (rows of `UiMemoryHearts.gsheet` and `UiMemoryShells.gsheet`). Received items hold the bits of shuffled sources, so the module (`ap_indices.cpp`) marks source i once it is done instead: a vanilla source by its bit, a shuffled one by its location's check.
- Item actors show by their flag or actor switch alone, as in LASR: LASR's `randoFixes` code patch stops the game's inventory check, which hides an item actor while the player has its item (`ItemActor_CanAppear`, scripts/re/ITEMS.md, Item actors). LASR gives every heart piece and seashell actor a flag, shuffled or not, so received heart pieces and seashells never hide an actor.

## IDs

- `ITEM_BASE = 0x4C410000` and `LOCATION_BASE = 0x4C420000`. The AP id is the base plus a stable offset.
- **Stable offsets.** They live in `apworld/las/data/ids.json` (`{"items": {lasr_name: offset}, "locations": {lasr_location: offset}}`).
  - The file is generated once from LASR's data in file order and committed.
  - New names are appended; existing offsets never change.
- **Local id.** A location's local id is its offset, which is the `index` stored in-game. It must stay below 65536.

## Names

- **AP display names** are human-readable, e.g. `Progressive Sword`, `Small Key (Tail Cave)`, `Tail Cave - Feather Chest`.
- **Location names** (`apworld/las/data/location_names.json`) are `<region or dungeon> - <label>`, the label as the PopTracker pack names the check, so hints, the spoiler, the in-game map and the tracker agree: a dungeon check's room on the pack's dungeon map, an overworld check's section, or `<pin> (<section>)` where the section alone says little (`Mamasha (Trade Yoshi Doll)`). `scripts/poptracker_map.py` finds dungeon checks in the pack by that label.
- **LASR names** (`sword`, `key-D1`, `D1-west-hallway`) are used in the patch file and in `ids.json`.
- The world keeps the mapping between the two.

## Save name

- A new file's name entry shows `UI:NameEntry_Default` ("Link" in the base game) until the player renames it, and OK keeps it (scripts/re/UI.md, Name entry). The module hands out the patch's `slot_name` for that label, from `config.ini` `[archipelago]` `save_name` (`ap_save_name.py` makes it), so a new save is named after the slot; the player can still rename it on that screen. Files made before the mod keep their names.
- The game takes up to 8 characters: its keyboard's limit, and OK cuts a longer name. From the slot name the patcher keeps printable ASCII except `@`, `%` and `\` (the keyboard refuses them) and `[`, `]` (they start a message tag), and the Latin-1 letters (`À`–`ÿ` without `×` and `÷`), which the game's fonts have for its European languages. Runs of spaces become one space, and the result is cut to 8 characters with no space at either end. When nothing is left (a slot name in another script, symbols or spaces only), the name is "Link". For example `Archipelago Player 7` gives `Archipel` and `Zoë[AP]_Archipelago` gives `ZoëAP_Ar`.

## Start state

- The module gives a new save its starting items and start flags; LASR's start event (`PlayerStart.bfevfl`, `player_start.py`) keeps only its other changes (`makeStartChanges`: the rooster after D7, the companions' wait at a loading zone). The seed file's `start` (`start_lines`) has `I <item key> <dungeon index>` per starting item (-1 for none), `R <rupees>` (the option `starting_rupees`), `F <flag>` per start flag.
- **Items.** The patch's `starting_items`, a second sword, shield or bracelet as its upgrade, a dungeon item for its own dungeon (`dungeon_item`), and for each `Start With` setting (Dungeon Maps, Compasses, Stone Beaks, Small Keys, Nightmare Keys) every dungeon's items of that kind in place of the patch's (`START_WITH_KINDS`). The module grants them once Link stands in his first level (`ap_start.cpp`, `TickStart`), before the save's `RECV`, as received items are granted (`GrantItem`: heart pieces, seashells and the other indexed items take the bits a received one would), and sets `APStartItems`. A save past Marin's talk at the wake-up (`OpTalked`) without `APStartItems` is an older mod's, whose start event gave the items in that talk: it gets `APStartItems` alone.
- **Flags.** `START_FLAGS` (the cutscenes and one-time scenes LASR marks watched, the Walrus awake, `EighthClear` for the ghost's reward) and the flags of the settings in `START_SETTING_FLAGS` (Open Kanalet, Completed Bridge, Open Mamu, Randomize Enemies, Fast Stalfos, Boss Cutscenes). The module sets them the first time Link stands in a level other than Tarin's house (`MarinTarinHouse`) while the save's `FirstClear` is unset, `FirstClear` last: the opening and Marin's talk in the house read `FirstClear`, `SwordGet`, `MarinRescueClear` and `WalrusAwaked`, as LASR's start event set them on Link's first exit from a building. Without a `start` section the module gives nothing.

## Options

The RomFS is the same for every seed. What a LASR setting changes in the game's files, the mod holds both ways, and `config.ini` `[options]` (`ap_options.OPTIONS`: `open_mabe`, `classic_d2`, `completed_bridge`, `randomize_enemies`, `fast_fishing`, `shuffled_bombs`, `shuffled_powder`, `song_cutscenes`, `owl_overworld`, `owl_dungeons`, `ammo_ghost`, `bouncy_items`) picks one at runtime (`ap_options.cpp`). LASR runs with fixed settings (`ap_options.LASR_SETTINGS`); `config.ini` has the seed's (`las_ap_patch.config_text`).
- **Flags.** The module's `EventFlags_Check` hook answers `APOpt.<option>` (the option is on) and `APIf|<option>|<type>|<argument>|<type>|<argument>` (the first condition while the option is on, else the second, by `Conditions_Check` type and argument; type 0 holds unless its argument is `false`). Events' `CheckFlag` and sheet conditions of type 1, NPC layout conditions among them, reach it (scripts/re/EVENTS.md).
- **Events.** `ap_option_edits.gated` runs LASR's event edits and puts each link they change behind a `CheckFlag` of `APOpt.<option>`: case 1 the edit's target, case 0 the old one; the events and entry points they add stay as made. Gated: the owl statues' gifts (Owl Gifts, `owl_changes`; each statue's location has an id in every mod, the patch's `removed_location_ids` for those the options leave out), Marin's, Manbo's and Mamu's songs (Song Cutscenes), Kiki's bridge (Completed Bridge), the blue guard's powder (Shuffled Powder), and the drops' launches (Bouncy Items).
- **Sheets.** `option_if` conditions in `Npc.gsheet` (the bomb and powder refills hide until Link finds bombs or powder, Shuffled Bombs and Powder; Kiki leaves with `KikiGone` or `StickDrop`, Completed Bridge), `Conditions.gsheet` (`ShopBombCondition`) and `CranePrize.gsheet` (the bombs and the red rupee before them). The module edits some sheets as the game makes them (`Datasheet_Create`): `FishingFish` (Fast Fishing: every fish that gives an item gives `ClothesGreen`, which the game turns into the row's item), `FishingSpot` (Easy Fishing: Ol' Baron's weight in the deep spot), `ItemDrop` (Disable Guardian Acorn and Piece of Power: the row's drop empty) and `Npc` (Bouncy Items: `ItemAPDrop` takes `ItemAPDropBall`'s row, its name kept).
- **Rooms.** The module's `Room_OnLebActor` hook (scripts/re/ACTORS.md, Rooms) leaves out, retypes or moves LEB actors by key (`kActorEdits`): Open Mabe leaves out the grass, rocks and monsters around Mabe, Randomize Enemies the Armos over the two stairs; Classic D2 makes the rock before Bottle Grotto a swamp flower (`EnemyMonea`); Completed Bridge stands Kiki and the stick aside; the Ammo Ghost is left out while off. Drops that chests and owl statues launch are left out without Bouncy Items.
- **Shuffles** (player settings Music, Randomize Environments, Randomize Text; `ap_shuffles.cpp`, `patcher/ap_shuffles.py`). The seed file's `shuffles` has, when one is on, a line per swap: `M <track> <track>` (`-` for none: Music Removed), `E <environment> <environment>` (one of its kind, top-down or side view, as LASR picks), `T <File:Label> <File:Label> <fix>` (LASR's dialogue and Talker pools). The module swaps the name as the game looks it up: the game's music requests (`BgmManager_Play`, the stop and volume by name; the Jukebox's chosen track is not swapped), `LevelEnvironment_Find` (the original where the level lacks the environment; scripts/re/FRAMEWORK.md) and `MessageManager_Find`. A message shown in another's place gets the input wait at its end added (`+`), taken off (`-`) or kept (`=`), as LASR fixes its moved text.

## Patch file (`.aplas`)

An Archipelago player container (`container.py`, `APPlayerContainer`): a zip with `archipelago.json` (game, player, player name, server; WebHost fills in the room's server) and `patch.json`. The patcher also accepts a bare `patch.json`. `patch.json` is UTF-8 JSON:

```json
{
  "format": 1,
  "seed_name": "<AP seed name>",
  "player": 1,
  "slot_name": "Link",
  "seed_hash": "<8 hex chars; also in slot_data; the game reports it in HELLO>",
  "settings": { "<LASR setting key>": "<value>" },
  "starting_items": ["<lasr item name>"],
  "placements": { "<lasr location name>": "<lasr item name> | \"ap-item\"" },
  "location_ids": { "<lasr location name>": "<local id (int)>" },
  "removed_location_ids": { "<lasr location name>": "<local id (int)>" },
  "optional_locations": ["<lasr location name>"],
  "location_names": { "<lasr location name>": ["<AP item name>", "<owner's name, empty for this slot>"] },
  "location_models": { "<lasr location name>": "<lasr item name whose model it shows>" },
  "location_chests": { "<lasr location name>": ["<LASR item type: chest size>", "<chest texture or null>"] },
  "dungeon_entrances": { "<dungeon>": "<dungeon>" },
  "hints": { "<hint source>": { "kind": "<hint kind>", "text": "<hint text>", "player": "<slot of the location (int)>", "location": "<AP location id (int)>" } },
  "ghost_secret": "<32 hex chars, the same in every LAS slot's patch of the multiworld>"
}
```

- `settings` uses LASR's `SettingsManager.fetch()["Settings"]` keys (`lasr_settings.lasr_settings`), as the options set them; the player settings hold their defaults (Client install). "Bad Pets" is always off: it is not supported.
- `starting_items` are what a new save starts with (Start state).
- `placements` covers every LASR item location: AP locations are `"ap-item"`, the kept and fixed ones carry their vanilla item. Owl statues that give no gift are left out, as in LASR.
- `removed_location_ids` gives the owl statues the options leave out their ids, so every mod has each statue's gift (Options). It is optional.
- `optional_locations` lists the AP locations of the activities the options leave out (`LASWorld.optional`). The map tracker leaves them off the map. It is optional: older patches show them.
- `location_names` covers the AP locations. The patcher writes it to the seed file's `names` for the in-game text, which gets the same names at runtime from the client.
- `location_models` leaves out locations that show the Archipelago model. It is optional: older patches show the Archipelago model everywhere.
- `location_chests` gives each AP location's chest the size and texture of LASR's "Chest Types" setting (option `chest_appearance`): for this slot's items, the LASR item's type and `chest-type` with the adjustments LASR's shuffler makes, and `seashell` (the blue seashell chest) for seashells; for other players' items, `important` for progression, `good` for useful, and `junk` with the junk texture for filler and traps (`lasr_settings.chest_look`). The patcher turns it into the module's chests (Item models, **Chests**). It is optional. The patcher gives LASR's seashell the `seashell` chest-type too, so a chest holding this slot's seashell is blue as well.
- `dungeon_entrances` maps each dungeon's door to the dungeon it leads into (Shuffled dungeons): an identity map with the option off.
- `slot_name` is also a new save's name (Save name).
- `ghost_secret` groups the multiworld's LAS players on the ghost relay (Ghosts). It is optional: without it the client shows no ghosts.
- `hints` gives each in-game hint source its kind and text (In-game hints). `player` and `location` name the hinted location when reading the hint makes a server hint. It is optional and empty with the option off.

## slot_data

`{"seed_hash": str, "goal": str, "instruments_required": int, "instruments_known": bool, "seashells_required": int, "seashells_known": bool, "death_link": bool, "location_count": int, "settings": {...}, "logic": {...}, "options": {...}, "starting_instruments": [...], "dungeon_entrances": {...}}`

`goal` is always `wind_fish`: the Wind Fish reached after the egg opened with `instruments_required` instruments or, on a seashell hunt, with `seashells_required` secret seashells (Goal; 0 for what the goal does not take, so trackers tell the goal by `options`' `goal`), through the Nightmare or, on a seashell hunt, straight from the egg's door. `instruments_known` and `seashells_known` are false for a count left to chance (Goal, **Hidden count**); slot data without them counts as known.

`settings` holds the seed's LASR settings that decide which checks exist and what reaches them (`TRACKER_SETTINGS` in `lasr_settings.py`), under LASR's names and values (`"Preset": "Basic"`, `"Owl Gifts": "None"`, `"Seashell Mansion": 15`, ...), as the options set them. Trackers such as PopTracker packs read them on connect.

`logic` is what the client needs to evaluate the world's rules for the map tracker (`tracker.py`): `preset` (the logic option), `tokens` (the settings tokens the rules test), `vanilla` (fixed locations that keep a progression item, whose items count as found once they are reachable), `locked` (AP locations holding their own progression item; the map counts their items once received, like any other), `optional` (`LASWorld.optional`, in logic only once the goal is) and `starting` (the slot's starting items: the patch grants them, so the server does not send them).

`dungeon_entrances` is the patch's (Shuffled dungeons). The map tracker's rules (`LogicTracker`) follow it.

`options` (the world's own option values, `SLOT_DATA_OPTIONS`), `starting_instruments` (the LASR instruments the slot starts with) and `dungeon_entrances` let Universal Tracker regenerate the slot without a YAML: the world sets `ut_can_gen_without_yaml`, `interpret_slot_data` returns the slot data, and `generate_early` takes the options, starting instruments and dungeon entrances from `multiworld.re_gen_passthrough` instead of the YAML and the seed's random (`test_universal_tracker.py` compares the regenerated slot). Universal Tracker asks the server for the starting inventory (items_handling `0b111`), which the LAS client leaves out.

**Deferred.** Universal Tracker leaves what the player finds in the game to the player, through its deferred entrances: the world lists `las_sign_<team>_<slot>` and `las_doors_<team>_<slot>` (Data storage) in `found_entrances_datastorage_key`, and Universal Tracker passes each one's value to `reconnect_found_entrances` when it changes. Its host.yaml setting `enforce_deferred_entrances` (`multiworld.enforce_deferred_connections`) decides: `on` and `default` defer (`LASWorld.deferred`), `off` shows everything at once.
- A count left to chance takes every instrument or seashell until the sign key is true (Goal, **Hidden count**).
- With shuffled dungeons the doors' entrances stay unconnected (`connect_entrances`) until the doors key names them; once eight are found the ninth is connected too, as its dungeon is the one left (`connect_doors`). An unconnected door shows in Universal Tracker's list of unconnected entrances while it is reachable, and the dungeon behind it is out of logic. Universal Tracker sweeps only event locations, so it counts a locked location's item once the server sends it (after the check); the LAS client counts it once the location is reachable.

## Data storage

The client writes these keys from the game's lines; `SIGN` and `DUNGEON` count only from the game of the slot's seed.
- `las_level_<team>_<slot>`: the level the game shows (`Field`, `Lv01TailCave`, ...), from `LOG level`; trackers show the current dungeon's map.
- `las_sign_<team>_<slot>`: `true` once the sign at the egg's stairs is read, from `SIGN` (Goal, **Hidden count**).
- `las_doors_<team>_<slot>`: `{door: dungeon}` for each dungeon door found, by `dungeon_entrances` names, from `DUNGEON` (Shuffled dungeons, **Doors found**).

## Game ↔ client protocol (TCP 43384, game listens)

ASCII lines terminated by `\n`, fields separated by single spaces. The game accepts one client at a time. The client sends `PING` every 2 s, and the game drops a client that has been silent for 10 s.

- The game never waits for the client: the network thread sends on a non-blocking socket, without the lock the game thread takes to queue a line. A client that takes nothing for 10 s while lines wait, or leaves more than `kMaxWaiting` waiting (`ap_net.cpp`; the module's heap is small), is dropped; it connects again, and its `SYNC` brings the game's state back.
- The client logs and skips a line from the game it cannot handle (a field it cannot read, a line longer than its reader's limit); the connection goes on (`LASContext.on_game_line`).
- The game reads a line's fields with `Fields` (`config/fields.hpp`, also the seed file's reader). It answers an unknown command with `ERR unknown command <command>` and an `ITEM` or `NAME` missing a field or with a non-number where a number goes with `ERR malformed <command>`; an id list (`CHECKED`, `INLOGIC`, `DOORS`, `HINTED`) ends at its first field that is not a number, and a `GHOST` line with a bad field is skipped.

- The game listens and the client connects, so a Switch needs no address of the PC. The network thread polls for a client rather than blocking in `Accept`, which would keep emulators from closing the game.
- The client drops a connection that gets no `HELLO` within 5 s: the game serves another client (a second client window), which the Patch tab then says, and Play starts no emulator. The Patch tab shows the game and server connections.
- Opened with a patch file, or given one in the Patch tab, the client logs in as the patch's slot.

**Client → game**

| Line | Meaning |
|---|---|
| `PING` | Keep-alive; the game answers `PONG` |
| `ITEM <n> <item-key> <count> <dungeon> <location> <item name>\|<sender>` | The n-th received item (1-based AP index). `item-key` is the game's item symbol (`SwordLv1`, `SmallKey`, …). `dungeon` is the dungeon level for dungeon items, else `-1`. `location` is the local id the item came from when it is this slot's own, else `-1`. `sender` is empty for own items and items from the server. The game applies it only if `n` = stored count + 1, then answers `RECV <count>` |
| `NAME <local id> <item name>\|<owner>` | What a location holds, from `LocationScouts`; `owner` is empty for this slot's items. Sent for every location on connect |
| `NOTICE <text>` | A toast (In-game text, **Toasts**); `\|` starts a new line. The client sends its connection notices this way |
| `SERVER 1` / `SERVER 0` | Whether the client is logged into the slot of the game's seed: sent when the game connects, when the slot connects and when the server goes away |
| `SYNC` | Asks the game to send `RECV <count>` and `CHECKS ...`, and `GOAL`, `SIGN` and the read hints when they apply |
| `CHECKED <id> <id> ...` | Locations the server has as checked, for the map tracker: all on connect (possibly several lines), then new ones from `RoomUpdate`. Kept in memory only |
| `INLOGIC CLEAR` / `INLOGIC <id> <id> ...` | Locations in logic for the items received, for the map tracker: `CLEAR`, then all of them (possibly several lines), each time the set changes. Kept in memory only |
| `DOORS CLEAR` / `DOORS <id> <id> ...` | Dungeon locations whose dungeon's door is reachable for the items received, for the map tracker's hidden dungeon icons: `CLEAR`, then all of them (possibly several lines), before `INLOGIC` each time either set changes. Kept in memory only |
| `HINTED CLEAR` / `HINTED <id> <id> ...` | Locations of this slot holding a server hint not yet found, for the map tracker (Map tracker, **Hints**): `CLEAR`, then all of them (possibly several lines), on each game connection and each time the set changes. Kept in memory only |
| `DEATH [<player>]` | DeathLink: another player died; a toast names them (see DeathLink) |
| `GHOSTNAMES 1` / `GHOSTNAMES 0` | Whether name tags show over the ghosts (Ghosts); sent on each game connection and when the setting changes |
| `GHOSTS 1` / `GHOSTS 0` | Whether the client relays positions (joined to the ghost relay); with 0 the game sends no `POS` and shows no ghost (Ghosts) |
| `GHOST <n> <level> <x> <y> <z> <yaw> <anim> <anim frame> <upper anim> <flags> <time> <shapes> <tunic> <eye> <mouth> <ear> <slot name>` / `GHOST <n> off` | Another player in this area, in ghost slot n (0–29), with the time its game took the position (ms, 16 bits), or nobody there any more (Ghosts) |
| `MSG <text>` | Logged by the module |
| `DBG <cmd> [args]` | Test-only debug commands (see the module source) |

**Game → client**

| Line | Meaning |
|---|---|
| `HELLO <proto=2> <seed_hash>` | Sent on connect |
| `PONG` | Answer to `PING` |
| `RECV <count>` | Number of items applied (saved; Persistence): in answer to `ITEM` and `SYNC`, and once each time a save has loaded (from the title or the System page's Load), so the client sends the items it lacks |
| `CHECK <local_id>` | A location was collected |
| `CHECKS <id> <id> ...` | Every collected location, sent on connect and on `SYNC` (possibly several lines). The client keeps the checks and the goal of the game connection (a new `HELLO` drops them) and sends them only into a slot whose seed hash is the game's |
| `HINT <slot> <location id>` | An in-game hint was read (its flag is set): once per hint and connection, and all read hints again on `SYNC` |
| `GOAL` | Goal completed: Link entered the `Ending` level, or the `ShadowClear` flag is set (also resent on `SYNC`) |
| `SIGN` | The sign at the egg's stairs has been read (Goal, **Hidden count**): once, and again on each `SYNC` |
| `DUNGEON <n>` | The player has entered dungeon `Lv<n>` (1–8, 10 the Color Dungeon; Shuffled dungeons, **Doors found**): once per connection, and again on each `SYNC` |
| `DIED` | DeathLink: Link died, and no Secret Medicine saved him (see DeathLink) |
| `DEATHDROPPED` | DeathLink: a `DEATH` arrived with no save loaded and was dropped; the client logs it |
| `GHOSTNAMES 1` / `GHOSTNAMES 0` | The player turned the ghosts' name tags on or off in the game (d-pad up); the client keeps it as its `ghost_names` setting and sends it back |
| `LOG <text>` | Debug text; `LOG level <name>` on every level change and when a client connects |
| `POS <level> <x> <y> <z> <yaw> <anim> <anim frame> <upper anim> <flags> <time> <shapes> <tunic> <eye> <mouth> <ear>` / `POS none` | Link's position while the client asks for it (`GHOSTS 1`), with the time it was taken (ms), or no player (title, file menu, level load, leaving a level by its exit) (Ghosts) |

Lines that need a loaded save (`ITEM`, `SYNC`, `DEATH`, most `DBG`) wait until the player has stood in the current level for a moment (`kSettleMs` in `ap_game.cpp`), counted again from each level reload; other lines are handled immediately. A jump to another point of the same level (Manbo's Mambo, a warp hole) keeps Link and the level's name, so the module marks each level jump from its start (`LevelManager_LevelJump`) until the level arrives (`SetCurrentLevel`, `game/hooks/level.cpp`) and counts the moment again from there. From the game over menu on they wait until its Retry has reloaded the level, as do item displays: Retry stands Link up with full health before the reload, under the same level name.

**Items with special handling in the module**
- Progressive sword, shield and bracelet arrive as their Lv1 key; the module upgrades when LASR's `*FoundFlag` is set.
- Seashells, heart pieces, heart containers, golden leaves and bottles take the lowest in-game index that is unused and that no vanilla source sets (Indexed items, above).
- The Secret Medicine is a single inventory bit, and the pool has three. One received while Link holds one shows its item-get and waits in the save (`APMedicine0`..`APMedicine1`, a count up to 3); once Link is free with none (the medicine revived him), the module gives the next with the notice "Secret Medicine from your stock". A patch without the flags loses such a medicine.
- Traps (`*Trap`, `$ENEMY`, the Zol Trap) wait like item displays (below). Unknown keys are logged and counted as applied.

**In-game text**
- A found placeholder says what it is: "You found <item> for <player>!", or "You found your <item>!" for this slot's own items. The patcher writes the names to the seed file's `names` (`NAME` lines without the command), which the module reads at boot, so this works before the client connects; `NAME` lines replace them. A location without a name says "You found an Archipelago item!".
- **Toasts.** Notices that are not items, and items with Instant Pickups, show in the autosave popup (`ThrobberSave`, the "Now saving." text with a spinning icon at the bottom right; scripts/re/UI.md, Autosave popup), which does not stop the game:
  - The module shows `NOTICE` lines from the client and "Archipelago client disconnected" when the client goes away. While the client or the server (`SERVER`) is not connected, it shows "Archipelago client not connected" or "Archipelago server not connected" after a while in a level and then again at intervals (`kOfflineNoticeMs`, `kOfflineRepeatMs` in `ap_game.cpp`); after a disconnect notice, the first reminder waits a whole interval.
  - The module shows the popup in its auto mode with the toast as its text (`ap_text.cpp`). A toast waits while the popup is busy, as during a real save; a save during a toast shows the toast's text.
  - The patcher widens the popup's text pane and its text buffer, and replaces the egg icon with the Archipelago logo (`ap_ui.py`, `StartUp.arc`). The loading screen's spinner shares that texture.

That makes a random value (Archipelago's `random`, `random-range-<min>-<max>`, ...) readable in the game.

**Shuffled dungeons** (option `shuffled_dungeons`, settings key `Shuffled Dungeons`; `lasr.door_logic`, `lasr.dungeon_logic`, `patcher/ap_entrances.py`)
- Each of the nine dungeons' overworld doors leads into a random dungeon, the Color Dungeon included, as in LASR's shuffler (`lasr.shuffle_dungeons`). `dungeon_entrances` names each door by its dungeon's LASR region (`tail-cave`, ...) and maps it to the dungeon it leads into.
- **Logic.** In LASR's logic a dungeon's region node is its inside, and its conditions are its door's. The Face Shrine's region is either of its entrance rooms (`D6-8D`, or `D6-3A`, which its side entrance reaches); its door is the outside part of `D6-8D`'s conditions (`river & face-key & (hookshot | rooster)` and the room's glitched and hell conditions). LASR's shuffler moves only `condition-basic`, and moves the Face Shrine's region with its entrance rooms.
  - The world (`lasr.door_logic`): each door is a region of its own (`<dungeon>-door`, entered from Menu) with the door's conditions, those of every preset, and an AP entrance (`<Dungeon name> Entrance`) into the region of the dungeon it leads into (`lasr.dungeon_region`: the dungeon's, the Face Shrine's `D6-8D`), which `connect_entrances` connects. Those regions have no other way in (`lasr.ENTERED_BY_DOOR`), but `D6-8D` keeps the way in from `D6-3A`. The logic is the same for every map of the doors; the map is in the entrances.
  - The top of Turtle Rock (`Field_01A` to `Field_01C`: the heart piece, the side doors into Turtle Rock's rooms `03C` and `03F`, and the warp point `WarpPoint.gsheet` index 1) is a region of its own, `turtle-rock-top` (`lasr.EXTRA_NODES`, `lasr.MOVED_LOCATIONS`), entered from Turtle Rock's `D8-4C`, so it follows Turtle Rock through whichever door leads into it. LASR has the heart piece in `taltal-west-2` with the condition `D8-4C`. Neither LASR nor the world has a way onto the top from a warp point or back into Turtle Rock's rooms through the side doors: the warp point unlocks only once Link stood on it, after walking through Turtle Rock. Shuffled warp points would need both, and Turtle Rock's rooms by its side doors (LADXR's `dungeon8.py`: the top joins the rooms either side of the F stairs).
  - `lasr.dungeon_logic` gives each dungeon the conditions of the door that leads into it, with the door leading into the Face Shrine replacing the outside part of `D6-8D`'s. `test_logic.py` checks the world's entrances against LASR's evaluator with these conditions.
  - The client's map tracker (`LogicTracker`) takes the world's door logic and enters a dungeon's region from the region of the door that leads into it once that door is found (**Doors found**), as Universal Tracker does: until then the dungeon's checks are out of logic, and so is what only its inside reaches (the Rapids' south island chest through the Face Shrine's `D6-2A`, the top of Turtle Rock, the Color Dungeon's shop slot). `test_tracker.py` checks the client's rules against the world's.
- **Patch.** The rooms and flowcharts keep their vanilla targets; the module leads the level jumps (`LevelManager_LevelJump` hook, `ap_jumps.cpp`). The seed file's `jumps` (`jump_lines`) has `<from level> <level> <locator> <new level> <new locator>` per led jump, a jump from `<from level>` to that level and locator going to the new one instead. Per door that leads into another dungeon (`ap_entrances.jumps`), the overworld's jump to the door's dungeon entrance goes to the entrance of the dungeon behind it, and that dungeon's jumps to the outside of its own door (its exit, its instrument's warp, the Fairy Queen's warps and her room's loading zone `Lv10ClothesDungeon_04C`) go to the outside of the door that leads into it. The module swaps the overworld map's dungeon markers: the seed file's `markers` (`ap_entrances.markers`) has `<door's marker label> <label> <show flag>` per door that leads into another dungeon, the label and show flag of the dungeon behind it, and once the game has loaded the map's sheets at boot (`UiDatasheets_Load`) the module gives each such door's `UiFieldMapIcons` row those, in memory (`ap_jumps.cpp`). The map tracker's dungeon icons sit at the door that leads into their dungeon and hide its name until it is entered. The side entrances of the Face Shrine (`Field_07M`) and Turtle Rock (`Field_01A`, `Field_01C`) are not shuffled.
- **Doors found.** The first time the game shows a dungeon's name on entering it, it sets the dungeon's marker flag (`UI_FieldMapIcon_Lv<nn>Dungeon`), the flag that shows the dungeon's name on the map (Map tracker). The module reports each dungeon whose flag is set as `DUNGEON <n>` (`ap_checks.cpp`, with the in-game hints' flags), so dungeons entered while the client was away count too. The client adds the door that leads into each to `las_doors_<team>_<slot>` (Data storage; `update`, once per server connection), for the slot of the seed the game runs only. The PopTracker pack sets each found door's item to its dungeon, unless the player marked it Dungeon Completed; on another seed it sets every door back to Unknown. The slot data has every door, but the tracker shows only the doors found, as the map does. Universal Tracker connects a door's entrance once it is found (slot_data, **Deferred**). The client's map tracker takes as found the doors into the dungeons the game reports and those in `las_doors_<team>_<slot>`, which it asks for on connecting (`Get`), as the save may have lost a marker flag; once eight doors are found, the ninth counts as found too (`tracker.known_doors`).

**Map tracker** (option `map_tracker`, settings key `Map Tracker`; `patcher/ap_map.py`, `modbuild/ap_map_edits.py`, `map/`)
- The pause map shows the slot's unchecked locations, and the whole overworld and every dungeon room are revealed. Off for a patch without the settings key. The map pages, their markers and the cursor in the game: scripts/re/UI.md (Overworld map, Dungeon map, Map cursor, Map markers, Markers made by the module).
- **Positions.** `patcher/map_positions.json`, written by `scripts/map_positions.py` (whose docstring gives the sources and rules: item actors, the doors into buildings and caves, NPC actors, else the LASR PopTracker pack's pins through an affine fit), gives each location a place: overworld locations world coordinates (x, z, and the height y, as the map draws higher places further north), dungeon locations a room and level coordinates (a location in Eagle's Tower's collapsed top also its room before the collapse, on 3F). Each entry also has the AP location name, and each overworld location the name of its spot: its place in the PopTracker pack (the parent of its section), or `SPOT_NAMES`, which gives the checks of different places that share an icon one name.
- **Overworld icons.** The patcher groups every overworld location of `map_positions.json` within 3 units of each other (in name order) and adds four `UiFieldMapIcons.gsheet` rows per group, one per look, each with `APMap<mark><group>` as its show flag and its name label: in logic (no mark), partly in logic (`P`), out of logic (`X`) and collected (`C`). Each dungeon door also gets a group, 2.5 units east of the game's marker of the door (`DUNGEON_MARKERS`, `door_groups`), holding the checks of the dungeon behind it. The rows are the same in every seed: the seed file's `map` gives each group the slot's locations in it (`O` lines). Only the patch's `location_ids` are listed, so checks left vanilla are off the map, and its `optional_locations` are left off too, as PopTracker hides them; a group without any shows no icon. The module's `CheckFlag` hook answers the show flags: the group has locations and its look is set. A location counts as checked in the checks file or by `CHECKED`, and in logic by `INLOGIC` (every location before the client's first `INLOGIC`). The hover text (`Place:APMap<mark><group>`, empty entries the patcher adds, whose text the module gives) is the group's name (`ap_map.group_name`: its dungeon, as `D1 Tail Cave`, its location's name without its region, or its first location's spot; `NAME_WIDTH` fits it), after `<to do>/<unchecked> ` when the group has several locations and some are unchecked: to do are those in logic neither checked nor skipped, unchecked those not checked. With shuffled dungeons a dungeon's group reads `Unknown dungeon` (`HIDDEN_DUNGEON`) without a count, and shows its door's look unless collected (in logic while that door can be reached, `DOORS`), until the dungeon's marker flag is set (Shuffled dungeons, **Doors found.**): the group sits at that door, so its name, count or checks' look would tell where the door leads.
- **Icons.** `ap_map_icons.py` adds the looks to `Game.arc` (an asset): dots (green, green and red split diagonally, red, grey with a tick) and a gold ring around a hinted one (Hints), a texture per look and frames of the marker's `SetMark` animation after the game's, per look one at a group's size and one at a single check's (`frame()`). A row's `mType` picks the group's frame; the module sets a marker of a group of one location to the single check's (`FitFrame`, `map_icons.cpp`).
- **Logic.** The client evaluates the world's rules (`LogicCompiler`, `logic.py`) for the items received with `tracker.LogicTracker`, from the slot data's `logic`: a state holding item counts and region stand-ins, with regions and the progression items of vanilla locations added until nothing changes, as Archipelago's sweep does. A location is in logic only for the items the player has: a locked location's item (a trade item, a companion) counts once received, not while the location is reachable, as the player may not know where it is (Mamasha needs the Yoshi Doll in hand). An optional location is in logic only once the goal is (the egg with `instruments_required` instruments, then the Nightmare; on a seashell hunt the egg with `seashells_required` seashells). `test_tracker.py` checks it against Archipelago's reachability with a sweep that leaves out the locked locations. With shuffled dungeons a dungeon is in logic only through a found door (Shuffled dungeons, **Logic**). The same sweep (`LogicTracker.sweep`) gives the dungeon locations whose door, the one that leads into their dungeon, is reachable, found or not. The client sends them as `DOORS`.
- **Overworld reveal.** The map shows an area once its flag `UI_FieldMapTraverse_<area>` is set, and plays the reveal once `UI_FieldMapOpen_<area>` is not; the `CheckFlag` hook answers both as set. `LocationName.gsheet` gates the area name banners on the same flags.
- **Dungeons.** The dungeon map draws the rooms Link visited and, with the compass, the room icons. While Link is in a dungeon the module fills its visited-room mask, so every room counts as visited in the save, and an inline hook makes the compass and the map read as owned for the map screen only; the sidebar still shows the items Link has.
- **Out-of-logic toggle.** The map's X button, which opens the memories, hides and shows the out-of-logic icons instead, on both map pages; its caption (`UI:MapCaptionMemory`) reads "Toggle out of logic" after the button's glyph tag, "Offline: toggle out of logic" while the server is not connected, or "Offline: logic unknown" before the client has sent any `INLOGIC` (every location then shows in logic). The module reads the press where each page does and clears it. Out-of-logic markers are made as any other, and a hook after the icon setup hides them while the toggle is off; toggling sets their visible bit on the open page. The toggle is kept in memory only.
- **Skipping a check.** A on an overworld icon of one unchecked location marks that location skipped, and A again unmarks it (`SE_SY_DECIDE`); the press then does not reach the game. A on an icon of several locations opens its check list (below). A on empty map still opens the game's pin menu, and A on any other icon does what it does in the game. A skipped location counts as checked on the map: its icon shows collected, its hover text reads "Skipped: <name>", and it leaves a group's to-do count but stays in its unchecked count. A location checked in the game or on the server cannot be marked. The mark is the player's alone: the client and server are not told, and the module keeps it per seed (Persistence). A mark swaps the visible bits of the icon's markers on the open page (Live updates), and the hover moves to the shown marker.
- **Live updates.** The open map follows a logic (`INLOGIC`, `DOORS`), checks (`CHECKED`) or hints (`HINTED`) update one frame after its last line, as an update comes in several lines: the overworld page's markers and the dungeon page's dots take their looks, an open check list its rows, and the cursor's name, while it shows one of ours, its text (`MapCursor_ShowName`). An overworld icon has a marker in every look skipping or an update can give it while the map is open (collected, in logic and out of logic with an unchecked location, partly with two unchecked unless its name is hidden); the hook after the icon setup hides those not shown.
- **Check list.** A on an overworld icon or dungeon dot of several locations opens a panel in the middle of the map listing them; the map dims behind it. Not for a dungeon's icon whose name is hidden (Shuffled dungeons). It is built from the game's layouts, hung under the map page and dropped with it (`map_checklist.cpp`, which names the layouts and panes; the list, the pad and the guide are `ap_list.cpp`'s, shared with the Jukebox page):
  - the panel: the Memories list on the paper window of the Memories' count, as on the Jukebox page, sized to the header and the rows, opaque enough that the map's place names do not show through;
  - the header names the icon as its hover text does ("Mabe Village", "D1 Tail Cave"), with its count as in that hover text, "<to do>/<unchecked>", on the right: skipping a location lowers the first number, not the second;
  - a row per location of the icon, checked ones included, in the `map` section's order: the location's name without its area (`N` lines), narrowed to fit one line, after a dot of its look (the map's marker at `ap_map_icons.frame` for that look): in logic green, out of logic red, checked or skipped the grey dot with a tick. A skipped location has a small light grey italic "skipped" after its name, a hinted one the item hinted there at the row's right end (Hints); a checked or skipped location's name is dimmer. Out-of-logic locations are listed also while X hides their icons;
  - Up and Down move the cursor, repeating while held (`ap_list.cpp`'s `kRepeatDelay`, `kRepeatEvery`), and the list scrolls past seven rows with its scroll bar;
  - A marks the location under the cursor skipped or not, by the rules of an icon of one location (a checked one beeps, `SE_SY_BEEP`); the row, the header's count and the icon on the map change at once;
  - B closes the panel (`SE_SY_MAP_OMOIDE_OFF`; opening plays `SE_SY_MAP_OMOIDE_ON`), back on the map; the buttons held as it closes reach the game only once released, so B does not close the menu, and a Minus held as it opened is let go (not a tap that closes the menu once released);
  - while it is open the game sees no buttons and no sticks, so nothing reaches the map or the pause menu; the panel reads the pad itself. The map's cursor and its name are hidden;
  - the guide reads "Ⓐ Skip / unskip Ⓑ Back" (the map's guide with A and B in its first two slots and the rest hidden, `MapCaptionPin` read as "Skip / unskip"), and the map's own again once the panel closes.
- **Dungeon dots.** The dungeon map shows the slot's dungeon locations as dots in the overworld icons' looks (smaller for one location), one per spot: locations within `DOT_DISTANCE` of each other in the same room share one, as Key Cavern's basement key and its owl statue do; a location with two places has a dot in each. The game's chest icons of the slot's chests are hidden; the other room icons stay. The dungeon page has no icons of its own for checks, so `map_dots.cpp` adds them:
  - after the page's setup, a map marker per dot of the current dungeon whose room the page shows, placed as the page places its room icons and hung after them, so the pins draw over the dots;
  - a dot shows while its room is on the shown floor, following the page's floors, also in Eagle's Tower once its pillars are broken (its 3F then shows the rooms of 4F and of the collapsed top); X hides the out-of-logic dots as it hides the overworld's icons;
  - while no pin is hovered and Y does not show the dungeon's info, the nearest shown dot within the pins' radius is hovered: it plays its On animation and the map cursor names it (`Place:APMapDot`, whose text the module gives as an overworld icon's: count, name or "Skipped: "); with the stick idle the cursor eases onto it as onto a hovered pin;
  - A on a hovered dot does what A on an overworld icon does (Skipping a check, Check list) and places no pin; on a dot of one checked location it beeps.
- **Hints.** The client sends the slot's locations that hold a server hint not yet found (`HINTED`, from the server's `_read_hints_<team>_<slot>`, which Archipelago's client keeps), and `NAME` lines say what each holds. A location shows its hint while it is neither checked nor skipped and its item has a name:
  - its overworld icon and its dungeon dot get a gold ring: a map marker at the ring's SetMark frame (`ap_map_icons.ring_frame`, its inside on the dot's edge), made after the page's setup for each icon or dot with a hint then and hung just before the icon, so it draws under it, at the icon's place (`MakeRing`).   - while the page waits for buttons with the cursor on a ringed icon or dot, a paper strip on the rule under the map reads "Hints: <item>, <item>" (`map_hintstrip.cpp`: the check list's paper window and texts, built with a page that has rings; as many items as fit, then "+<n> more" for the others, which the check list shows), each item as `HintedItemText` gives it: "<item>", or "<item> for <player>" for another player's. **In-game hints** (options `in_game_hints` and `hint_distribution`; `hints.py`, `patcher/ap_hints.py`, `modbuild/ap_hint_edits.py`)
- The hint sources are the 9 overworld owl statues, the 24 dungeon owl statues (by the LASR name of their location) and six of the library's books (`book-<color><n>`, the book actor's name); the map, the egg book and the Color Dungeon's book keep their text. Dungeon owl statues need their dungeon's stone beak, as in the game.
- The world picks the hints once the multiworld is filled (`choose_hints`, with the world's random). An area is the part of a location's name before " - " (Location names): an overworld region or a dungeon. The kinds:
  - `always`: one of this world's long checks (`hints.ALWAYS`) that is shuffled, not optional, and holds a progression or useful item, anyone's: "Your <item> is at <location>." or "<location> holds <player>'s <item>.".
  - `required`: an area of this world, or a location of another, holding an item of this slot without which the multiworld's other items do not reach this slot's goal (a sweep without that location's item; tested only as hints are wanted, this world's locations first, one hint per area or location): "Something in <area> is needed to wake the Wind Fish." or "Something in <player>'s world at <location> is needed to wake the Wind Fish.".
  - `barren`: an area of this world whose locations, events included and optional ones left out, hold no progression item of any player, with at least two locations whose item is not known anyway: "<area> holds nothing anyone needs.".
  - `area`: "Your <item> is in <area>." or "Your <item> is in <player>'s world.", this world's locations first.
  - `precise`: "Your <item> is at <location>." or "Your <item> is in <player>'s world at <location>.".
  - `joke`: a joke line, for the sources left over.
- `hint_distribution` sets how many of each, in the order they are picked (`hints.DISTRIBUTIONS`): `precise` only precise hints; `balanced` (default) some always, required, barren and area hints, precise for the rest; `vague` more required and barren hints and a few precise ones, area for the rest. A kind that runs out leaves its sources to the rest's kind, then to precise and area hints (`FALLBACK`), then to jokes. Area and precise hints name this slot's progression items first, then useful ones; each location is named once. They leave out the locations whose item is known anyway, and those nobody needs: unrandomized, kept, locked and optional locations of this slot, items in `start_hints` and locations in `start_location_hints`, seashells, dungeon items in their own dungeon; no hint rests on an owl statue's own gift for that statue. The spoiler lists each source's hint with its kind.
- In every patch each source shows its own message (`ap_hint_edits.add`), `Hint:APHint<n>` for owl statues and `System:APHint<n>` for books (n: the source's place in `ap_hints.SOURCES`): a copy of the text it replaces, with its window style, so a patch without hints keeps the vanilla texts. Owl statues that share an entry point (Tail Cave 04B and 05F, the three Color Dungeon statues) get entries of their own, as LASR's Owl Gifts give them, with their own copy of the statue's events. With Owl Gifts on, the gift follows the hint.
- The seed file's `hints` (`ap_hints.lines`) has, per source with a hint: `L <n> <text>` per line and `P <n>` before each further page, wrapped to `LINE_WIDTH` characters and `PAGE_LINES` lines per box (a line never starts with the dash between a location's region and spot); for a book `B <n> <question label> <volume>`; with `server`, for a hint that names one location (`always`, `precise`), `S <n> <slot> <location id>`. The module (`ap_text.cpp`) shows the hint in the source's message, owl statues' in their sky blue, and names a book with a hint "Koholint Lost and Found, Volume <n>" in its question's first line. Showing a hint sets the event flag `APHint<n>` (`ap_hints.FLAGS`, all in `GlobalFlags.gsheet`), which the save keeps. The module polls the flags of the `S` lines and sends `HINT` lines; the client sends `CreateHints` with priority status for each new one, or on servers before 0.6.2 `LocationScouts` with `create_as_hint` 2 for this slot's own locations. It sends them again after each server connection; the server skips hints it has.

- The multiworld's other LAS players show where this player is, as see-through Links. Positions travel game → client → ghost relay → the other clients → their games; the AP server is not involved. Running a relay (options, password, port forwarding, proxies, container, service): docs/ghost-relay.md and the setup guide (`apworld/las/docs/setup_en.md`, Ghosts); its limits are `ghost_relay.py`'s constants (`MAX_GROUP`, `MAX_PER_ADDRESS`, `MAX_RATE`, `WRONG_PASSWORD_DELAY`).
- **Relay.** `ghost_relay.py` (standard library only, runs on its own) can serve any number of multiworlds. The client connects to the one in `las_options.ghost_relay`, else the patch file's (the generating host's `las_options.ghost_relay`), else `DEFAULT_RELAY`, which is also the setting's default value, so the patch file's relay applies only to a player who empties the field. The default relay failing is a note in the Patch tab (INFO), not an error, as nobody chose it. The world draws one random secret per multiworld (`LASWorld.ghost_secret`) into every LAS slot's patch file, not into the slot data, which anyone who can log into a slot reads. A client joins the group SHA-256(`lasghost|<secret>`) (`group_id`) with its slot name and player name, so the relay never sees the secret; the LAS players of one multiworld share a group whatever their slots' seeds. The relay forwards a player's frames to the group's members in the same level, in `Field` only to those within the 3×3 screens around the sender (`field_screen`); each member gets the `MAX_SHOWN` nearest players of its area (the game's ghost slots; chosen again every `CHOOSE_EVERY` with a margin, `KEEP_MARGIN`), its frames batched (`BATCH`), and a still player's last frame at once on entering that player's area. A player who leaves a member's area, is in no level, sends nothing for `SILENT_OFF` or leaves the group gets an `OFF`. A second connection of the same slot of the same multiworld replaces the first. With `--nogroups` every member is in one group (`ONE_GROUP`): the relay still tells a reconnect by the join's group and slot name, and the client tells its own player by the id in `WELCOME`, not by its slot name, which another multiworld's player may share. With `--password` the relay lets in only joins carrying it, the join's last field (optional, so a relay without a password takes joins without it); the client takes it from the address, `password@host:port`, and leaves it out of its status messages. The password travels in plain text: it keeps strangers off the relay, not eavesdroppers.
- **Wire.** `ghost_relay.py` defines it, both ends included (`connect`, `WebSocketReader`, `WebSocketWriter`). TCP with TCP_NODELAY (also between the game and the client), or a WebSocket on the same port (RFC 6455; the client uses one for a `ws://` or `wss://` address, `http://` and `https://` taken for them) for a relay behind a proxy such as a Cloudflare Tunnel; the relay tells them apart by the first byte. Each message is a u16 length (big-endian) and a payload whose first byte is its type (`JOIN` … `ERROR`, with their fields); a WebSocket's binary messages carry the same byte stream (a relay batch one message, a client frame one). The join carries `PROTOCOL_VERSION`; the relay refuses a client of another version. A position (`Pos`, `encode_pos`, `decode_pos`) has the sender's game clock when it took it (ms, a wrapping u16), the level (the index in `LEVELS`, append only), x/y/z, yaw, Link's animation (`PlayerAnimation.gsheet` key + 1) and its frame, his upper-body animation, flags (`FLAG_WARPED`, `FLAG_HIDDEN`, `FLAG_STILL`, `FLAG_STARTED`), the shapes of his model drawn (`SHAPE_COUNT`), his tunic and the frames of his face's three material animations. A keyframe carries every field; any other only the fields that changed since the sender's previous position, which the receiver applies to it. The level changes only with a keyframe, and so does a jump too far for a difference. A client sends a keyframe first and after `NOWHERE`. The relay keeps each member's last position: to a member that got each of the sender's frames since a keyframe it passes a frame on as it came, to any other (the sender just shown to it, a frame dropped for it or over the sender's rate) a keyframe of its own. Proxy headers count for the per-address limit only from a trusted proxy (`Relay.trusts`, docs/ghost-relay.md).
- **Rate.** The module sends `POS` at most every `kMovingMs` while the position, yaw, level or animation changes, and every `kStillMs` while Link stands still (`ghost_net.cpp`). What the player does goes out at once: a new level, an animation starting (another one, or the same again from its start), a turn of `kTurnDeg` or more, starting or stopping to move, another look; the animation frame running on is no change. The client caps frames at about the same rate (`MIN_INTERVAL`), what the player does excepted. Flag warped: the first position in a level and a jump of more than `kWarpDistance`.
- **Client.** `GhostLink` joins once ghosts are on, a relay address is set, and the patch file's ghost secret (`--ghost-secret` replaces it, for tests) and the slot name are known; it reconnects when any of them changes, and after a failure with a growing delay. It gives each player in the area one of `GHOST_SLOTS` ghost slots and turns the relay's frames into `GHOST` lines; a player beyond them waits for a free slot. It sends `GHOSTS 1` once joined and `GHOSTS 0` when it leaves. The Patch tab has "Show ghosts" (`las_options.ghosts`, on by default), "Ghost relay" (`ghost_relay`, `DEFAULT_RELAY` by default) and the relay status; `/ghosts [on|off]` in the client; `/ghostrelay [<address>|default]` shows the relay in use and where it comes from (the setting, the patch file or the default), or sets the setting. `/ghostnames [on|off]` turns the name tags on or off (`ghost_names`, on by default) with `GHOSTNAMES`; so does ↑ on the d-pad in the game while ghosts are on (D-pad in the game, Music).
- **Module.** `ghost_net.cpp` reads Link's position, yaw, animations and look each frame, with no player during level loads and while he stands at the origin (leaving a level by its exit), and keeps the last `GHOST` lines per slot (`HISTORY`). A new client connection clears both until it sends `GHOSTS 1`.
- **Puppet** (`ghost_puppets.cpp` and its parts, the other `ghost_*.cpp`; the test build's `DBG puppet`). Each ghost slot of `GhostNet` has a puppet: an `NpcGhost` actor spawned through the game's actor factory, whose NPC component the module gives the Npc row `APGhost` while it spawns it, drawn with Link's model from `PlayerGhost.bfres`, dithered in screen space (`ghost_dither.cpp`), with no collision, action or event triggers. The asset build adds the row and its facial row (`ap_player_ghost.py`), the patcher makes the model from the player's `Playerlink.bfres` (`ap_ghost_model.py`, Assets); `scripts/ghost_puppet.py` adds them to a test mod deployed from an older patcher output. In a mod without the `APGhost` row the module spawns no puppet, since `NpcGhost`'s component looking up a missing row crashes. Each frame the module places the puppet by replaying the slot's `GHOST` lines on the sender's clock a buffer behind, the buffer following how evenly they arrive, so a late or bursty link shows as a ghost further behind, not a jerky one (`ghost_replay.cpp`). It plays the sender's animation by name (the key's file name in its own game's sheet) from the sent frame, the upper-body animation on a second layer as Link's (the `APGhost` row only), and for a sender with no animation id `wait`, `walk`, `run` or `dash_lp` by its speed. It draws the line's look: shapes, tunic and face (`ghost_look.cpp`).
- A ghost that arrives (a warped line: another level, a respawn, a warp) stays hidden until a later line moved, started or changed the animation, or `kArriveHoldMs` passed on the sender's clock, so a player entering a level stands still through their own fade-in first; it shows again with that line, whose animation then plays unblended. A ghost is ready, and its name tag and instanced shapes show, once its body has drawn two whole frames with its actor active.
- A puppet shows while the client is connected, its ghost is in Link's level and not hidden, and its last line is under `kStaleMs` old (a backstop for a lost off: a still player's game sends twice a second). Otherwise it hides and waits for its ghost again; after `kHiddenRemoveMs` hidden its actor is removed, and a later line spawns a new one. Factory actors outlive level changes, so a slot keeps its actor (a weak reference; the actor system owns it) across them. `NpcGhost` is zone-scoped and an actor of a zone Link has left is suspended (scripts/re/ACTORS.md, Activity); a ghost goes where its player goes, so every puppet spawns in zone -1, which is never suspended.
- **Crowds** (`ghost_crowd.cpp`). Each shape a ghost draws costs a draw call in each of two render passes, and on an emulator the draw calls limit the frame rate (TESTING.md, Ghost crowd), not the lines or the module's own work. The nearest ghosts draw their whole look, the next ones only the arms, tunic, face and hair (`kCrowdShapes`), the farthest none. How many of each follows the frame rate the module measures, slowly and with minimums (`kMinWhole`, `kMinDrawn`), so the game's own slow moments do not hide ghosts, and with a ranking margin per step of detail, so ghosts at about the same distance do not switch back and forth.
- **Instanced equipment** (`ghost_instanced.cpp`). The shapes of Link's model bound to one bone each (the swords, the shields, the Magic Rod, the shovel, the hookshot and the ocarina at the hands, the ear, eyes and mouth at the head) draw once for all ghosts, as the game draws its lawn grass: per group of shapes shown together one InstancedModel component on Link, one record per drawn ghost whose look has the group's shapes, written each frame (scripts/re/MODELS.md, Instanced models). The puppets draw none of these shapes; while a ghost's face differs from the instanced one (all frames 0) it draws its own face shapes. The components are made again in each level; their draws dither as the ghosts' do.
- **Name tags** (`ghost_nametag.cpp`). A ghost drawn whole has its slot name (up to 16 characters, Archipelago's limit) over its head bone in the game's action prompt (`Gm_HUDInteract.bflyt`) without its button picture, smaller: a layout of its own per ghost slot, drawn over the HUD and under menus and the message window, hidden off screen. The name goes in through the game's message pipeline (scripts/re/UI.md, Text boxes, Glyphs). The tags are built again after each level load.

**Music** (jukebox; `music.cpp`)
- The Jukebox page chooses a BGM that plays instead of the zone's music until the player stops it, through `AP::Music::Choose`. The tracks are the patcher's `BGM_TRACKS`, the looping tracks the Music setting shuffles, then the Ballad of the Wind Fish (`music_tracks.hpp`). The module keeps the choice while the game runs, until a save loads: the title's file menu (no save loaded there) and the System page's Load (`FileOperate20_StartLoad`) turn the Jukebox off, so a track chosen in one save never plays on into another, and the loaded save starts on its zone's own music. It leaves the client out of the choice: no protocol line carries it and the client logs nothing of it.
- The module's hook on `BgmManager_Play` asks for the chosen track in the zone music's calls (the zone update and `PlayZoneBgm`, told apart by their return address, and the rapids game's end, which plays `BGM_FIELD_NORMAL` itself) and in the event action `PlayBGM`'s call for the two event songs that stand in for the zone's music with no `PlayZoneBGM` after them, the washed-up sword's `BGM_FIELD_NORMAL_INTRO` and the new game's wake-up `BGM_HOUSE_FIRST`; the game then treats it as the zone's track (the BGM manager: scripts/re/FRAMEWORK.md, Audio). While music that stands in for the zone's plays (Marin's song, a miniboss's, the Rapids Ride's and the race's), the zone update asks for it again so it plays on; the hook leaves those calls to the game, so that music plays alone and the chosen track comes back after it. It replaces the zone's track whatever the Music setting did to it, also with Music Removed: the game's requests go through the music shuffle (Options, Shuffles), the chosen track does not. It keeps playing through room changes and through doors to other levels: the module keeps it out of the doors' and the level load's stops until it knows what follows. A level load, or the game asking for the zone's music again: it plays on. Another track starting (an event's song, a fanfare), or the player free for a few frames with neither (an event that meant silence): it stops then (`music.cpp`, Doors, also for stairs between 2D and 3D rooms). A track that sets its volume by Link's height reads him with no check; the module's hook makes that update do nothing while there is no player.
- The game's uses of a track by name follow the choice: the Great Fairy's `BGM_FAIRY` (her positional instance, her volume by Link's distance, her stop by name) and an event's `Audio.StopBGM` of a song that is the chosen track are held as the doors' stops are, and her instance becomes the chosen track's when a zone call finds it playing (`music.cpp`). So `BGM_FAIRY` chosen in the woods plays at full volume and plays on through the Woods Crossing Cave's doors.
- Every other request plays as the game makes it: event songs, Marin's and the instruments' songs, boss and miniboss music, fanfares, jingles, the Guardian Acorn's and Piece of Power's music. Events silence music with `StopAllBGM` and bring it back with `PlayZoneBGM`, and stop only their own songs by name (no event stops a zone track), so the chosen track gives way to event music and comes back where the zone's music would.
- On a change the module calls `PlayZoneBgm` with fading: the new choice (or, with off, the zone's own track) starts from its beginning, intro included, after `kStartDelayFrames` (0.5 s), and the other zone and event tracks fade out. The track that played before the change is also stopped by name, for the cases where nothing new starts (a zone without a track, a buff's music playing). A change waits while the BGM manager prepares a track, which no fade or stop reaches before it starts, and then applies the latest choice. An unknown name (`BgmTable_Find`) is refused and clears the choice.
- **Ballad of the Wind Fish.** The Wind Fish's Egg plays the Ballad for the instruments Link has (`WindFishsEgg.bfevfl`'s `PlayOrchestra`, `Orchestra_Play` in las.sym): most sets as `BGM_ENSEMBLE_INST`, a stream of eight tracks, one per instrument, whose `onStart` silences the tracks of the instruments Link lacks. The Jukebox's Ballad is `BGM_ENSEMBLE_INST` for every set of instruments: the hook gives its instance the egg's `onStart`, so the tracks of missing instruments are silent from the first sample, and an instrument found while it plays fades its track in (one lost, out). The stream does not loop (the egg plays it once), so the patcher writes a looping copy beside it, `BGM_ENSEMBLE_LOOP.bfstm` (`ap_ballad.py`), which the module's `nn::fs::OpenFile` hook opens in the original's place while the latest request for the ensemble is the Jukebox's; the egg's request opens the original and stops the Jukebox's copy first. A mod without the copy plays the original. Its eight channels leave room for only one more stream, and a stream that starts without room is dropped (`music.cpp`, Stream channels), so the Jukebox's Ballad waits for its channels and for no jingle, gives way to a jingle and to any stream that would not fit beside it, and comes back from where it would be had it played on; meanwhile it counts as playing. With no instrument it cannot play (`AP::Music::Playable`): a choice of it is refused, next and previous pass over it, and a save without instruments loaded while it is chosen turns the Jukebox off.
- **Mute.** While muted, all music plays silent: every BGM but the jingles (item fanfares, the ocarina's songs), so the zone's music, events' songs, boss music, the buffs' music and the chosen track. The game's music runs on as without it: tracks start, stop, duck under jingles and take their stream channels. Every BGM volume goes through `Sound_SetVolume`, also the volumes tracks set themselves each frame (by Link's height, the Great Fairy's by his distance), whose hook gives music 0 and keeps the volume the game asked for, which unmuting gives back; both fade over `kMuteFadeFrames`. The mute lasts while the game runs.

**Jukebox page** (`music_jukebox.cpp`, `music_tracks.hpp`)
- The pause menu's fourth page, after System: Map, Items, System, Jukebox, round with L and R. The header names it: "Jukebox" with System under L and Map under R, and "Jukebox" as System's R and the map's L neighbour. Plus, Minus and B work as on any page. The menu never opens on it. There is none in the Chamber Dungeon, whose third page is the dungeon's own.
- The header (Navi, `Gm_Navi.bflyt`) has room for three pages, so the Jukebox is a mode of index 2, System's slot: while the module's flag is set, the `Gm_System` page the header builds for index 2 hides its content and shows the Jukebox. The module makes the page changes the header would not (R on System and L on the Jukebox: index 2 to index 2; L on the map lands on the Jukebox) where the game would let the page go (`music_jukebox.cpp`; the header: scripts/re/UI.md, Pause menu).
- The page is built from the game's layouts (which ones: `music_jukebox.cpp`), faded in and out with the page and freed with it; the list, the runtime layouts, the pad and the guide made from the map's are `ap_list.cpp`'s, which the map's check list (Map tracker) uses too:
  - the track list (`Gm_MemoryList`) on the right: `music.TRACKS` in order with the names of `music_tracks.hpp`, the chosen track's row lit and marked with a note. It opens with the cursor on the chosen track, else on the zone's own;
  - "Now playing", a card (`Gm_MemoryCollect`), on the left: the chosen track's name and number in the list; with the Jukebox off, "Jukebox off" and the zone's own track ("Silence" in a zone without music); with the music muted, "Music muted". Notes float up out of it while music plays and is not muted;
  - the name and description of the track under the cursor, at the bottom, where the Items page names its item;
  - under the card, the playback state: Shuffle and Repeat one, on or off, and "In game: ← → change track";
  - the guide "Ⓧ Shuffle Ⓨ Repeat one ZR Mute Ⓐ Play Ⓑ Back": the overworld map's guide (X, Y, R, A, B) with its captions read as Shuffle, Repeat one, Mute and Play, R's caption drawing ZR's button (`ap_text.cpp`).
- Up and Down move the cursor, repeating while held (`ap_list.cpp`'s `kRepeatDelay`, `kRepeatEvery`). The list goes round: Up pressed on the first track goes to the last, Down pressed on the last to the first, the rows scrolled to show the cursor; held, the cursor stops at either end. A chooses the track through `AP::Music::Choose`; on the chosen track (the guide reads "Ⓐ Stop" there) it turns the Jukebox off, the game's own music again. A track that cannot play yet (the Ballad with no instrument) shows its name faded into the row and, under the list, "No instruments yet: each instrument Link finds adds its part."; A on it beeps (`SE_SY_BEEP`). The page runs `AP::Music::Tick` each frame, which does not run otherwise while the menu is open, so the track plays in the menu. The pause menu turns music down; a track chosen on the page plays at full volume until the menu closes. X turns Shuffle on or off, Y Repeat one, ZR mutes or unmutes the music (Music, Mute; the guide reads "Unmute" while muted). The header turns the page on ZR as on R (and on ZL as on L); on the Jukebox it does not see ZR, except while the page opens (`music_jukebox.cpp`).
- **Playback** (`music.cpp`). Repeat one is on at the start: the chosen track loops, as the game loops its music; a track that does not loop starts again once it has ended, while the player is free or the pause menu is open, with no start delay (`kLoopDelayFrames`). With it off, once the chosen track has played through, the next one follows. Next and previous step through one order, round: the list's, or with Shuffle a random order of the list, drawn each time Shuffle turns on, so every track plays once before any plays again and previous retraces next. A track's play-through is its stream's end, with a short loop repeated until a minute has passed (`music_tracks.hpp`), counted while it plays, also under the pause menu, and from the start again whenever the game starts it again. A track that does not loop is followed once it has ended (gone within a second of its length, no other music playing); a track cut off by other music has not ended. The next track follows only while the player is free, as a change fades out an event's song too. The modes last while the game runs.
- **D-pad in the game.** While the player is free, outside the trendy game and the fishing pond, → chooses the next track and ← the previous one in that order, from the chosen track or else the zone's own, and ↑ turns the ghosts' name tags on or off while ghosts are on (Ghosts). The d-pad does nothing else in free play. The track's name shows in a toast ("♪ Tail Cave"), and the name tags' state in the same toast ("Ghost names off"), which takes the place of the one showing or waiting, so skipping through tracks shows the last one.
- `music_tracks.hpp` holds each track's name (at most 24 characters, one list row), description (at most 80 characters, two lines of 40) and play-through length; `test_music` checks it against `music.TRACKS` followed by the Jukebox's own tracks (`JUKEBOX_ONLY`). `scripts/track_lengths.py` writes the lengths from the RomFS (the sound archive `Richard.bfsar` leads from a label to its `.bfstm`, whose stream info has the sample rate, the loop start and the end). Names come from where the game plays each track (zone tables in the levels, event flows, stream names in the sound archive).

**Persistence**
- **Received-item count:** event flags `APRecv0`..`APRecv15`, read as a 16-bit counter. The patcher adds them to `GlobalFlags.gsheet`.
- **Waiting Secret Medicines:** event flags `APMedicine0`..`APMedicine1`, a 2-bit count, also added by the patcher.
- **Collected locations:** a bitset file `sd:/lasap/<seed_hash>.chk`, written on each check, so checks made while disconnected are reported later.
- **Skipped locations:** a bitset file `sd:/lasap/<seed_hash>.skp`, written on each mark or unmark on the map (Map tracker, Skipping a check).
- **Read hints:** event flags `APHint<n>` (In-game hints).
