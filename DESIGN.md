# LAS Archipelago: design

How the pieces fit and the contracts between them. FEASIBILITY.md covers the background; TESTING.md covers the harness.

## Components

| Dir | What | Language / runtime |
|---|---|---|
| `apworld/las/` | Archipelago world (`Links Awakening Switch`) plus PC client | Python, AP's venv (`.venv-ap`, Py 3.12) |
| `patcher/` | Builds the romfs/exefs mod from an AP patch file; derived from LASR (MIT) | Python: pure Python plus `bsdiff4` for patching (`requirements.txt`); oead, quicktex and Pillow only to build the assets (`requirements-assets.txt`) |
| `las-ap-exl/` | exlaunch module (subsdk9) derived from Owen-Splat/exlaunch (GPL-2.0) | C++, Docker `devkitpro/devkita64` |

The module runs LASR's hooks and its code patches (`patches.hpp`), except LASR's `CompareInt` event rewrite (`lasrOnlyFixes`), which only LASR's own keysanity chest flows use.

Flow:
1. AP generates a multiworld. The world writes `AP_<seed>_P<n>_<slot>.aplas` (the patch file).
2. The player opens the patch file with the Launcher, which starts the client with it. The client runs the patcher on the patch file plus the user's romfs dump, and installs its output (see Client install).
3. The game runs with the mod. The module listens on TCP port **43384**, or on the port `config.ini` sets (`[archipelago] port`); the client's `--game-port` must match. Players keep the default; the test sandbox uses its own port so it runs beside a modded game.
4. The client connects to the AP server (websocket) and to the game (TCP), and relays checks and items.

## Assets

The files the mod changes the same way for every seed are assets (`patcher/ap_assets.py`): `StartUp.arc` (LASR's title screen logo and the notice look, `ap_ui.py`), `ItemArchipelago.bfres` (`ap_model.py`), `Game.arc` (the map tracker's icons, `ap_map_icons.py`; installed only with the map tracker), `PlayerGhost.bfres` (the multiplayer ghosts' model, `ap_player_ghost.py`) and the chest textures for "Texture + Size": LASR's (`ObjTreasureBox{Junk,Key,LifeUpgrade}.bfres`) and the seashell chest (`ObjTreasureBoxSeashell.bfres`, the plain chest's albedo recolored blue, `ap_chest.py`). Building them needs native packages (oead's SARC, quicktex, Pillow). `scripts/build_assets.py` builds them from a RomFS dump and stores each in `patcher/assets` as a bsdiff4 patch against the RomFS file it comes from, with both files' SHA-256 in `assets.json`. The patcher applies the patches to the player's dump and checks the results; a dump of another game version fails with a message naming the file. After a change to `ap_ui.py`, `ap_model.py`, `ap_map_icons.py`, `ap_player_ghost.py`, `ap_chest.py` or LASR's title screen or chest textures, rebuild and commit the assets.

Datasheets (`.gsheet`) are read and written by `RandomizerCore/Tools/gsheet.py`, a pure-Python version of oead's gsheet module that LASR's `oead_tools` and `flag_manager` use. It writes what oead writes, byte for byte, and copies values stored into structs and arrays as oead does. `scripts/check_gsheet.py` compares the two on every RomFS datasheet and on any given files.

## Release

`scripts/build_release.py` (in `.venv-lasr`, after `build_exl.sh`) writes `build/release/LASAP-<world version>/`: `las.apworld`, the options template `Links Awakening Switch.yaml` and the setup guide `Setup guide.md` (`docs/setup_en.md`). The template asks for the world's minimum Archipelago version (`archipelago.json`), not that of the checkout that wrote it.
- The world carries the patcher as `las/patcher/`: its Python files, LASR's code and data (and the resources it reads), the assets, the game module, and in `lib/` the pure-Python libraries it needs (evfl, PyLibMS, appdirs, with their licenses). `build.txt` holds a hash of all of it. The world's own build ("Build APWorlds") is the same without it, and with the world's tests (`las/test`), which the release leaves out.
- The patcher runs in Archipelago's Python: pure Python (Assets) plus PyYAML and bsdiff4, which Archipelago ships. LASR imports PySide6 only for its GUI thread and signals; `patcher/lasr_qt.py` stands in for it. `las_ap_patch.py` sets LASR's paths (`randomizer_paths`) to its own folder.

## Client install

- The client's Patch tab (`client_gui.py`) edits the settings in `host.yaml` under `las_options` (`host_settings.py`): `emulator`, `game_file`, `romfs_folder`, `sd_card_folder`, `mod_folder`, `patcher_command`, `game_host`. `checklist.py` turns them into one status line per setting and decides whether everything needed to install is valid.
- **Gameplay options and player settings.** Settings that change how the game plays are options, so a seed plays the same for everyone in it (Archipelago is raced): the option group "Gameplay" (`damage`, `movement_speed` on by default as in LASR, `movement_360`, `skip_song_cutscenes`, `instant_text`, `nice_hookshot`, `disable_guardian_acorn`, `disable_piece_of_power`, `easy_fishing` on by default, `randomize_enemies`, `randomize_enemy_sizes`), which the patch file's `settings` carry under LASR's names. Settings that change only how the game looks or sounds are the player's, chosen at patch time for every seed: the Patch tab's "Look and sound" (also `/setting` in the client), stored in `las_options` (`host_settings.PLAYER_SETTINGS`): Blur Removal, Music, Randomize Text, Randomize Environments, Disable Low Health Beep. The patch file carries their defaults; the client passes the player's values to the patcher as `--settings <JSON object>`, which replace them (`las_ap_patch.PLAYER_SETTINGS`, the same keys and defaults; the patcher rejects any other key). LASR does not implement Item Get Animations or Randomize Sound Effects, so they stay off.
  - The patcher writes the `[movement]` keys the module reads into `config.ini`: `full_360` (LASR writes `full_direction`), and `walk_speed` and `swim_speed`, 1.2 with Movement Speed on and 1.0 off (LASR writes a single `speed`; dashing keeps the module's default). It also empties the `ItemDrop.gsheet` rows `GuardianAcorn` and `PowerPiece` for the two Disable settings, for drops that name those rows, and with Easy Fishing gives Ol' Baron the weight of the other fish in the deep spot (`FishingSpot.gsheet` row `mId` 4: `[0, 15, 0, 0, 15, 0]`, vanilla `[0, 25, 0, 0, 5, 0]`).
  - Instant Text, Disable Low Health Beep and the buffs of the two Disable settings, which LASR lists but never implemented, are the module's: the patcher writes them to `config.ini` (`[tweaks]` `instant_text`, `no_low_health_beep`, `no_guardian_acorn`, `no_piece_of_power`). With Instant Text the module does what B does while a page of text appears (the message window's Reading state): it shows the page whole and skips the text's pauses; waits for input stay. Disable Low Health Beep removes the two calls that play `SE_SY_HP_ALLEART` (`Hooks/Mods/tweaks.hpp`). The buff that replaces an enemy's drop after a run of kills is picked in the game's code, not in `ItemDrop.gsheet`: Disable Guardian Acorn removes the branch to the acorn, Disable Piece of Power makes the Piece of Power's check always take the normal drop.
  - Easy Fishing is not a LASR setting; the patcher writes it to `config.ini` (`[tweaks]` `easy_fishing`). A hooked fish's line tension rises while Link reels against it, and its fight states snap the line once the tension reaches the fish's limit; with Easy Fishing the module stores 0 in place of the new tension, so the line never snaps (`Hooks/Mods/tweaks.hpp`). A fish that swims off the pond's edge still gets away. LASR's Fast Fishing (a world option) only removes the instruments the bigger fish need.
  - Randomize Enemies and Randomize Enemy Sizes are LASR's and its module's (`Hooks/Randomizer/enemies.hpp`, `actorreader.hpp`), from `config.ini` `[randomizer]` `enemies` and `enemy_sizes`. As a room's LEB actors load, an enemy of one of LASR's groups (walking, flying, in trees, in shallow water, in deep water, in side-view water) becomes a random enemy of its group, unless its actor hash is on LASR's list of enemies that must be defeated (`actor_exclusions`); it never becomes a blocking enemy, a Vire on the overworld, or a strong enemy already among the last ten picks. Trap chests let out a random enemy. With sizes, every enemy of a group gets a random scale from 0.5 to 1.5, those that must be defeated too. Neither is seeded: a room's enemies change each time it loads. The logic does not change. The test build counts what the randomizer did (`DBG enemies`).
  - Received Items is not a LASR setting either (`[tweaks]` `received_items`: `itemget` or `popup`; the Patch tab's Item-get, Popup): how the module shows an item from the server (Showing received items).
  - No 30 FPS Drops is not a LASR setting either (`[tweaks]` `no_30fps_drops`: `emulator`, `true` or `false`; the Patch tab's On emulators, Always, Never). The game ends each frame by waiting for the display's next vsync while its vsync watcher runs, so a frame that misses one waits for the next and the game falls from 60 to 30 fps at once (TESTING.md, Frame pacing); with the setting the module starts no watcher and a late frame costs only its own time. On emulators (the default) applies it where the kernel is no Atmosphere: mesosphere answers `svcGetInfo(InfoType_MesosphereMeta)`, Ryujinx and the yuzu-based emulators do not. The module logs which it found.
- `emulators.py` derives the rest from the emulator's executable:
  - Ryujinx: data folder `portable` next to the executable, else the per-user `Ryujinx` folder. SD card `<data>/sdcard`, mods `<SD card>/atmosphere/contents/01006BB00C6F0000`, game folders from `Config.json`.
  - Yuzu and its forks (Eden, Citron, Sudachi, Suyu, Torzu): data folder `user` next to the executable, else the per-user folder named after the emulator. `config/qt-config.ini` gives the SD card (`sdmc_directory`), mods (`load_directory`, plus `01006BB00C6F0000/Archipelago`; their SD card's `atmosphere/contents` loads only RomFS mods), RomFS dumps (`dump_directory`), game folders and recent files.
  - The game is the `.nsp` or `.xci` whose name holds the title id, or whose PFS0 file list holds the base game's ticket.
  - An SD card folder in the settings overrides the emulator's; for Ryujinx, its parent is the data folder, passed as `--root-data-dir` when it is not the default.
- Install (`install.py`): with `patcher_command` empty, the client runs the patcher in its own process, on a worker thread: the release world's `las/patcher`, unpacked once per `build.txt` into Archipelago's cache folder (`las/patcher/<build>`), or the repository's `patcher/` when the world runs from source. It imports `las_ap_patch` fresh for each run and calls `main([<patch>, "--romfs", <dump>, "--out", <temp dir>, "--settings", <player settings>])`, then drops the patcher's modules again, as the patcher keeps state in module globals. The patcher thread's printed lines go to the client's log. With `patcher_command` set, the client runs that command with the same arguments as a subprocess and logs its output. It then replaces `romfs` and `exefs` in the mod folder and copies `config/lasr-exl/config.ini` to the SD card, config last.
- The mod is current when the installed `config.ini`'s `[archipelago] seed_hash` matches the patch, both mod folders exist, and, for the built-in patcher of a release world, `config/lasr-exl/patcher_build.txt` names its `build.txt`, and `config/lasr-exl/player_settings.json` (written on install; the defaults when missing) holds the current player settings; then Play skips patching (`mod_state`). Reinstall mod patches regardless. Other Link's Awakening mod folders the emulator would also load are reported.
- The client never looks at running programs: the player chooses the emulator in the Patch tab the first time.
- Opened with a patch file (double-click, drag onto the Launcher, "Open Patch"), the client shows it in the Patch tab and connects to the patch's `server` as its `player_name`; it neither installs nor starts anything. Play (`/play` without the window) installs the mod when it is not current, then starts the emulator with the game (unless the game is connected or the emulator this client started is still open).
- `file_types.py` registers `.aplas` for the current user (`HKCU\Software\Classes`), opening with the Archipelago Launcher, which hands the file to the client. It runs only from the Patch tab's button.

## Code the module writes

The module patches and hooks the game's code at boot, after an emulator may already have translated it. Ryujinx's translation cache (PPTC, on by default) translates the functions of earlier runs at boot from the unpatched code, and drops a translation on an `IC IVAU` that overlaps it as Ryujinx registers it: from its entry, over its size. A translation that starts after a patched instruction (a switch case reached through `br`) and branches back over it covers the instruction without overlapping its line, so the flush of the written line alone leaves it running the unpatched code. Every code write in the exlaunch lib (`util::InvalidateWrittenCode`, used by the patchers and the hooks) therefore also invalidates the text after it, up to `WrittenCodeReach`. On hardware and on emulators without a translation cache this costs nothing that matters.

## Item model: remote items

- Every randomized location in the patched game gives the **AP placeholder item**, with `index` = the location's **local id** (AP location id − `LOCATION_BASE`).
- The module's `Inventory::AddItemID` hook sees the placeholder item id, reports a check, and adds nothing to the inventory.
- Every real item, including the player's own, arrives from the server and is granted by the module. The client uses `items_handling = 0b011`: starting inventory is granted by the patch (LASR's starting gear), so the server does not send it again.
- The activities the options leave out are optional (`lasr_settings.optional_locations`, `LASWorld.optional`): the trade quest, Dampe, the Rapids Ride (with its owl statue) and fishing when their option is off, and the Seashell Mansion's rewards above `seashell_mansion`. Their locations are shuffled AP locations like any other, but the logic reaches them only after the goal (their rule and the `Victory` event) and they take only the slot's own items, so no seed needs them. `pre_fill` fills them first (`_fill_optional`) with a random choice of the slot's items from the pool (`_optional_items`). A progression item goes there only when the slot reaches every other location it reaches with all its items without it, so nothing else, no other player's item either, waits for an optional location; small keys never do, as the player spends them on any door. Their vanilla items (trade items, the magnifying lens, bottles, the Mansion's level-2 sword, Dampe's heart container) are in the pool like any shuffled location's. The patch's settings keep the options as they are (`Trade Quest` off), which PopTracker reads to hide those checks.
- A location the other options do not randomize (a place on the way: chests, gifts, boss drops, the shop, ...) gives its default item (`lasr_settings.unrandomized_locations`). It is a check only when the logic can need that item (`lasr_settings.default_item_matters`: an item the rules ask for, seashells included, as every Mansion reward is a check). Such a location is an AP location holding its default item, locked (`LASWorld.locked`): it holds the placeholder, reports a check, can be hinted, and the item arrives from the server. Any other (`LASWorld.plain`) is no AP location, the patcher leaves it alone and the logic leaves its item out, so the player never needs it.
- The Trendy Game's prizes and the companions cannot hold the placeholder (LASR does not place items in the crane game; LASR's followers are no item locations). They are never randomized and keep their item in the game (`lasr_settings.kept_locations`); the patch's `placements` give them that item, and the rule above decides which are checks. The companions are the locations `moblin-cave` (Bow-Wow) and `rooster-statue` (the rooster), holding the items Bow-Wow and Flying Rooster, which the rules ask for. The patcher writes `config/lasr-exl/ap_vanilla.txt`: per Trendy Game check the item's key, its index (-1 for none) and the local id; per companion `F`, the flag its joining sets and the local id (`BowWowJoin`; `RoosterFoundFlag`, which the patcher sets after the rooster's `Join` in `RoosterBones.bfevfl`). The module's `Inventory::AddItemID` hook reports a Trendy Game check when the game adds that item with that index (any index for -1), except while the module grants a received item; the module reports a companion once its flag is set. The server then sends the item back; the module does not grant it again when the location was collected here. Their heart pieces and seashells count as vanilla sources in `ap_indices.txt`.
- The shop slots LASR does not shuffle (`lasr_settings.fixed_locations`) keep their vanilla content and are AP event locations (no id) with the vanilla item locked, if it is progression.
- Each location shows a model for the item it holds. The world picks it (`models.py`):
  - LAS items show their own model.
  - Other games' items are matched by name against `data/item_models.yml` (e.g. any shield shows the shield).
  - Traps and unmatched names show the Archipelago model.
- The patch file's `location_models` carries these picks.
  - The patcher gives each such location a variant of the placeholder, `ArchipelagoItem_<item key>`. It shows the item's model on the ground and in shops.
  - Each variant gets an `Items.gsheet` row with its own item ID, because the item-get picks its model by ID. IDs come from 72–99, 103, 107, 109, 118, 119, 132–199 and 203–255, which neither the game nor LASR uses. That is more IDs than LASR has models; should they run out, the most used models keep theirs and the rest fall back to the placeholder's ID 71.
  - Item IDs are a byte. The item-get finds the row by searching `Items.gsheet` for the ID, and handles every one of these IDs the same way (the default case of its switch on the ID).
  - The module counts all these IDs as the placeholder (`AP::IsPlaceholderItem`).
  - A room with a chest whose item key has 32 characters or more crashes the game as it loads (`std::length_error`). Variant keys longer than 31 characters are cut short and end in a hash of the item key (`variant_key`).
- The Archipelago model is six balls in the logo's colors. The patcher builds it from the player's Seashell Sensor model (`patcher/ap_model.py`) and writes it as `ItemArchipelago.bfres`, with its own Npc entry, `ItemArchipelago`.
- Indexed items (heart pieces, seashells, golden leaves, heart containers, bottles) are counted by inventory bits: collecting one sets the bit of its source (its vanilla index, `index` in `logic.yml`), and the count is the number of bits set. A bottle's bit is its slot (`Bottle0`..`Bottle2`); one added with index -1 sets no bit and the player has no bottle. The patcher writes `config/lasr-exl/ap_indices.txt`: per source its kind (`S`, `H`, `L`, `C`, `B`), its bit and the local id of its location when shuffled, else -1. A received item takes the lowest bit that is free and that no vanilla source of the seed sets, so a vanilla source collected later still counts. Received heart pieces stay below index 32 and seashells below 50, the game's totals.
- The Memories map marks heart piece and seashell bit i at the vanilla place of source i (rows of `UiMemoryHearts.gsheet` and `UiMemoryShells.gsheet`). Received items hold the bits of shuffled sources, so the module (`ap_memory.cpp`) marks source i once it is done instead: a vanilla source by its bit, a shuffled one by its location's check.
- Item actors show by their flag or actor switch alone, as in LASR: LASR's code patch in `randoFixes` stops the game's inventory check (`ItemActor_CanAppear`, TESTING.md), which hides an item actor while the player has its item, by index for heart pieces, seashells and golden leaves and by the item alone for the others. LASR gives every heart piece and seashell actor a flag, shuffled or not; its dig items are `ItemSlimeKey` actors, which the check hid once the Slime Key was owned. Received heart pieces and seashells therefore never hide an actor.

## IDs

- `ITEM_BASE = 0x4C410000` and `LOCATION_BASE = 0x4C420000`. The AP id is the base plus a stable offset.
- **Stable offsets.** They live in `apworld/las/data/ids.json` (`{"items": {lasr_name: offset}, "locations": {lasr_location: offset}}`).
  - The file is generated once from LASR's data in file order and committed.
  - New names are appended; existing offsets never change.
- **Local id.** A location's local id is its offset, which is the `index` stored in-game. It must stay below 65536.

## Names

- **AP display names** are human-readable, e.g. `Progressive Sword`, `Small Key (Tail Cave)`, `Tail Cave - Feather Chest`.
- **Location names** (`apworld/las/data/location_names.json`) are `<region or dungeon> - <label>`, the label as the PopTracker pack names the check, so hints, the spoiler, the in-game map and the tracker agree: a dungeon check's room on the pack's dungeon map, an overworld check's section, or `<pin> (<section>)` where the section alone says little (`Mamasha (Trade Yoshi Doll)`). `scripts/poptracker_map.py` finds dungeon checks in the pack by that label.
- **LASR names** (`sword`, `key-D1`, `D1-west-hallway`) are used in the patch file and in `ids.json`.
- The world keeps the mapping between the two.

## Save name

- A new file's name entry shows `UI:NameEntry_Default` ("Link" in the base game) until the player renames it, and OK keeps it. The patcher writes the patch's `slot_name` there in every language's `UI.msbt` (`ap_save_name.py`), so a new save is named after the slot; the player can still rename it on that screen. Files made before the mod keep their names.
- The game takes up to 8 characters: its keyboard's limit, and OK cuts a longer name. From the slot name the patcher keeps printable ASCII except `@`, `%` and `\` (the keyboard refuses them) and `[`, `]` (they start a message tag), and the Latin-1 letters (`À`–`ÿ` without `×` and `÷`), which the game's fonts have for its European languages. Runs of spaces become one space, and the result is cut to 8 characters with no space at either end. When nothing is left (a slot name in another script, symbols or spaces only), the name is "Link". For example `Archipelago Player 7` gives `Archipel` and `Zoë[AP]_Archipelago` gives `ZoëAP_Ar`.

## Patch file (`.aplas`)

An Archipelago player container (`container.py`, `APPlayerContainer`): a zip with `archipelago.json` (game, player, player name, server; WebHost fills in the room's server) and `patch.json`. The patcher also accepts a bare `patch.json`. `patch.json` is UTF-8 JSON:

```json
{
  "format": 1,
  "seed_name": "<AP seed name>",
  "player": 1,
  "slot_name": "Link",
  "seed_hash": "<8 hex chars; also in slot_data; the game reports it in HELLO>",
  "settings": { "<LASR setting key>": "<value>" },
  "starting_items": ["<lasr item name>"],
  "placements": { "<lasr location name>": "<lasr item name> | \"ap-item\"" },
  "location_ids": { "<lasr location name>": "<local id (int)>" },
  "optional_locations": ["<lasr location name>"],
  "location_names": { "<lasr location name>": ["<AP item name>", "<owner's name, empty for this slot>"] },
  "location_models": { "<lasr location name>": "<lasr item name whose model it shows>" },
  "location_chests": { "<lasr location name>": ["<LASR item type: chest size>", "<chest texture or null>"] },
  "dungeon_entrances": { "<dungeon>": "<dungeon>" },
  "hints": { "<hint source>": { "kind": "<hint kind>", "text": "<hint text>", "player": "<slot of the location (int)>", "location": "<AP location id (int)>" } },
  "ghost_secret": "<32 hex chars, the same in every LAS slot's patch of the multiworld>"
}
```

- `settings` uses LASR's `SettingsManager.fetch()["Settings"]` keys (`lasr_settings.lasr_settings`), as the options set them; the player settings hold their defaults (Client install). "Bad Pets" is always off: it is not supported.
- `starting_items` are granted when Link first wakes up. LASR adds them with index -1, which sets no inventory bit; the patcher gives starting heart containers, heart pieces, seashells, golden leaves and bottles the bits a received one would take (`starting_bits`, Indexed items).
- `placements` covers every LASR item location: AP locations are `"ap-item"`, the kept and fixed ones carry their vanilla item. Owl statues that give no gift are left out, as in LASR.
- `optional_locations` lists the AP locations of the activities the options leave out (`LASWorld.optional`). The map tracker leaves them off the map. It is optional: older patches show them.
- `location_names` covers the AP locations. The patcher uses it for the shop's price tags; in-game text gets the same names at runtime from the client.
- `location_models` leaves out locations that show the Archipelago model. It is optional: older patches show the Archipelago model everywhere.
- `location_chests` gives each AP location's chest the size and texture of LASR's "Chest Types" setting (option `chest_appearance`): for this slot's items, the LASR item's type and `chest-type` with the adjustments LASR's shuffler makes, and `seashell` (the blue seashell chest) for seashells; for other players' items, `important` for progression, `good` for useful, and `junk` with the junk texture for filler and traps (`lasr_settings.chest_look`). It is optional. The patcher gives LASR's seashell the `seashell` chest-type too, so chests that keep a vanilla seashell are blue as well.
- `dungeon_entrances` maps each dungeon's door to the dungeon it leads into (Shuffled dungeons): an identity map with the option off.
- `slot_name` is also a new save's name (Save name).
- `ghost_secret` groups the multiworld's LAS players on the ghost relay (Ghosts). It is optional: without it the client shows no ghosts.
- `hints` gives each in-game hint source its kind and text (In-game hints). `player` and `location` name the hinted location when reading the hint makes a server hint. It is optional and empty with the option off.

## slot_data

`{"seed_hash": str, "goal": str, "instruments_required": int, "instruments_known": bool, "death_link": bool, "location_count": int, "settings": {...}, "logic": {...}, "options": {...}, "starting_instruments": [...], "dungeon_entrances": {...}}`

`goal` is always `wind_fish`: the Nightmare beaten after the egg opened with `instruments_required` instruments (Goal). `instruments_known` is false for a count left to chance, which trackers keep hidden until the player has read the sign (Goal, **Hidden count**); slot data without it counts as known.

`settings` holds the seed's LASR settings that decide which checks exist and what reaches them (`TRACKER_SETTINGS` in `lasr_settings.py`), under LASR's names and values (`"Preset": "Basic"`, `"Owl Gifts": "None"`, `"Seashell Mansion": 15`, ...), as the options set them. Trackers such as PopTracker packs read them on connect.

`logic` is what the client needs to evaluate the world's rules for the map tracker (`tracker.py`): `preset` (the logic option), `tokens` (the settings tokens the rules test), `vanilla` (fixed locations that keep a progression item, whose items count as found once they are reachable), `locked` (AP locations holding their own progression item; the map counts their items once received, like any other), `optional` (`LASWorld.optional`, in logic only once the goal is) and `starting` (the slot's starting items: the patch grants them, so the server does not send them).

`dungeon_entrances` is the patch's (Shuffled dungeons). The map tracker's rules (`LogicTracker`) follow it.

`options` (the world's own option values, `SLOT_DATA_OPTIONS`), `starting_instruments` (the LASR instruments the slot starts with) and `dungeon_entrances` let Universal Tracker regenerate the slot without a YAML: the world sets `ut_can_gen_without_yaml`, `interpret_slot_data` returns the slot data, and `generate_early` takes the options, starting instruments and dungeon entrances from `multiworld.re_gen_passthrough` instead of the YAML and the seed's random. Universal Tracker asks the server for the starting inventory (items_handling `0b111`), which the LAS client leaves out. `test_universal_tracker.py` checks that the regenerated slot has the same regions, locations, locked items and reachability. Universal Tracker sweeps only event locations, so it counts a locked location's item once the server sends it (after the check); the LAS client counts it once the location is reachable.

## Data storage

The client keeps the level the game shows (`Field`, `Lv01TailCave`, ...) in `las_level_<team>_<slot>`, from the game's `LOG level` lines. Trackers watch it to show the current dungeon's map.

The client sets `las_sign_<team>_<slot>` to `true` once the game reports the sign at the egg's stairs as read (`SIGN`, for the slot's seed); trackers show a hidden instrument count from then on (Goal, **Hidden count**).

## Game ↔ client protocol (TCP 43384, game listens)

ASCII lines terminated by `\n`, fields separated by single spaces. The game accepts one client at a time. The client sends `PING` every 2 s, and the game drops a client that has been silent for 10 s.

- The game listens and the client connects, so a Switch needs no address of the PC. The network thread waits for a client with `Poll` in 100 ms steps rather than a blocking `Accept`, which would keep emulators from closing the game.
- The client drops a connection that gets no `HELLO` within 5 s: the game serves another client (a second client window), which the Patch tab then says, and Play starts no emulator. The Patch tab shows the game and server connections.
- Opened with a patch file, or given one in the Patch tab, the client logs in as the patch's slot.

**Client → game**

| Line | Meaning |
|---|---|
| `PING` | Keep-alive; the game answers `PONG` |
| `ITEM <n> <item-key> <count> <dungeon> <location> <item name>\|<sender>` | The n-th received item (1-based AP index). `item-key` is the game's item symbol (`SwordLv1`, `SmallKey`, …). `dungeon` is the dungeon level for dungeon items, else `-1`. `location` is the local id the item came from when it is this slot's own, else `-1`. `sender` is empty for own items and items from the server. The game applies it only if `n` = stored count + 1, then answers `RECV <count>` |
| `NAME <local id> <item name>\|<owner>` | What a location holds, from `LocationScouts`; `owner` is empty for this slot's items. Sent for every location on connect |
| `NOTICE <text>` | A toast (see In-game text); `\|` starts a new line. The client sends "Archipelago connected as <slot>" (or a wrong-seed warning) once the game and the slot are both connected, and "Archipelago server disconnected" when the server goes away |
| `SERVER 1` / `SERVER 0` | Whether the client is logged into the slot of the game's seed: sent when the game connects, when the slot connects and when the server goes away |
| `SYNC` | Asks the game to send `RECV <count>` and `CHECKS ...`, and `GOAL`, `SIGN` and the read hints when they apply |
| `CHECKED <id> <id> ...` | Locations the server has as checked, for the map tracker: all on connect (possibly several lines), then new ones from `RoomUpdate`. Kept in memory only |
| `INLOGIC CLEAR` / `INLOGIC <id> <id> ...` | Locations in logic for the items received, for the map tracker: `CLEAR`, then all of them (possibly several lines), each time the set changes. Kept in memory only |
| `DEATH [<player>]` | DeathLink: another player died; a toast names them (see DeathLink) |
| `GHOSTNAMES 1` / `GHOSTNAMES 0` | Whether name tags show over the ghosts (Ghosts); sent on each game connection and when the setting changes |
| `GHOSTS 1` / `GHOSTS 0` | Whether the client relays positions (joined to the ghost relay); with 0 the game sends no `POS` and shows no ghost (Ghosts) |
| `GHOST <n> <level> <x> <y> <z> <yaw> <anim> <anim frame> <upper anim> <flags> <time> <shapes> <tunic> <eye> <mouth> <ear> <slot name>` / `GHOST <n> off` | Another player in this area, in ghost slot n (0–29), with the time its game took the position (ms, 16 bits), or nobody there any more (Ghosts) |
| `MUSIC <track>` / `MUSIC off` | The jukebox's track (a BGM name, `BGM_FAIRY`) plays instead of the zone's music, or the game's own music again (Music); sent when `/music` changes it, and on a game connection whose `MUSIC` report has no track while the client has one. The game answers an unknown track with `LOG music: unknown track <track>` |
| `MSG <text>` | Logged by the module |
| `DBG <cmd> [args]` | Test-only debug commands (see the module source) |

**Game → client**

| Line | Meaning |
|---|---|
| `HELLO <proto=2> <seed_hash>` | Sent on connect |
| `PONG` | Answer to `PING` |
| `RECV <count>` | Number of items applied, stored in the save as a flag-bit counter |
| `CHECK <local_id>` | A location was collected |
| `CHECKS <id> <id> ...` | Every collected location, sent on connect and on `SYNC` (possibly several lines) |
| `HINT <slot> <location id>` | An in-game hint was read (its flag is set): once per hint and connection, and all read hints again on `SYNC` |
| `GOAL` | Goal completed: Link entered the `Ending` level, or the `ShadowClear` flag is set (also resent on `SYNC`) |
| `SIGN` | The player read the sign at the egg's stairs (Goal, **Hidden count**): once when it is read, and again on each `SYNC` after |
| `DIED` | DeathLink: Link died, and no Secret Medicine saved him (see DeathLink) |
| `DEATHDROPPED` | DeathLink: a `DEATH` arrived with no save loaded and was dropped; the client logs it |
| `GHOSTNAMES 1` / `GHOSTNAMES 0` | The player turned the ghosts' name tags on or off in the game (d-pad up); the client keeps it as its `ghost_names` setting and sends it back |
| `LOG <text>` | Debug text; `LOG level <name>` on every level change and when a client connects |
| `MUSIC <track>` / `MUSIC off` | The jukebox's track in the game, or none (Music): on each connection, and when the player chooses in the game (the Jukebox page). The client takes it as its choice and sends nothing back, except to a report of none on connecting while it has a track |
| `POS <level> <x> <y> <z> <yaw> <anim> <anim frame> <upper anim> <flags> <time> <shapes> <tunic> <eye> <mouth> <ear>` / `POS none` | Link's position while the client asks for it (`GHOSTS 1`), with the time it was taken (ms), or no player (title, file menu, level load, leaving a level by its exit) (Ghosts) |

Lines that need a loaded save (`ITEM`, `SYNC`, `DEATH`, most `DBG`) wait until the player has been in the current level for 1.5 s; other lines are handled immediately. The 1.5 s start again whenever the level reloads (no player), and from the game over menu on they wait until its Retry has reloaded the level, as do item displays: Retry stands Link up with full health for about a second before the reload, under the same level name.

**Items with special handling in the module**
- Progressive sword, shield and bracelet arrive as their Lv1 key; the module upgrades when LASR's `*FoundFlag` is set.
- Seashells, heart pieces, heart containers, golden leaves and bottles take the lowest in-game index that is unused and that no vanilla source sets (Indexed items, above).
- Traps (`*Trap`, `$ENEMY`) wait like item displays (below). Unknown keys are logged and counted as applied.

**In-game text**
- A found placeholder says what it is: "You found <item> for <player>!", or "You found your <item>!" for this slot's own items. The patcher writes the names to `config/lasr-exl/ap_names.txt` (`NAME` lines without the command), which the module reads at boot, so this works before the client connects; `NAME` lines replace them. A location without a name says "You found an Archipelago item!".
- **Toasts.** Notices that are not items, and received items with Received Items set to Popup, show in the autosave popup (the "Now saving." text with a spinning icon at the bottom right), which does not stop the game:
  - The module shows `NOTICE` lines from the client and "Archipelago client disconnected" when the client goes away. While the client or the server (`SERVER`) is not connected, it shows "Archipelago client not connected" or "Archipelago server not connected" once the player has been 20 s in a level, then every 5 minutes; after a disconnect notice, the first reminder comes 5 minutes later.
  - It calls the game's show function for the popup (autosave mode) and hooks the popup's state changes: when its auto state starts, the module sets the popup's display time and puts the toast into its text pane (the message `UI:SystemSaving`, which the text hook hands out). When the popup is hidden again, the pane gets the game's own text back. A toast waits while the popup is busy, as during a real save; a save during a toast shows the toast's text.
  - The patcher widens the popup's text pane and its text buffer, and replaces the egg icon with the Archipelago logo, white on transparent like the egg (`ap_ui.py`, `StartUp.arc`). The loading screen's spinner shares that texture.
- A received item from another player says "You got <item> from <player>!". Own items found here are not shown again; other own items and server items show the item's native text, except items whose native text names their vanilla source (the Boomerang, the capacity upgrades), which say "You got <item>!".
- In these texts an item name longer than 32 bytes and a player name longer than 16 end in "..." (UTF-8 kept whole). A shop's price tag (the buy dialog's first line) holds 46 characters: a longer item name ends in "…" and the owner stays.
- The patcher adds the messages `Place:ArchipelagoItem` and `System:APReceived` (with the native item-text window style) and the Item event entry point `APReceived`. The module hooks the game's MSBT label lookup and text getter and hands out the text for these two messages (`ap_text.cpp`).
- The module learns the location from the placeholder's `AddItemID`, so placeholder flows add the item before playing the item-get (LASR's item-get chains and a TreasureBox branch); other items keep LASR's order. That location names the found text until the player is free again.
- The Seashell Mansion's presents add their item after the item-get. The module reads the location from `ShellMansionMaster.PopBox` when the present appears.

**Showing received items**
- The module grants an item the moment its `ITEM` line is handled, and queues a display of it.
- A display is the game's own item-get (Link holds the item up, the item's text shows), played as an event (Received Items set to Item-get, the default; Popup below): the patcher adds the `Common.bfevfl` entry `APItemGet`, Link's item-get of the placeholder with the message entry `APReceived`. The module starts that entry the way the game starts its game over, and hooks the item-get code behind `Link.GenericItemGetSequenceByKey` to show the received item and its text instead. The swap is pending from the request until that item-get starts, apart from the event's state: the event takes the player before its item-get runs. As an event, the game locks Link's controls and returns the camera when it ends; an item-get outside an event leaves the camera zoomed in.
- A display starts once the player has been free for 0.6 s (no talk, event, cutscene, pause menu or level load), 0.2 s when the last display just ended, and holds nothing over his head: an item-get takes a held object out of the game, such as a shop item. Displays run one at a time. In the trendy game (`CraneGame`) they wait until Link leaves: Link counts as free while the player steers the crane, which a display would cut off.
- LASR's songs and tunics show NPC models: Marin, Manbo and Mamu, and the Color Dungeon's guards (the patcher gives the tunics' `Items.gsheet` rows the guards' npcKey, which LASR leaves empty, so the item-get showed no model and no shine). The item-get's model component is a node under the item's node (2 units above Link, tilted back towards the camera, where the shine shows), posed by the game per kind of item (the tunics tilted forward, the songs rolled like the ocarina); item models are small and centred on their origin, NPC models stand on their feet. The module fixes these five in every item-get (`g_HeldModelFixes` in `ap_game.cpp`): it finds them by model name in the item-get's model task and replaces the game's pose of the model component's node (hooking the node mark-dirty, so the game's own update carries it to the model; the item's node and the shine stay as they are) with the ocarina's place, an angle per model (picked by eye: tilted and rolled a little, like the ocarina; Manbo turned to show his side), and the scale that gives the model the ocarina's size: the same radius around its centre. It moves the model's root bone so that its centre sits on the component's origin. Radius and centre are measured from the models' bind-pose vertices (`scripts/model_bounds.py`).
- **Shorter item-get.** Every item-get, the player's own finds included, is shorter (TESTING.md, Item-get timing). The game builds it as steps (`ItemGet_BuildSteps`): Link raises the item (animation `item_get_st`), a delay of 1 s, the item's text; then a delay of 0.083 s and Link lowers the item (`item_get_ed`). The item's fanfare (the sound of its `Items.gsheet` row: a BGM jingle or an SE) starts with the item-get, and the text's step ends only once the text has closed and the fanfare has stopped. The module patches the text's delay to 0.25 s and makes the fanfare's wait done at once (`ItemGet_FanfareDone`): the fanfare plays on, and Link lowers the item as the text closes.
- **Popup** (Received Items set to Popup). A received item shows as a popup instead of an item-get, and play goes on: its 3D model above Link's head for 2.8 s (growing in, turning from side to side towards the camera, shrinking away), and the toast "You got <item>" / "from <sender>" (names clipped as in the received text; a `DBG grant` without a name shows the item's key). It starts once the player has been free for 0.2 s and holds nothing, also in the trendy game, and the next one waits until both the model and the toast are gone. Traps still play their effect as an event. The model is made as the NPCs that hold an item make theirs (`ap_popup.cpp`): the game's item model maker (`ItemModel_Make`: owner, name, root node, item id) loads the item's model file and makes a skeletal model component of the owner, under the root node, in the item-get's model task; the module passes Link and his model component (under his root component, PlayerCollision, the model is not drawn). The component comes disabled, as the item-get enables its model only once the item pops up; the module enables it, poses its node each frame in Link's frame with his turn and scale taken out, and destroys it at the end (`Entity_Destroy`; removing it as a child of Link, the way the module removes actors, crashes, as that treats the child as an actor). A level load takes it with Link. The NPC models of the songs and tunics get the item-get's size and centre (`g_HeldModelFixes`).
- With three or more displays waiting, filler (rupees, ammo, drops) is granted without a display. The queue is not saved; a restart drops pending displays, not items.
- A trap plays LASR's effect of that trap instead of an item-get, as the `Common.bfevfl` event `AP<trap key>` the patcher builds with LASR's trap flow (animation, damage, autosave), and the autosave popup names the trap and its sender. The damage follows the damage mode; in the normal mode a trap leaves at least a quarter heart (the module raises health first if needed). The Zol Trap has no such flow (in a chest it spawns enemies) and costs one heart.

**DeathLink** (option `death_link`; `patcher/ap_deathlink.py`)
- The client takes the `DeathLink` tag when the slot data's `death_link` is on: it turns a `DIED` into a DeathLink ("<slot> fell on Koholint.") and a received DeathLink into `DEATH <source player>`. With the option off the client has no tag: the server sends it no deaths, and `DIED` is ignored.
- The patcher changes `Common.bfevfl`'s `GameOver`, which plays Link's death animation and then revives him with Tracy's Secret Medicine (`Inventory.HasItem` itemType 22, used up) unless the shopkeeper takes revenge for a theft. A bottled fairy never revives Link in this game. After the animation the flow checks the flag `APDeathLink`: set, it clears it and goes to the game over without the medicine. A death that then stands (the shopkeeper's, or no medicine) sets `APDied` before the game over; the module polls that flag, clears it and sends `DIED`. So the medicine's rescue sends nothing, and a received death is never sent back.
- `DEATH` is dropped (`DEATHDROPPED`) on the intro, the title and the file menus, and when Link is dead already. Otherwise it waits until Link is free (no event, message or pause menu) and no item display is starting or showing, then the module sets `APDeathLink` and his health to zero and queues the toast "DeathLink / from <player>". A received death kills Link even with the Secret Medicine, which he keeps. While Link's health is zero no item display or warp menu starts. `APDeathLink` set by a death that reached no game over within 10 s, while Link lives, is cleared.

**Ammo ghost** (option `ammo_ghost`, settings key `Ammo Ghost`; `patcher/ap_ghost.py`)

**Goal** (option `instruments_required`, settings key `Instruments Required`; `patcher/ap_goal.py`)
- The goal is the Nightmare beaten, reported as `GOAL` when Link enters the `Ending` level: the Wind Fish and the owl in the clouds (room `Ending_12O`), where the stairs after the fight lead. The Wind Fish's event sets `ShadowClear` only at its end, when the credits start; the module reports that too. The Wind Fish's egg opens with `instruments_required` of the eight instruments (0–8, default 8); starting instruments count. All eight stay progression items.
- **Logic.** LASR's `egg` region asks for all eight. With fewer, `lasr.goal_logic` replaces them by the count token `instruments:N`, which `LogicCompiler` resolves through `lasr.COUNTED`: it holds with N different instruments (`instruments:0` always holds).
- **Patch.** The egg's song (`WindFishsEgg.bfevfl`, entry `orchestra`) asks `Inventory.HasAllInstruments` at four switches: the instruments' playing, the song's length, the fade, and whether the egg opens (`oepn`). Below eight, the patcher turns each into a chain of `Inventory.HasItem` checks, one per instrument (itemType 45–52, Full Moon Cello to Thunder Drum), that reaches the switch's case 1 once enough are held and its case 0 once they can no longer be. With eight, or without the settings key, the file stays as it is.
- **Sign.** The sign at the foot of the egg's stairs (`Place:SBMountTamaranch`, used by no other event) gets two lines under its place name, "The Wind Fish's Egg opens / with N instruments.", in every language's text (in English). That makes a random value (Archipelago's `random`, `random-range-<min>-<max>`, ...) readable in the game.
- **Hidden count.** A count left to chance stays hidden in the trackers until the player reads that sign; a number the player picked shows at once. `InstrumentsRequired.from_any` sets `known` unless the value is a `random...` text. Generate weights a YAML dict or list before `from_any` sees it, so a number picked by weight from several shows at once; `supports_weighting` stays on, as the Options Creator offers its Random toggle only for weighted options. The slot data carries it as `instruments_known`.
  - The module notices the sign when the game fetches its text (the text getter on the message looked up as `SIGN_LABEL`), sets the save's event flag `APSignRead` (`SIGN_FLAG`, which the patcher adds to the global flags, `ap_goal.SIGN_FLAG`) and sends `SIGN`; it sends `SIGN` again on each `SYNC` while the flag is set. The flag lasts as long as the save file: a read the player quits without saving is gone from the save, and a new game reads the sign again.
  - The client sets the data storage key `las_sign_<team>_<slot>` (`tracker.SIGN_KEY`) on `SIGN` from the game of the slot's seed, and asks for it on connecting (`Get`): a `true` there counts as read, as the save may have lost it. Until then, with `instruments_known` false, its map tracker's rules take all eight instruments (`tracker.tracked_instruments`).
  - Universal Tracker regenerates the slot with all eight while the count is hidden. It watches `LASWorld.found_entrances_datastorage_key` (the sign key, a hook UT has for deferred entrances) and calls `reconnect_found_entrances` with its value; once it is true, the world compiles the rules with the real count and sets them again.
  - The PopTracker pack shows "?" for Instruments Required (count 0 with the overlay `?`, as a consumable's nonzero count replaces the overlay) and its logic takes eight (`INSTRUMENTS_HIDDEN`) until the sign key is true.

**Shuffled dungeons** (option `shuffled_dungeons`, settings key `Shuffled Dungeons`; `lasr.dungeon_logic`, `patcher/ap_entrances.py`)
- Each of the nine dungeons' overworld doors leads into a random dungeon, the Color Dungeon included, as in LASR's shuffler (`lasr.shuffle_dungeons`). `dungeon_entrances` names each door by its dungeon's LASR region (`tail-cave`, ...) and maps it to the dungeon it leads into.
- **Logic.** A dungeon's region node is its inside, and its conditions are its door's. `lasr.dungeon_logic` gives each dungeon the conditions of the door that leads into it, those of every preset. The Face Shrine's region is either of its entrance rooms (`D6-8D`, or `D6-3A`, which its side entrance reaches); its door is the outside part of `D6-8D`'s conditions (`river & face-key & (hookshot | rooster)` and the room's glitched and hell conditions), which the door leading into the Face Shrine replaces. LASR's shuffler moves only `condition-basic`, and moves the Face Shrine's region with its entrance rooms.
- **Patch.** LASR's `EntranceRandomizer` points each door's loading zone into its dungeon and that dungeon's exit back out of the door, and swaps the overworld map's dungeon markers (label and show flag; the map tracker's dungeon dots follow the markers and hide their dungeon's name until it is entered). `InstrumentRandomizer` sends each instrument's warp out of the door that leads into its dungeon, and `FreeGiftsRandomizer` sends the Fairy Queen's warp after her gifts (`FairyQueen.bfevfl` `Event37`) to the Color Dungeon's. `ap_entrances.py` does the same for the Fairy Queen's other warps (`Event22`, `Event26`, `Event42`) and for her room's loading zone (`Lv10ClothesDungeon_04C`, which lies off the floor). The side entrances of the Face Shrine (`Field_07M`) and Turtle Rock (`Field_01A`, `Field_01C`) are not shuffled.

**Map tracker** (option `map_tracker`, settings key `Map Tracker`; `patcher/ap_map.py`, `ap_map.cpp`)
- The pause map shows the slot's unchecked locations, and the whole overworld and every dungeon room are revealed. Off for a patch without the settings key.
- **Positions.** `patcher/map_positions.json`, written by `scripts/map_positions.py`, gives each location a place: overworld locations world coordinates (x, z), dungeon locations a room and level coordinates. Sources, in order: the location's item actor in an overworld room (LASR's `*_ROOMS` tables); for a location inside a building or cave (a room table, or `DOOR_LEVELS` for NPCs, shops and games), the overworld door into it (`AreaLevelOpen`), or the hole that drops into it (`AreaHole`, as into Mabe's well); for an NPC or statue outside (`ACTOR_PREFIXES`), its actor; otherwise the pin of the LASR PopTracker pack (Br00ty/lasr_brooty), converted by an affine fit through the locations with an actor. Where there are several doors or actors, the one nearest the pack's pin counts. Dungeon locations use the item actor or owl statue in their room, else the room's upper left. Overworld positions carry the height (y) of their actor or door, or of the overworld actor nearest to them (not counting each room's static mesh, `MapStatic`, at height 0): the map draws higher places further north, as the game's own icon rows do with their `mPosY`. Each entry also has the AP location name, and each overworld location the name of its spot: its place in the PopTracker pack (the parent of its section), or `SPOT_NAMES`, which gives the checks of different places that share an icon one name.
- **Overworld icons.** The patcher groups the slot's overworld locations that lie within 3 units of each other and adds four `UiFieldMapIcons.gsheet` rows per group, one per look, each with `APMap<mark><group>` as its show flag and its name label: in logic (no mark), partly in logic (`P`), out of logic (`X`) and collected (`C`). Each dungeon also gets a group with all of its checks, 2.5 units east of the game's marker of its entrance (`DUNGEON_MARKERS`). Only the slot's shuffled locations (the patch's `location_ids`) get icons, so options that leave checks vanilla leave them off the map; the optional locations (the patch's `optional_locations`) are left off too, as PopTracker hides them. The map builds its icons each time it opens and shows a row while `EventFlags::CheckFlag` of its show flag is true. The module's `CheckFlag` hook answers these flags: the group's look is set. A location counts as checked in the checks file or by `CHECKED`, and in logic by `INLOGIC`; before the client sends `INLOGIC`, every location counts as in logic. Hovering an icon shows `Place:APMap<mark><group>`; the patcher adds those entries, and the module's text hook replaces them with the group's name (`ap_map.group_name`) after `<to do>/<unchecked> ` when the group has several locations and some are unchecked: to do are its locations in logic that are neither checked nor skipped, unchecked those not checked (skipped ones included). A group is named by its dungeon (`D1 Tail Cave`), by its location's name without its region when it has one, or else by its first location's spot; such a name fits the hover box's line after the count (`NAME_WIDTH`). With shuffled dungeons a dungeon's group shows `Unknown dungeon` (`HIDDEN_DUNGEON`) without a count, and out of logic unless collected, until the dungeon's marker flag (`UI_FieldMapIcon_Lv<nn>Dungeon`) is set, which the game sets the first time it shows the dungeon's name on entering it (`LocationName.gsheet`); the group sits at the door leading into the dungeon, so its name, its count of locations or its look would tell where that door leads.
- **Icons.** `ap_map_icons.py` adds the looks to `Game.arc`: dots (green, green and red split diagonally, red, grey with a tick). The map's marker (`Gm_MapMarker`) shows the frame of its `SetMark` animation given by the row's `mType`; that animation's texture pattern (FLTP) picks a marker texture per frame, and its pane animation (FLPA, size targets 8 and 9) the marker's size. It adds a texture per look to `timg/__Combined.bntx` and eight frames after the game's seven: per look one at the size of a group, then one at the smaller size of a single check (`frame()`). New texture names need the BNTX name dictionary (a Patricia trie, `_DIC`) rebuilt: `build_dictionary()` builds it as the game's files are built, which the asset build checks on the original dictionary first.
- **Logic.** The client evaluates the world's rules (`LogicCompiler`, `logic.py`) for the items received with `tracker.LogicTracker`, from the slot data's `logic`: a state holding item counts and region stand-ins, with regions and the progression items of vanilla locations added until nothing changes, as Archipelago's sweep does. A location is in logic only for the items the player has: a locked location's item (a trade item, a companion) counts once received, not while the location is reachable, as the player may not know where it is (Mamasha needs the Yoshi Doll in hand). An optional location is in logic only once the goal is (the egg with `instruments_required` instruments, then the Nightmare). `test_tracker.py` checks it against Archipelago's reachability with a sweep that leaves out the locked locations.
- **Overworld reveal.** The map shows an area once its flag `UI_FieldMapTraverse_<area>` is set, and plays the reveal once `UI_FieldMapOpen_<area>` is not; the `CheckFlag` hook answers both as set. `LocationName.gsheet` gates the area name banners on the same flags.
- **Dungeons.** The dungeon map draws the rooms whose bit (column + 8·row) is set in the dungeon's visited-room mask and, with the compass, the chests, open or closed by their opened flag. While Link is in a dungeon the module fills the mask (`DungeonItems[dungeon] + 8`), so every room counts as visited in the save. An inline hook on the map's read of the dungeon's flags byte (bit 0 compass, bit 1 map) sets both for the map screen only; the sidebar still shows the items Link has.
- **Out-of-logic toggle.** The map's X button, which opens the memories, hides and shows the out-of-logic icons instead, on both map pages, and its caption (`UI:MapCaptionMemory`) reads "Toggle out of logic" after the button's glyph tag. While the server is not connected it reads "Offline: toggle out of logic", or "Offline: logic unknown" before the client has sent any `INLOGIC` (every location then shows in logic). The overworld page reads the button inline (`w21` in its KeyWait state), the dungeon page through a check function; the module clears the press. The icon setup creates a marker only for rows whose flag is set and adds it to the page's markers (a vector of shared pointers): out-of-logic rows keep their flag, and a hook after that step hides their marker while the toggle is off. Toggling sets the visible bit of the out-of-logic markers on the open page. The toggle is kept in memory only.
- **Skipping a check.** A on an overworld icon of one unchecked location marks that location skipped, and A again unmarks it; the press then does not reach the game. A on an icon of several locations opens its check list (below). A on empty map still opens the game's pin menu, and A on any other icon does what it does in the game. A skipped location counts as checked on the map: its icon shows collected, its hover text reads "Skipped: <name>", and it leaves a group's to-do count but stays in its unchecked count. Unmarking shows its real look again. A location checked in the game or on the server cannot be marked; its icon shows collected anyway. The mark is the player's alone: the client and server are not told, and the module keeps it per seed (Persistence). The overworld page reads A inline (`w0` in its KeyWait state, after the call that reads it), and keeps the hovered marker's index into the page's markers (`+0x8150`, -1 none). The flag hook makes an icon's marker in every look skipping can give it (collected; in logic with an unchecked location in logic, out of logic with one out of logic, partly with both), and the hook after the icon setup hides those not shown, so a mark swaps the visible bits on the open page; the cursor's hover then moves to the shown marker, which shows its text. A plays `SE_SY_DECIDE`.
- **Check list.** A on an overworld icon of several locations opens a panel in the middle of the overworld map listing them; the map between the page's rules dims behind it. Not for a dungeon's icon whose name is hidden (Shuffled dungeons). Built from the game's layouts, hung under the map page and dropped with it (`ap_map.cpp`, `ap_list.cpp`):
  - the panel: the Memories list (`Gm_MemoryList`, as on the Jukebox page) on the paper window of the Memories' count (`Gm_MemoryCollect`'s `W_window_00`, rounded corners, as the Jukebox page's card), sized to the header and the rows, at alpha 245 so the map's place names do not show through; the dim is the map pin bar's black (`Gm_MapMarkList`'s `P_pict_00`) at alpha 150. The game's dialog dim (`Cm_Dlg`) is not used: its masks capture the screen into a texture the pause menu's backdrop shares;
  - the header names the icon as its hover text does ("Mabe Village", "D1 Tail Cave") in dark brown, with its count as in that hover text, "<to do>/<unchecked>", on the right: skipping a location lowers the first number, not the second;
  - a row per location of the icon, checked ones included, in `ap_map.txt` order: the location's name without its area (`ap_map.short_name`, `N` lines), on one line, narrowed to fit the row down to 0.6 of its width, and before it a dot of the location's look, the map's own marker (`Gm_MapMarker`) at the frame of its `SetMark` animation for that look at a group's size (`ap_map_icons.frame`): in logic green, out of logic red, checked or skipped the grey dot with a tick. A skipped location has a small light grey italic "skipped" after its name (a text box's italic slant and text colours: a colour tag does not reach a text box of a layout); a checked or skipped location's name is dimmer. Out-of-logic locations are listed also while X hides the out-of-logic icons;
  - Up and Down move the cursor (held: again after 20 frames, then every 5), and the list scrolls past seven rows with its scroll bar, fitted to the rows, the window widening to hold it;
  - A marks the location under the cursor skipped or not, by the rules of an icon of one location: a location checked in the game or on the server cannot be marked (`SE_SY_BEEP`). The row, the header's count and the icon's look on the map change at once;
  - B closes the panel (`SE_SY_MAP_OMOIDE_OFF`; opening plays `SE_SY_MAP_OMOIDE_ON`), back on the map, which takes buttons again; the buttons held as it closes reach the game only once released, so B does not close the menu, and a Minus held as it opened is let go (not a tap that closes the menu once released);
  - while it is open the game sees no buttons and no sticks (the input hook clears them after the module has read them), so nothing reaches the map or the pause menu (stick, L, R, Plus, Minus, X, Y, R's zoom); the panel reads the pad itself. The map's cursor and the name over its icon (`Gm_MapCursor`, a UI of its own drawn over the pages) are hidden;
  - the guide reads "Ⓐ Skip / unskip Ⓑ Back" (the map's guide with A and B in its first two slots and the rest hidden, `MapCaptionPin` read as "Skip / unskip"), and the map's own again once the panel closes.
- **Dungeon icons.** Every room with locations that are not chests (key drops, instruments, bosses, owl statues, the Color Dungeon's rupees and fairies) gets a `UiDungeonIcon.gsheet` row with the chest icon (`mActorID` 0xF7). The game makes these icons from the rows like actors whose switches are unset, so the module hooks the icon update and shows the icon open once all of the room's locations are checked. The same hook shows a dungeon chest open once its location is checked on the server.
- **ap_map.txt.** The patcher writes `config/lasr-exl/ap_map.txt` next to `config.ini`: `O <group> <local id>...` per overworld icon, `D <group> <x> <z> <local id>...` per dungeon icon (the module finds an icon by its position), `C <level> <x> <z> <local id>` per dungeon chest of the slot (found by the placeholder and local id in the room's actors) `G <group> <name>` per overworld icon, with shuffled dungeons `H <group> <flag> <name>` per dungeon icon: its name, shown without the count, until the flag is set, and `N <local id> <name>` per location of an overworld icon: its name without its area, for the check list (a file without them lists "Location <local id>"). The module turns the tracker on when the file exists. An install without the option removes it (`install.OPTIONAL_CONFIG`).

**In-game hints** (options `in_game_hints` and `hint_distribution`; `hints.py`, `patcher/ap_hints.py`)
- The hint sources are the 9 overworld owl statues, the 24 dungeon owl statues (by the LASR name of their location) and six of the library's books (`book-<color><n>`, the book actor's name); the map, the egg book and the Color Dungeon's book keep their text. Dungeon owl statues need their dungeon's stone beak, as in the game.
- The world picks the hints once the multiworld is filled (`choose_hints`, with the world's random). An area is the part of a location's name before " - " (Location names): an overworld region or a dungeon. The kinds:
  - `always`: one of this world's long checks (`hints.ALWAYS`: the trade quest's end, the 40 and 50 seashell rewards, the rapids race's best time, Ol' Baron, Dampe's last challenge) that is shuffled, not optional, and holds a progression or useful item, anyone's: "Your <item> is at <location>." or "<location> holds <player>'s <item>.".
  - `required`: an area of this world, or a location of another, holding an item of this slot without which the multiworld's other items do not reach this slot's goal (a sweep without that location's item; tested only as hints are wanted, this world's locations first, one hint per area or location): "Something in <area> is needed to wake the Wind Fish." or "Something in <player>'s world at <location> is needed to wake the Wind Fish.".
  - `barren`: an area of this world whose locations, events included and optional ones left out, hold no progression item of any player, with at least two locations whose item is not known anyway: "<area> holds nothing anyone needs.".
  - `area`: "Your <item> is in <area>." or "Your <item> is in <player>'s world.", this world's locations first.
  - `precise`: "Your <item> is at <location>." or "Your <item> is in <player>'s world at <location>.".
  - `joke`: a joke line, for the sources left over.
- `hint_distribution` sets how many of each (`hints.DISTRIBUTIONS`): `precise` only precise hints; `balanced` (default) up to 6 always, 8 required, 5 barren and 8 area hints, precise for the rest; `vague` up to 6 always, 12 required, 8 barren and 3 precise hints, area for the rest. A kind that runs out leaves its sources to the rest's kind, then to precise and area hints, then to jokes. Area and precise hints name this slot's progression items first, then useful ones; each location is named once. They leave out the locations whose item is known anyway, and those nobody needs: unrandomized, kept, locked and optional locations of this slot, items in `start_hints` and locations in `start_location_hints`, seashells, dungeon items in their own dungeon; no hint rests on an owl statue's own gift for that statue. The spoiler lists each source's hint with its kind.
- The patcher gives each source its own message, `Hint:APHint<n>` for owl statues and `System:APHint<n>` for books (n: the source's place in `ap_hints.SOURCES`), wrapped to 42 characters and 3 lines per box, with the window style of the text it replaces; a line never starts with the dash between a location's region and spot. The books' question before reading names them "Koholint Lost and Found, Volume <n>". Owl statues that share an entry point (Tail Cave 04B and 05F, the three Color Dungeon statues) get entries of their own, as LASR's Owl Gifts give them, with their own copy of the statue's events. With Owl Gifts on, the gift follows the hint.
- With `server`, a hint that names one location (`always`, `precise`) sets the event flag `APHint<n>` after its text (added to `GlobalFlags.gsheet`), and the patcher writes `config/lasr-exl/ap_hints.txt`: per hint `<n> <flag> <slot> <location id>` (`install.OPTIONAL_CONFIG`). The module polls the flags, which the save keeps, and sends `HINT` lines; the client sends `CreateHints` with priority status for each new one, or on servers before 0.6.2 `LocationScouts` with `create_as_hint` 2 for this slot's own locations. It sends them again after each server connection; the server skips hints it has.

**Ghosts** (`ghosts.py`, `ghost_relay.py`, `ap_ghostnet.cpp`)
- The multiworld's other LAS players show where this player is. Positions travel game → client → ghost relay → the other clients → their games; the AP server is not involved. The game draws the ghosts from `AP::GhostNet::Get(n)` (the puppet side is separate work).
- **Relay.** `ghost_relay.py` (standard library only, runs on its own) can serve any number of multiworlds; the client connects to the one in `las_options.ghost_relay`, else the one in the patch file (the generating host's `las_options.ghost_relay`), and without either uses `DEFAULT_RELAY` (`ghosts.py`, `wss://ghosts.zerozshadow.com`). The default relay failing to connect or refusing is a note in the Patch tab (INFO), not an error, as nobody chose it; the link keeps retrying with its growing delay. The world draws one random secret per multiworld (`LASWorld.ghost_secret`, `secrets.token_hex(16)`) into every LAS slot's patch file, not into the slot data, which anyone who can log into a slot reads. A client joins the group SHA-256(`lasghost|<secret>`) with its slot name and player name, so the relay never sees the secret; the LAS players of one multiworld share a group whatever their slots' seeds. The relay forwards a player's frames to the group's members in the same level, and in `Field` only to those within the 3×3 screens around the sender (screen from x/z: column ⌊x/15⌋, row ⌊z/12⌋+1, as TESTING.md's overworld coordinates). Each member gets the 30 nearest players of its area (`MAX_SHOWN`, the game's ghost slots), chosen again every half second; a shown player stays unless another is 2 units nearer. A member's frames go out together every 20 ms (`BATCH`), one TCP segment instead of one per frame. A member entering a still player's area gets that player's last frame at once. A player who leaves a member's area, is in no level, sends nothing for 10 s or leaves the group gets an off. A second connection of the same slot of the same multiworld replaces the first. With `--nogroups` every member is in one group (`ONE_GROUP`), whatever its multiworld: the relay still tells a reconnect by the join's group and slot name, and the client tells its own player by the id in `WELCOME`, not by its slot name, which another multiworld's player may share; neither the relay nor the client shows a player itself as a ghost. With `--password` (or `LAS_GHOST_RELAY_PASSWORD`) the relay lets in only joins carrying that password, the join's last field (optional, so a relay without a password takes joins without it); the client takes it from the address, `password@host:port`, and leaves it out of its status messages. A wrong password is refused after 1 s, so guessing is slow; the password travels in plain text, keeping strangers off the relay, not eavesdroppers. `LASGhostRelay.exe` asks for one when double-clicked. Limits: 64 per group (`--max-group`, `LAS_GHOST_RELAY_MAX_GROUP`; with `--nogroups` the whole relay), 16 connections per address, 40 frames/s per client. The log has one line per join (slot, player name, the first 8 hex digits of the join's group, transport) and per leave (time joined, reason); connections that never join log nothing. `--forward` maps the port on the host's router and removes the mapping when the relay stops: NAT-PMP to the default gateway (the router picks the external port, which the relay prints), else UPnP (SSDP on each IPv4 address, then the WANIPConnection or WANPPPConnection service; a permanent mapping where the router takes only those); leases of an hour are renewed every half lease.
- **Wire.** TCP with TCP_NODELAY (also between the game and the client); each message is a u16 length (big-endian) and a payload whose first byte is its type (`ghost_relay.py` lists them). The relay's port also takes WebSocket connections (RFC 6455; the client uses one for a `ws://` or `wss://` address, `http://` and `https://` taken for them), for a relay behind a proxy such as a Cloudflare Tunnel. The relay tells them apart by the first byte: a frame's length starts with 0 or 1 (`MAX_FRAME` is 256), an upgrade request with `G`. Their binary messages carry the same byte stream of frames: a relay batch is one message, a client frame one. Both sides are in `ghost_relay.py` (`connect`, `WebSocketReader`, `WebSocketWriter`; standard library, `wss://` checked against certifi's certificates where Archipelago has them). A WebSocket from a trusted proxy counts as the address in its `CF-Connecting-IP` header, else the last `X-Forwarded-For` entry, for the per-address limit; from anywhere else those headers are ignored. Trusted are loopback and each `--trusted-proxy` (`LAS_GHOST_RELAY_TRUSTED_PROXY`): a network, or a host name looked up for each WebSocket, as a proxy container's address changes when it is recreated (`Relay.trusts`). A plain HTTP request gets a `426 Upgrade Required` page. The join message carries the protocol version (`PROTOCOL_VERSION`); the relay refuses a client of another version. A position is 33 bytes (`POS_BODY`, the fields of `Pos`): time u16 (the sender's game clock in ms when it took the position, wrapping), level id u16 (the index in `LEVELS`, append only), x/y/z f32, yaw u16 (360° = 65536), animation id u16, animation frame u16, upper-body animation id u16, flags u8 (1 warped: snap, 2 hidden, 4 still: not moved since the previous frame, 8 an animation started since the previous frame sent), shapes u32, tunic u8 (0 green, 1 red, 2 blue), and the frames of his face's material animations: eye u8, mouth u8, ear u8. An animation id is Link's `PlayerAnimation.gsheet` key + 1 (0 none), the animation frame in tenths; the upper-body animation is the one on his upper body's layer (`idle_carry` while he holds something over his head). Bit i of the shapes draws shape i of Link's model (20: his body and the items on it, among them the swords, shields, ocarina, shovel, rod, hookshot handle, boots and flippers). The relay adds the player id: 36 bytes with the type, 38 with the length.
- **Rate.** The module sends `POS` at most every 50 ms while the position, yaw, level or animation id changes, and every 500 ms while Link stands still. What the player does goes out at once: a new level, an animation starting (another one, or the same again from its start), a turn of 10° or more, starting or stopping to move (the still flag), another look; the animation frame running on is no change. The client caps frames at the same rate, a frame with another yaw, animation id, flags or look than the last one sent excepted. Flag warped: the first position in a level and a jump of more than 4 units.
- **Client.** `GhostLink` joins once ghosts are on, a relay address is set, and the patch file's ghost secret (`--ghost-secret` replaces it, for tests) and the slot name are known; it reconnects when any of them changes, and after a failure with a growing delay. It gives each player in the area one of 30 ghost slots and turns the relay's frames into `GHOST` lines; a 31st player waits for a free slot. It sends `GHOSTS 1` once joined and `GHOSTS 0` when it leaves. The Patch tab has "Show ghosts" (`las_options.ghosts`, on by default), "Ghost relay" (`ghost_relay`, empty by default: the patch file's, else the default relay) and the relay status; `/ghosts [on|off]` in the client. `/ghostnames [on|off]` turns the name tags on or off (`ghost_names`, on by default) with `GHOSTNAMES`; so does ↑ on the d-pad in the game while ghosts are on (D-pad in the game, Music).
- **Module.** `ap_ghostnet.cpp` reads Link's position and yaw from his collision component's coordinates, with no player during level loads and while he stands at the origin (leaving a level by its exit, until the next one loads), and once a frame the animations on slots 0 and 1 (his upper body) of his animation controller (the row of `PlayerAnimation.gsheet` playing, and slot 0's frame) and his look (his model's shape bytes, which the game sets for the items he holds, the inventory's tunic bits, and the frames on the `eye`, `mouth` and `ear` slots of his material animation component); it keeps the last `GHOST` lines per slot. A new client connection clears both until it sends `GHOSTS 1`.
- **Puppet** (`ap_puppet.cpp`; the test build's `DBG puppet`). Each ghost slot of `GhostNet` has a puppet: an `NpcGhost` actor spawned through the game's actor factory, whose NPC component the module gives the Npc row `APGhost` while it spawns it, drawn with Link's model from `PlayerGhost.bfres`, with no collision (shape 0), action or event triggers in its row (the patcher adds the row and the model, `ap_player_ghost.py`; in a mod patched before them the module shows no ghosts): the albedos of the body and the items on Link's model carry alpha 128 in render pass 1 (the red and blue tunics at half size; the items' other maps, but the mirror shield's, shrunk to make room), and the module binds an NVN multisample state with alpha-to-coverage for the ghost's draws only, so it dithers in screen space. The module writes its root component's coordinates each frame, replaying the slot's last `GHOST` lines on the sender's clock 100 ms (two lines' time) behind: the position between the two lines around that time, the facing of the line before it (Link turns in steps, so turns are not smoothed), a jump at a warped line's time; past the newest line it goes on along the last segment for up to 100 ms unless that line was still, then holds. The sender's clock maps to this one by the least delay seen, rising slowly, so a late line shortens the wait instead of speeding the ghost up. When new lines move the replay's position (the sender turned or stopped while the replay ran on past its newest line), the ghost does not jump: the difference fades out over about 100 ms. It plays the sender's animation by name (the key's file name in its own game's sheet, an FSKA of the ghost's model) from the sent frame, when the replay reaches the line it started in, through the NPC animation component; for a sender with no animation id, `wait`, `walk`, `run` or `dash_lp` by its speed. The ghost's animation player is layered as Link's is (the module makes it in place of the NPC's single-layer one, for the `APGhost` row only): layer 1, masked from the bone `spine_a` up, plays the upper-body animation and is off without one. It draws the replayed line's look: the shapes through the model instance's shape bytes (but those drawn instanced), the tunic with the material animation `clothes` held at its frame on the NPC's material animation component, and the face: `APGhost`'s facial row (`Facial.gsheet`, the patcher's) names `eye`, `mouth` and `ear`, so the component has a slot for each, which the module holds at the sent frames. While the face differs from the instanced one (all frames 0) the ghost draws its own face shapes.
- A ghost that arrives (a warped line: another level, a respawn, a warp) stays hidden from that line's time until a line after it moved, started or changed the animation, or 1 s passed on the sender's clock: a player entering a level stands still through their own fade-in first (falling into Mabe's well: about 0.6 s on the floor, then `fall_from_top` drops the model from above while the position sinks). It shows again with that line, whose animation then plays unblended. A ghost is ready, and its name tag and instanced shapes show, once its body has drawn two whole frames with its actor active; the instanced shapes take the bones the frame before posed.
- A puppet shows while the client is connected, its ghost is in Link's level and not hidden, and its last line is under 5 s old (a backstop for a lost off: a still player's game sends twice a second). Otherwise it hides (its materials' visibility bits cleared) and waits for its ghost again; after 10 s hidden the module removes its actor as the game removes actors, and a later line spawns a new one. Actors from the factory outlive level changes, so a slot keeps its actor (a weak reference; the actor system owns it) across them and follows the model it loads in each level; the render thread only compares bind addresses with each shown puppet's GPU address range, which the game thread publishes. An actor spawned in a level's first frames can stay inactive (entity flags without bit 2: never updated or drawn); a shown puppet whose actor was never active is removed and spawned again after 30 inactive frames. A dungeon room's change clears bit 2 on every actor but Link's, for its scroll and, on a ghost's actor, for good once Link has left its room and come back; the module sets it again on a shown ghost's actor that was active, so the ghost goes on moving through the scroll. The `APGhost` row is `ghost_puppet.py`'s for now; the module keeps `NpcGhost`'s row when the sheet has no `APGhost`, since a missing row crashes.
- **Crowds.** Each shape a ghost draws costs a draw call in each of two render passes; on an emulator the draw calls limit the frame rate (TESTING.md, Ghost crowd), not the lines or the module's own work. The nearest ghosts draw their whole look, the next ones only the arms, tunic, face and hair (`kCrowdShapes`), the farthest none. How many of each follows the frame rate the module measures: down by a quarter after a second under 55 fps, up by one after 3 s at 59 or more, back to a count found too slow only after 30 s. The 6 nearest always draw whole and the 16 nearest always draw, and nothing changes in the first 3 s of a level: the game's own slow moments are no reason to hide a few ghosts. The ranking takes 2 units off a ghost's distance per step of detail it has, so a ghost near a limit keeps its detail until another is that much nearer and ghosts walking about at about the same distance do not pop in and out.
- **Instanced equipment.** The shapes of Link's model bound to one bone each (the swords, the shields, the Magic Rod, the shovel, the hookshot and the ocarina at the hands, the ear, eyes and mouth at the head) draw once for all ghosts, as the game draws its lawn grass: per group of shapes shown together one InstancedModel component on Link, whose model the game draws with one instance per record, the module writing one record per drawn ghost whose look has the group's shapes each frame (the ghost's bone in the world times the inverse of the bone in the instanced model's bind pose). The puppets draw none of these shapes. The components go with Link at a level change and are made again in the next, from the first ghost's model resource; their draws dither as the ghosts' do (TESTING.md, Instanced models). The records are emptied each frame drawn; while the game pauses (a menu opening: the frame count stays) the module writes them again from the standing ghosts. 30 ghosts drawn whole draw 103 times a command buffer instead of 185.
- **Name tags** (`ap_nametag.cpp`). A ghost drawn whole has its slot name (up to 16 characters, Archipelago's limit) over its head in the game's action prompt (`Gm_HUDInteract.bflyt`: text in a dark rounded window) without its button picture, at 0.6 of its size, the text at alpha 230 and the window at 200, the window stretched around the name, the text raised by 0.14 of its height so its capitals sit in the middle (the font's glyphs sit low in their line); a layout of its own per ghost slot drawn over the HUD, under menus and the message window. The prompt's text box holds 13 characters; the module gives it room for 32 UTF-16 units through ui2d's `AllocateStringBuffer` with the gfx device the UI manager builds layouts with (TESTING.md, Text box glyphs). Each frame the module projects the point 0.68 units above the head bone of the ghost's model (so the tag follows a fall from above or a jump) with the game's camera and hides the tag behind the camera or off screen. The name goes into the text box through the game's message pipeline; the module queues the box with the UI manager so the font draws the name's glyphs, as the game does for its scenes' layouts (TESTING.md, Text box glyphs). The tags are built again after each level load.

**Music** (jukebox; `music.py`, `ap_music.cpp`)
- `/music <track>` in the client plays a BGM instead of the zone's music until `/music off`. The track is a name from `music.TRACKS` (the patcher's `BGM_TRACKS`, the looping tracks the Music setting shuffles), case-insensitive, `BGM_` optional, or a unique part of one (`fairy`, `tail`); another `BGM_` name goes to the game as typed. The client keeps the choice for its session only; `/music` alone shows it and the tracks.
- The Jukebox page chooses through `AP::Music::Choose`, which applies the track as a client's `MUSIC` line does and sends the client game-to-client `MUSIC <track>` / `MUSIC off`; the client takes it as its choice and logs it as `/music` does, so `/music off` afterwards turns it off.
- The module keeps its choice while the game runs, also across client connections, and is the authority: on each connection it reports its choice (`MUSIC <track>` / `MUSIC off`, after `HELLO`). The client adopts a reported track and sends nothing. Only to a report of none does it send its own choice, when it has one (given by `/music` while the game was off or restarting). A `/music` the client sent after `HELLO` but before the report is newer than the report, so the client ignores that report.
- The game's zone music reaches `BgmManager_Play` from the zone update (Link enters a zone, a level starts) and from `PlayZoneBgm` (the event action `PlayZoneBGM`, which events call to bring the zone's music back). While a track is chosen, the module's hook on `BgmManager_Play` asks for it in those calls, which it tells apart by their return address; the game then treats it as the zone's track. It keeps playing through room changes and through doors to other levels: a door's event stops all music (`StopAllBGM`) and fades the zone's out, and the level load stops what is left (`BgmManager_StopAll`), but the module keeps the chosen track out of those stops until it knows what follows. A level load, or the game asking for the zone's music again: it plays on, and the new level finds it playing. Another track starting (an event's song, a fanfare): it stops then. The player free for 10 frames in a row with neither (an event that meant silence): it stops then. Stairs between 3D and 2D rooms of one level stop and fade the music, free the player for a single frame after the room change and then call `PlayZoneBGM`, so a single free frame does not stop it. It replaces the zone's track whatever the Music setting did to it, also with Music Removed. Two event songs stand in for the zone's music with no `PlayZoneBGM` after them, the washed-up sword's `BGM_FIELD_NORMAL_INTRO` (`SinkingSword.bfevfl`) and the new game's wake-up `BGM_HOUSE_FIRST` (`PlayerStart.bfevfl`); the hook asks for the chosen track in the event action `PlayBGM`'s call for those two.
- Every other request plays as the game makes it: event songs, Marin's and the instruments' songs, boss and miniboss music, fanfares, jingles, the Guardian Acorn's and Piece of Power's music. Events silence music with `StopAllBGM` and bring it back with `PlayZoneBGM`, and stop only their own songs by name (no event stops a zone track), so the chosen track gives way to event music and comes back where the zone's music would.
- On a change the module calls `PlayZoneBgm` with fading and makes it sound as a zone change does: the new choice (or, with off, the zone's own track) starts from its beginning, intro included, and fades in over 150 frames, and the other zone and event tracks fade out over 90 (`PlayZoneBgm` itself starts its track at full volume; the module sets the new instance's fade in). The track that played before the change is also stopped by name (90 frames), for the cases where nothing new starts (a zone without a track, a buff's music playing). A change waits while the BGM manager prepares a track (its list of instances about to start): no fade or stop reaches a track before it starts, so changes made within a few frames (→ ← on the d-pad) would leave both playing; the change then applies the latest choice. An unknown name (`BgmTable_Find`) is refused and clears the choice.
- Offsets and structures: TESTING.md, Reverse engineering; symbols in `scripts/re/las.sym`.

**Jukebox page** (`ap_jukebox.cpp`, `ap_tracks.hpp`)
- The pause menu's fourth page, after System: Map, Items, System, Jukebox, round with L and R. The header names it: "Jukebox" with System under L and Map under R, and "Jukebox" as System's R and the map's L neighbour. Plus, Minus and B work as on any page. The menu never opens on it. There is none in the Chamber Dungeon, whose third page is the dungeon's own.
- The header (Navi, `Gm_Navi.bflyt`) has room for three pages, so the Jukebox is a mode of index 2, System's slot: while the module's flag is set, the `Gm_System` page the header builds for index 2 hides its content and shows the Jukebox. The module steers the moves that differ from the game's: R on System and L on the Jukebox change index 2 to index 2 (System is removed and built again, as on any page change), when the game would let the page go (`Navi_WaitKey`'s checks: no dialog open, the page's `+0xe0` set); L on the map lands on the Jukebox; every other change leaves it. The header keeps an L or R pressed while it brings in a page and turns that page once it is open; the module reads the page from the header's target index, as `Navi_WaitKey` sets the current index from it only on the page's first frame.
- The page is built from the game's layouts, hung under the page's root with `LayoutWrapper_AttachTo`, faded in with the page and out as the header leaves it, and freed with the page:
  - the track list, `Gm_MemoryList` (the Memories list), on the right: `music.TRACKS` in order with the names of `ap_tracks.hpp`. The chosen track's row is lit (`W_Add` alpha, as the row animation On sets it) and marked with a note. The list opens with the cursor on the chosen track, else on the zone's own;
  - "Now playing", `Gm_MemoryCollect` (the Memories count card), on the left: the name of the chosen track and its number in the list; with the Jukebox off, "Jukebox off" and the zone's own track ("Silence" in a zone without music). A note in its paper window bobs, and notes float up out of it while music plays (the font's U+266A in `Gm_SystemOpUnit` text boxes);
  - the name and description of the track under the cursor, at the bottom, where the Items page names its item (`Gm_Item`'s `N_Info_00`);
  - under the card, the playback state (a second `Gm_MemoryCollect`, its text only, smaller): Shuffle and Repeat one, on or off, and "In game: ← → change track";
  - the guide "Ⓧ Shuffle Ⓨ Repeat one Ⓐ Play Ⓑ Back": the overworld map's guide (X, Y, R, A, B; `Navi_SetGuide` with index 0 and the map id 0xf for the call), A and B moved up over R and the last slot hidden, with the captions `UI:MapCaptionMemory`, `MapCaptionPlace` and `MapCaptionPin` read as Shuffle, Repeat one and Play during the call (`ap_text.cpp`). The guide keeps each slot's kind and loads a caption only for a new kind, and the Jukebox's X and Y share the map's, so the module clears the kept kinds when it sets the Jukebox's guide and when the next page sets its own. Button tags draw only in the game's own guide text boxes, not in a text box built here.
  - The list, the layouts built at runtime, the pad and the guide made from the map's are `ap_list.cpp`'s, which the map's check list (Map tracker) uses too.
- Up and Down move the cursor (held: again after 20 frames, then every 5). A chooses the track through `AP::Music::Choose`; on the chosen track (the guide reads "Ⓐ Stop" there) it turns the Jukebox off, the game's own music again. The page runs `AP::Music::Tick` each frame, which does not run otherwise while the menu is open, so the track plays in the menu and the client learns the choice. The pause menu turns music down (each BGM's volume to 0.2, also a track that starts while it is open); a track chosen on the page plays at full volume until the menu closes. X turns Shuffle on or off, Y Repeat one.
- **Playback** (`ap_music.cpp`). Repeat one is on at the start: the chosen track loops, as the game loops its music. With it off, once the chosen track has played through, the next one follows. Next and previous step through one order, round: the list's, or with Shuffle a random order of the list, drawn each time Shuffle turns on, so every track plays once before any plays again and previous retraces next. A track's play-through is its stream's end, with a short loop repeated until a minute has passed (`ap_tracks.hpp`). The module counts it while the track plays, also under the pause menu, and from the start again whenever the game starts the track again (after an event's music or a level load). A track that does not loop ends there and is followed at once. The next track follows only while the player is free (a change fades out the other zone and event music, an event's song too); a track cut off by other music has not ended. The modes last while the game runs.
- **D-pad in the game.** While the player is free, outside the trendy game and the fishing pond, → chooses the next track and ← the previous one in that order, from the chosen track or else the zone's own, and ↑ turns the ghosts' name tags on or off while ghosts are on (Ghosts). The d-pad does nothing else in free play. The track's name shows in a toast ("♪ Tail Cave"), and the name tags' state in the same toast ("Ghost names off"), which takes the place of the one showing or waiting, so skipping through tracks shows the last one.
- `ap_tracks.hpp` holds each track's name (at most 24 characters, one list row), description (at most 80 characters, two lines of 40) and play-through length; `test_music` checks it against `music.TRACKS`. `scripts/track_lengths.py` writes the lengths from the RomFS (the sound archive `Richard.bfsar` leads from a label to its `.bfstm`, whose stream info has the sample rate, the loop start and the end). Names come from where the game plays each track (zone tables in the levels, event flows, stream names in the sound archive).

**Persistence**
- **Received-item count:** event flags `APRecv0`..`APRecv15`, read as a 16-bit counter. The patcher adds them to `GlobalFlags.gsheet`.
- **Collected locations:** a bitset file `sd:/lasap/<seed_hash>.chk`, written on each check, so checks made while disconnected are reported later.
- **Skipped locations:** a bitset file `sd:/lasap/<seed_hash>.skp`, written on each mark or unmark on the map (Map tracker, Skipping a check).
- **Read hints:** event flags `APHint<n>` (In-game hints).
